## 학습 목표

- SSD1306 OLED 의 **제어 바이트(0x00 명령 / 0x40 데이터)**, 페이지 주소 방식, 1024바이트 화면 버퍼를 이해하고 글자를 그립니다.
- HC-SR04 의 TRIG · ECHO 타이밍으로 거리를 계산합니다 (**cm = µs / 58**).
- 4x4 키패드 **행 스캔**과 4자리 FND **멀티플렉싱**의 원리와 전류 한계를 설명합니다.
- DHT11 **단일 선 프로토콜**의 µs 단위 타이밍을 타이머로 재서 40비트를 읽습니다.
- 릴레이(능동 LOW) · 로터리 엔코더(직교 신호) · 조이스틱(ADC 2채널)을 안전하게 연결합니다.

## SSD1306 OLED

SSD1306 은 128x64 픽셀 OLED 컨트롤러입니다. 내부 GDDRAM 은 **128 열 × 8 페이지 = 1024 바이트**이고,
한 바이트가 세로 8픽셀(비트0 = 위)을 맡습니다. 화면 한 줄의 글자(높이 8픽셀)가 페이지 하나에 딱 들어갑니다.

```text
          열 0   열 1   ...  열 127
페이지 0  [b0]   [b0]         ← 픽셀 y = 0
          [..]   [..]
          [b7]   [b7]         ← 픽셀 y = 7
페이지 1  ...                    y = 8 ~ 15
 ...
페이지 7  ...                    y = 56 ~ 63
```

I2C 로 보내는 바이트마다 앞에 **제어 바이트**가 붙습니다. `0x00` 이면 뒤의 바이트가 명령, `0x40` 이면 화면 데이터입니다.
HAL 의 `HAL_I2C_Mem_Write` 는 "메모리 주소" 1바이트를 먼저 보내므로, 이 자리에 제어 바이트를 넣으면 코드가 짧아집니다.

@table[regmap]
| 명령 | 값 | 뜻 |
|---|---|---|
| Display OFF / ON | `0xAE` / `0xAF` | 초기화는 OFF 상태에서 |
| Memory addressing mode | `0x20`, `0x00`/`0x01`/`0x02` | 수평 / 수직 / 페이지 (리셋 기본 = 페이지) |
| Page start (페이지 모드) | `0xB0` ~ `0xB7` | 쓸 페이지 고르기 |
| Column low / high | `0x00`~`0x0F`, `0x10`~`0x1F` | 열 주소 하위·상위 4비트 |
| Column / Page range (수평·수직 모드) | `0x21 a b`, `0x22 a b` | 쓸 범위 지정 |
| Contrast | `0x81`, `0x00`~`0xFF` | 밝기 |
| Segment remap / COM scan | `0xA0`/`0xA1`, `0xC0`/`0xC8` | 좌우·상하 뒤집기 |
| Normal / Inverse | `0xA6` / `0xA7` | 흑백 반전 |
| Multiplex ratio | `0xA8`, `0x3F` | 64줄 |
| COM pins | `0xDA`, `0x12` | 128x64 배선 |
| Charge pump | `0x8D`, `0x14` | **켜지 않으면 화면이 안 켜짐** |

@sim[l17-oled] SSD1306 OLED 열기

@code[l17-oled] u0

- 화면에 직접 그리지 않고 **RAM 의 `oled_buf[1024]` 에 그린 뒤** `oled_update()` 로 한꺼번에 보냅니다. 이것이 프레임 버퍼 방식입니다.
- 400 kHz I2C 에서 1024바이트는 비트로 약 9,200개(바이트마다 ACK 포함)라 **한 화면 전송에 약 25 ms** 가 걸립니다. 바뀐 페이지만 보내면 빨라집니다.

:::info 1.3인치 모듈은 SH1106 인 경우가 많습니다
겉모양이 같아도 1.3인치 OLED 는 SH1106 컨트롤러(132열 RAM)인 경우가 많습니다. 이때는 열 주소를 2 만큼 밀어야 화면이 맞고, 수평 주소 모드가 없으므로 페이지 모드로만 씁니다.
:::

## HC-SR04 초음파 거리

1. TRIG 에 **10 µs 이상** HIGH 펄스를 줍니다.
2. 모듈이 40 kHz 초음파를 8번 쏘고 ECHO 를 HIGH 로 올립니다.
3. 반사파가 돌아오면 ECHO 가 LOW 로 내려갑니다. **HIGH 폭 = 왕복 시간**입니다.

소리는 20 °C 에서 약 343 m/s 이므로 1 cm 를 가는 데 29.2 µs, 왕복 58.3 µs 입니다. 그래서 **거리(cm) = 폭(µs) / 58** 입니다.
측정 범위는 약 2~400 cm, 400 cm 의 왕복 시간은 약 23 ms 입니다. 측정 간격은 **60 ms 이상**을 권장합니다.

@sim[l17-ultrasonic] HC-SR04 폴링 측정 열기

@code[l17-ultrasonic] u0

이 방식은 ECHO 가 끝날 때까지 CPU 가 `while` 에서 기다립니다(최대 23 ms). L19 에서는 **입력 캡처**로 기다리지 않고 재는 방법을 배웁니다.

## 4x4 키패드 스캔

키 16개를 핀 16개로 읽지 않고, 4행 × 4열 **매트릭스**로 8개 핀만 씁니다. 키를 누르면 그 행과 열이 연결됩니다.

- 행(R1~R4)은 출력, 열(C1~C4)은 **풀업 입력**입니다. 평소 열은 HIGH 입니다.
- 행 하나만 LOW 로 만들고 열을 읽으면, LOW 로 읽힌 열의 키가 그 행에서 눌린 키입니다.
- 네 행을 차례로 반복하면 16개 키를 모두 확인합니다. 20 ms 마다 스캔하면 채터링도 걸러집니다.

@sim[l17-keypad] 4x4 키패드 열기

@code[l17-keypad] u0,loop

:::warn 두 키를 동시에 누를 때
같은 열의 두 키를 누르면 LOW 인 행과 HIGH 인 행이 버튼을 통해 직접 연결됩니다. 행 출력을 **오픈드레인**으로 설정하거나 행마다 **330 Ω~1 kΩ 직렬 저항**을 넣으면 핀끼리 합선되지 않습니다.
:::

## 4자리 FND 멀티플렉싱

4자리 FND 는 8개 세그먼트 선(a~g, dp)을 네 자리가 **함께 씁니다**. 자리 선택선(D1~D4) 중 하나만 켜서
그 자리에 숫자를 쓰고, 2~3 ms 뒤 다음 자리로 넘어갑니다. 눈은 빠른 깜빡임을 연속으로 보므로 네 자리가 동시에 켜진 것처럼 보입니다.

- 한 바퀴(프레임) = 4 자리 × 2 ms = **8 ms → 125 Hz**. 60 Hz 아래로 느려지면 깜빡임이 보입니다.
- 한 자리는 1/4 시간만 켜지므로 1자리 FND(L12)보다 어둡습니다. 세그먼트 저항을 조금 줄여 보정합니다.
- **자리를 바꿀 때는 먼저 모든 자리를 끄고** 세그먼트를 바꾼 뒤 새 자리를 켭니다. 순서가 바뀌면 옆 자리에 잔상(고스트)이 남습니다.

@sim[l17-fnd4] 4자리 FND 열기

@code[l17-fnd4] u0,loop

:::danger 자리 공통 핀 전류
세그먼트 8개가 모두 켜지면 공통 핀 하나로 8 × 10 mA = 80 mA 가 흐릅니다. STM32F4 핀 하나의 절대 최대 전류는 **25 mA** 이고
칩 전체도 120 mA 를 넘으면 안 됩니다(데이터시트 확인). 실물에서는 자리 공통 핀을 **트랜지스터(예: 2N3904/2N3906, S8050)** 로 구동하고, 세그먼트마다 저항을 답니다.
:::

## DHT11 단일 선 프로토콜

DHT11 은 선 하나(DATA)로 명령과 데이터를 모두 주고받습니다. 선은 오픈드레인처럼 쓰고 **풀업(4.7~10 kΩ)** 이 HIGH 를 만듭니다.

@table[regmap]
| 단계 | 누가 | 시간 |
|---|---|---|
| 시작 신호 | MCU 가 LOW | **18 ms 이상** |
| 선 놓기 | MCU 가 입력(풀업)으로 전환 | 20~40 µs 뒤 센서 응답 |
| 응답 | 센서 LOW → HIGH | 80 µs + 80 µs |
| 비트 40개 | 센서 LOW 50 µs 뒤 HIGH | HIGH 26~28 µs = `0`, 70 µs = `1` |
| 데이터 | 습도 정수·소수, 온도 정수·소수, 체크섬 | 체크섬 = 앞 4바이트 합의 하위 8비트 |

@sim[l17-dht11] DHT11 온습도 열기

@code[l17-dht11] u0

- µs 단위로 재야 하므로 1 MHz 로 도는 TIM2 의 카운터를 씁니다(`__HAL_TIM_GET_COUNTER`).
- HIGH 폭이 40 µs 보다 길면 `1` 로 판정합니다. 26 µs 와 70 µs 사이의 가운데 값입니다.
- **1초에 한 번 이하**로 읽고, 전원을 넣은 뒤 1초는 기다립니다. 읽는 동안 긴 인터럽트가 끼면 비트가 틀어져 체크섬 오류가 납니다.
- DHT11 은 0~50 °C(±2 °C), 20~90 %RH(±5 %) 범위의 저가 센서입니다. 더 정밀해야 하면 DHT22 나 I2C 센서(SHT3x 등)를 씁니다.

## 릴레이 모듈

릴레이는 작은 전류(코일)로 큰 전류(접점)를 켜고 끄는 기계식 스위치입니다. 5 V 릴레이 코일은 약 70 mA 가 필요해
GPIO 로 직접 구동할 수 없습니다. 흔한 릴레이 **모듈**에는 트랜지스터(또는 포토커플러)와 **역기전력 다이오드**가 들어 있어 GPIO 로 IN 만 제어하면 됩니다.

- 대부분의 모듈은 **IN 이 LOW 일 때 켜집니다(능동 LOW)**. 그래서 예제는 초기값을 HIGH 로 두어 부팅 중에 릴레이가 붙지 않게 합니다.
- 코일 전류가 끊기는 순간 코일은 수십~수백 V 의 역기전력을 만듭니다. 모듈 없이 직접 만들 때는 코일에 **다이오드(1N4148, 1N4007)를 역방향 병렬**로 꼭 답니다.

@sim[l17-relay] 릴레이 토글 열기

@code[l17-relay] pv,loop

:::safety 릴레이와 교류(AC) 부하
- **AC 220 V 는 감전으로 생명을 잃을 수 있습니다.** 실습은 5~12 V 직류 부하(LED 띠, 소형 팬)로만 하세요. 교류 배선은 자격 있는 사람이 절연된 함체 안에서만 합니다.
- 접점 정격(예: 10 A 250 VAC / 10 A 30 VDC)을 넘기지 마세요. 모터·전구처럼 켜는 순간 큰 전류가 흐르는 부하는 정격의 절반 이하로 씁니다.
- 모듈의 JD-VCC 점퍼를 빼고 릴레이 코일 전원을 따로 주면 포토커플러로 **MCU 쪽과 전기적으로 분리**됩니다.
- 배선은 전원을 모두 끈 상태에서 하고, 릴레이 뒷면의 납땜면(고전압 쪽)을 손이나 금속에 닿지 않게 합니다.
:::

## 로터리 엔코더 (KY-040)

엔코더를 돌리면 CLK(A)와 DT(B) 두 신호가 **90° 어긋난 사각파(직교 신호)** 로 나옵니다. 어느 쪽이 먼저 떨어지는지로 방향을 압니다.

```text
시계 방향      CLK ‾‾\____/‾‾‾‾      CLK 가 먼저 LOW → 그 순간 DT 는 아직 HIGH → +1
               DT  ‾‾‾‾\____/‾‾
반시계 방향    CLK ‾‾‾‾\____/‾‾      CLK 가 떨어질 때 DT 는 이미 LOW → -1
               DT  ‾‾\____/‾‾‾‾
```

@sim[l17-encoder] 로터리 엔코더 열기

@code[l17-encoder] loop

- KY-040 은 한 바퀴에 **20 딸깍(detent)** 이 흔합니다. 한 딸깍에 CLK 가 한 번 떨어집니다.
- 빨리 돌리면 1 ms 폴링으로는 에지를 놓칠 수 있습니다. 실물에서는 EXTI 인터럽트를 쓰거나, 타이머의 **엔코더 모드**(`HAL_TIM_Encoder_Start`, 시뮬레이터 미지원)로 하드웨어가 직접 세게 합니다.
- 모듈의 CLK · DT 에는 10 kΩ 풀업이 있지만 SW 는 없는 모듈도 있어 내부 풀업을 켭니다.

## 조이스틱

조이스틱은 10 kΩ 가변저항 두 개(X, Y)와 누름 스위치입니다. VRx · VRy 를 ADC 두 채널로 스캔하면 가운데가 약 2048 입니다.
실물은 가운데 값이 정확히 2048 이 아니고 흔들리므로 **데드존**(예: 1000~3000 은 가운데로 봄)을 둡니다.

@sim[l17-joystick] 조이스틱 열기

@code[l17-joystick] u0,loop

:::safety 5 V 모듈을 3.3 V MCU 에 연결할 때

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| OLED 가 아무것도 표시하지 않음 | 차지 펌프 `0x8D 0x14` 누락, 주소 `0x3C` 를 시프트하지 않음 | 초기화 순서 확인, `0x3C << 1` |
| OLED 글자가 좌우·상하로 뒤집힘 | `0xA0/0xA1`, `0xC0/0xC8` 조합 | 모듈 방향에 맞게 둘 중 하나 변경 |
| 초음파 값이 늘 0 또는 "No echo" | TRIG 펄스 10 µs 미만, ECHO 5 V 를 분압 없이 비FT 핀에 | 펄스 폭 확인, 분압 · FT 핀 |
| 초음파 값이 가끔 튐 | 측정 간격이 60 ms 보다 짧아 이전 반사파를 받음 | 간격 늘리기, 중앙값 필터 |
| 키가 여러 번 입력됨 | 눌린 동안 매 스캔마다 처리 | 이전 키와 비교해 새로 눌린 순간만 처리 |
| FND 옆 자리에 흐린 숫자 | 자리 전환 순서가 틀림 | 모든 자리 끄기 → 세그먼트 → 새 자리 켜기 |
| DHT11 체크섬 오류 | 읽는 도중 인터럽트, 풀업 없음, 1초보다 자주 읽음 | 읽는 동안 긴 ISR 피하기, 4.7 kΩ 풀업, 2초 간격 |
| 릴레이가 부팅할 때 잠깐 붙음 | 출력 초기값이 LOW (능동 LOW 모듈) | CubeMX GPIO output level 을 High 로 |
| 엔코더 값이 반대로 셈 | CLK · DT 배선이 바뀜 | 선을 바꾸거나 코드의 ++/-- 교환 |

## 과제

1. OLED 에 초음파 거리를 막대그래프(0~100 cm → 0~128 픽셀)로 그리세요.
2. DHT11 의 온도가 28 °C 를 넘으면 릴레이(선풍기)를 켜고 26 °C 아래로 내려가면 끄는 **히스테리시스 제어**를 만드세요.
3. 조이스틱으로 OLED 위의 점(8x8 사각형)을 움직이는 간단한 게임을 만드세요.
