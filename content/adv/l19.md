## 학습 목표

- 타이머 **입력 캡처**가 에지 순간의 카운터 값을 CCR 에 저장하는 원리를 설명합니다.
- 캡처 값의 차이로 **주기 · 주파수 · 펄스 폭**을 계산하고, 틱 크기와 오버플로의 관계를 압니다.
- 캡처 **극성(상승 · 하강 · 양쪽)** 을 바꿔 가며 HIGH 폭을 재는 두 가지 방법을 구현합니다.
- HC-SR04 ECHO 폭과 버튼 누른 시간을 CPU 가 기다리지 않고 측정합니다.

## 왜 입력 캡처인가

L17 의 초음파 예제는 ECHO 가 끝날 때까지 `while` 로 기다렸습니다. 기다리는 동안 CPU 는 아무 일도 못 하고,
그 사이 인터럽트가 끼면 잰 시간이 늘어납니다.

입력 캡처는 **에지가 들어온 바로 그 순간 하드웨어가 카운터(CNT) 값을 CCRx 레지스터에 복사**합니다.
소프트웨어가 조금 늦게 읽어도 값은 이미 저장되어 있으므로 정확하고, CPU 는 기다릴 필요가 없습니다.

```text
타이머 클럭 ─► PSC ─► CNT: 0,1,2,3, … 1000, 1001, … 2450 …
                                  │                  │
TIMx_CHn 핀: ____/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\______
                  ↑ 상승 에지        ↑ 하강 에지
                  CCR1 = 1000        CCR1 = 2450   → HIGH 폭 = 1450 틱
```

캡처가 일어나면 CCxIF 플래그가 서고, 인터럽트를 켜 두었으면 `HAL_TIM_IC_CaptureCallback` 이 불립니다.

## 측정 공식

틱 하나의 시간은 $틱 = (PSC + 1) / 타이머 클럭$ 입니다. 84 MHz 에서 PSC = 83 이면 1 µs, PSC = 8399 이면 0.1 ms 입니다.

- **주기** = (다음 상승 에지 캡처 − 이번 상승 에지 캡처) × 틱
- **주파수** = 1 / 주기 = 틱 주파수 / 캡처 차이
- **펄스 폭** = (하강 에지 캡처 − 상승 에지 캡처) × 틱
- **듀티** = 펄스 폭 / 주기

@table[api]
| 틱 (84 MHz 기준 PSC) | 분해능 | 16비트 한 바퀴 | 32비트 한 바퀴 | 알맞은 측정 |
|---|---|---|---|---|
| 84 MHz (PSC 0) | 11.9 ns | 0.78 ms | 51 s | 수 kHz~수 MHz 주파수 |
| 1 MHz (PSC 83) | 1 µs | 65.5 ms | 71.6 분 | 초음파 ECHO, 서보 펄스, RC 수신기 |
| 10 kHz (PSC 8399) | 0.1 ms | 6.55 s | 약 5 일 | 버튼 누른 시간, 느린 회전수 |

### 오버플로와 뺄셈

카운터는 ARR 에 닿으면 0 으로 돌아갑니다. **ARR 이 최댓값(16비트 0xFFFF, 32비트 0xFFFFFFFF)** 이면
부호 없는 뺄셈 `now - last` 가 한 번 넘친 경우까지 자동으로 맞는 값을 줍니다. 예: last = 0xFFFFFFF0, now = 0x10 → 차이 0x20.

- 잴 시간이 **카운터 한 바퀴보다 짧아야** 합니다. 더 길면 업데이트 인터럽트로 넘친 횟수를 세어 더합니다.
- ARR 을 최댓값이 아닌 값으로 두면 뺄셈 결과를 `(ARR + 1)` 로 보정해야 합니다. 그래서 캡처 전용 타이머는 ARR 을 최댓값으로 둡니다.
- F411 에서 32비트 타이머는 **TIM2 · TIM5** 입니다. 긴 시간을 재기 좋습니다.

### 입력 필터와 분주

- **ICFilter**(0~15): 에지 뒤에 같은 레벨이 N 번 샘플링되어야 인정합니다. 잡음이 많은 선에 씁니다.
- **ICPrescaler**(DIV1/2/4/8): 에지 N 번마다 한 번만 캡처합니다. 높은 주파수를 잴 때 인터럽트 수를 줄입니다.
- **PWM 입력 모드**: 두 채널이 한 핀을 보면서 하나는 상승, 하나는 하강을 캡처하고 상승 에지마다 카운터를 0 으로 되돌립니다(슬레이브 리셋). 주기와 폭을 인터럽트 없이 얻을 수 있습니다(시뮬레이터 미지원).

## CubeMX 설정 (TIM2 CH1, PA0)

1. 핀아웃에서 **PA0 → TIM2_CH1** (Nucleo 의 A0 핀)
2. **Timers → TIM2 → Channel1: Input Capture direct mode**
3. Parameter Settings: **Prescaler `83`**, **Counter Period `4294967295`**, Polarity Selection **Rising Edge**, IC Selection Direct, Prescaler Division No division, Input Filter 0
4. **NVIC Settings → TIM2 global interrupt: Enabled**

생성 코드에는 `TIM_IC_InitTypeDef sConfigIC` 와 `HAL_TIM_IC_ConfigChannel()` 이 들어갑니다. 캡처를 시작하는 코드는 직접 씁니다.

```c
HAL_TIM_IC_Start_IT(&htim2, TIM_CHANNEL_1);                          /* 카운터 시작 + CH1 캡처 인터럽트 */
uint32_t v = HAL_TIM_ReadCapturedValue(&htim2, TIM_CHANNEL_1);         /* CCR1 읽기 */
__HAL_TIM_SET_CAPTUREPOLARITY(&htim2, TIM_CHANNEL_1, TIM_INPUTCHANNELPOLARITY_FALLING);   /* 극성 바꾸기 */
```

## 예제 1 — HC-SR04 ECHO 폭을 캡처로 재기

ECHO 를 PA0(TIM2_CH1), TRIG 를 PA8(GPIO)에 연결합니다. 상승 에지에서 값을 저장하고 **극성을 하강으로 바꿔** 다음 에지를 기다립니다.

@sim[l19-ic-ultrasonic] 초음파 입력 캡처 열기

@code[l19-ic-ultrasonic] pv,u0,loop,u4

- 콜백은 여러 타이머 · 채널이 공유하므로 `htim->Instance` 와 `htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1` 로 구분합니다. `Channel` 은 `TIM_CHANNEL_1`(0)이 아니라 `HAL_TIM_ACTIVE_CHANNEL_1`(1)과 비교합니다.
- 트리거 펄스는 TIM2 카운터로 10 µs 를 잽니다. 캡처용 카운터는 **0 으로 되돌리지 않습니다**. 되돌리면 저장해 둔 상승 에지 값이 틀려집니다.
- 측정 중에는 `HAL_Delay(60)` 대신 다른 일을 해도 됩니다. 결과는 `echo_done` 플래그로 확인합니다.
- 시뮬레이터에서 거리 슬라이더를 움직이면 `echo_us` 가 거리 × 58 로 바뀝니다.

## 예제 2 — 버튼 누른 시간 (양쪽 에지)

`TIM_INPUTCHANNELPOLARITY_BOTHEDGE` 로 두면 에지마다 캡처합니다. 대신 **어느 쪽 에지인지 알려 주지 않으므로** 콜백에서 핀 레벨을 읽어 구분합니다.
틱은 0.1 ms(PSC 8399)이고, 앞 에지와 20 ms 안에 들어온 에지는 채터링으로 버립니다.

@sim[l19-ic-button] 버튼 누른 시간 열기

@code[l19-ic-button] pv,loop,u4

- 버튼 모듈(내장 풀업)은 누르면 LOW 입니다. LOW 로 바뀐 에지 = 누름, HIGH 로 바뀐 에지 = 뗌.
- 시뮬레이터의 버튼은 채터링(약 4 ms 동안 3~5번 튐)을 흉내 냅니다. `DEBOUNCE_TICKS` 를 0 으로 바꿔 캡처가 몇 번 일어나는지 보세요.
- 1초 이상 누르면 LONG 으로 판단해 LD2 를 토글합니다. 길게 누르기 / 짧게 누르기로 버튼 하나에 두 기능을 줄 수 있습니다.

:::warn F1 시리즈의 양쪽 에지
STM32F1 의 타이머는 입력 캡처에서 **양쪽 에지(BOTHEDGE)를 지원하지 않습니다**(CCxNP 비트가 입력 모드에서 예약됨).
F1 에서는 예제 1처럼 캡처할 때마다 극성을 바꾸는 방법을 씁니다. F4 · L4 · G0 등은 양쪽 에지를 지원합니다.
:::

:::info 핀은 AF 로
입력 캡처 핀은 GPIO 입력이 아니라 **대체 기능(AF) TIMx_CHn** 입니다. 같은 핀을 `HAL_GPIO_ReadPin` 으로 읽는 것은 가능하지만(IDR 은 AF 모드에서도 핀 레벨을 보여 줌),
EXTI 와 입력 캡처를 한 핀에 함께 걸 필요는 없습니다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 콜백이 불리지 않음 | `HAL_TIM_IC_Start_IT` 누락, NVIC TIM2 꺼짐, 핀이 TIM2_CH1 이 아님 | 시작 코드, NVIC, 핀아웃 확인 |
| 폭이 엉뚱하게 큼 | 캡처 사이에 카운터를 0 으로 되돌림 | `__HAL_TIM_SET_COUNTER` 를 쓰지 않기 |
| 가끔 음수처럼 큰 값 | ARR 이 최댓값이 아니어서 뺄셈이 넘침 | ARR = 0xFFFFFFFF(32비트) 또는 0xFFFF(16비트) |
| 폭 대신 주기가 나옴 | 극성을 바꾸지 않아 상승 에지만 캡처 | 캡처마다 극성 전환, 또는 BOTHEDGE |
| 버튼 시간이 수 ms 로 나옴 | 채터링 에지를 누름/뗌으로 받아들임 | 시간 필터(20 ms), 입력 필터(ICFilter) |
| 다른 채널 콜백에서 값이 바뀜 | `Channel` 확인 누락 | `HAL_TIM_ACTIVE_CHANNEL_n` 비교 |
