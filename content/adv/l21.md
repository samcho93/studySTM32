## 학습 목표

- RTC 의 클럭(LSE 32.768 kHz)과 분주 **128 × 256 = 1 Hz** 구조, 백업 도메인을 설명합니다.
- `HAL_RTC_GetTime` → `HAL_RTC_GetDate` **순서 규칙**과 BCD / BIN 형식을 구분합니다.
- RTC **웨이크업 타이머**로 주기적인 인터럽트를 만듭니다.
- SLEEP · STOP · STANDBY 모드의 차이(멈추는 것, 유지되는 것, 깨우는 원인)를 표로 정리합니다.
- STOP 에서 깨어난 뒤 `SystemClock_Config()` 를 다시 불러야 하는 이유를 압니다.

## RTC 구조

RTC(Real-Time Clock)는 시 · 분 · 초와 연 · 월 · 일 · 요일을 하드웨어로 세는 달력 시계입니다.
메인 클럭과 따로 **백업 도메인**에 있어서, MCU 가 리셋되어도 계속 가고, VBAT 핀에 코인 전지를 달면 전원이 꺼져도 갑니다.

```text
LSE 32.768 kHz ─► ÷(PREDIV_A+1) = ÷128 ─► 256 Hz ─► ÷(PREDIV_S+1) = ÷256 ─► 1 Hz (ck_spre) ─► 초 · 분 · 시 · 날짜
                  AsynchPrediv = 127                  SynchPrediv = 255
```

@table[regmap]
| RTC 클럭 | 정확도 | AsynchPrediv / SynchPrediv | 비고 |
|---|---|---|---|
| **LSE** 32.768 kHz 크리스털 | ±20 ppm 정도 (하루 약 2 초) | 127 / 255 | 시계에는 이것 |
| LSI 약 32 kHz RC | ±수 % (하루 수십 분) | 127 / 249 | 크리스털이 없을 때 임시로 |
| HSE / 분주 | HSE 정확도 | 보드마다 계산 | 저전력 모드에서 꺼짐 |

Nucleo-64 보드는 리비전(C-02 이후)에 따라 32.768 kHz 크리스털(X2)이 달려 있습니다. 보드 매뉴얼 UM1724 에서 확인하세요.

### CubeMX 설정

1. **System Core → RCC → Low Speed Clock (LSE): Crystal/Ceramic Resonator**
2. **Timers → RTC → Activate Clock Source, Activate Calendar** 체크
3. Clock Configuration 탭에서 **RTC Clock Mux → LSE**
4. Parameter Settings: Hour Format 24, Asynchronous 127, Synchronous 255, 초기 시각 · 날짜
5. (웨이크업) **WakeUp: Internal WakeUp**, Wake Up Clock **1 Hz**, Wake Up Counter **0** → NVIC 에서 *RTC wake-up interrupt through EXTI line 22* 켜기

생성된 `MX_RTC_Init()` 은 시각을 **BCD 형식**(`sTime.Hours = 0x23;`)으로 설정합니다. CubeMX 의 규칙입니다.

## 시각 읽기 — 순서가 중요합니다

```c
RTC_TimeTypeDef t;
RTC_DateTypeDef d;
HAL_RTC_GetTime(&hrtc, &t, RTC_FORMAT_BIN);   /* 1) 시각 먼저 */
HAL_RTC_GetDate(&hrtc, &d, RTC_FORMAT_BIN);   /* 2) 반드시 날짜도 */
```

CPU 는 RTC 를 **그림자(shadow) 레지스터**를 통해 읽습니다. 시각 레지스터(TR)를 읽으면 날짜 레지스터(DR)를 읽을 때까지 그림자 값이 **잠깁니다**.
그래서 날짜가 필요 없어도 `GetDate` 를 불러야 다음 `GetTime` 이 새 값을 봅니다. 이 규칙을 어기면 **시계가 멈춘 것처럼** 보입니다.

@table[api]
| 형식 | 23시 59분 51초가 들어오는 모양 | 쓰는 곳 |
|---|---|---|
| `RTC_FORMAT_BIN` | `Hours = 23`, `Seconds = 51` | 계산 · printf `%d` |
| `RTC_FORMAT_BCD` | `Hours = 0x23`, `Seconds = 0x51` (십의 자리 = 위 4비트) | 레지스터 그대로, 7세그먼트 표시 |

`Year` 는 0~99(2000년 기준), `WeekDay` 는 1(월)~7(일)입니다.

## 예제 1 — RTC 달력 시계

CubeMX 에서 2026-12-31 23:59:50 으로 초기화하고, 초가 바뀔 때만 출력합니다. 10 초 뒤 해가 바뀌는지 보세요. B1 을 누르면 같은 시각을 BCD 로도 읽습니다.

@sim[l21-rtc-clock] RTC 달력 시계 열기

@code[l21-rtc-clock] pv,loop

```text
2026-12-31 (Thu) 23:59:51
  BCD raw: Hours=0x23 Minutes=0x59 Seconds=0x51 (BIN 51)
2026-12-31 (Thu) 23:59:52
```

:::warn 리셋할 때마다 시각이 초기값으로 돌아간다면
`MX_RTC_Init()` 은 부팅마다 시각을 다시 씁니다. 실물에서 시각을 유지하려면 CubeMX 가 만든 `USER CODE BEGIN Check_RTC_BKUP` 구역에서
백업 레지스터를 확인해, 이미 설정했으면 `return;` 으로 시각 설정을 건너뜁니다.

```c
/* USER CODE BEGIN Check_RTC_BKUP */
if (HAL_RTCEx_BKUPRead(&hrtc, RTC_BKP_DR0) == 0x32F2) return;   /* 이미 설정됨 */
HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR0, 0x32F2);                  /* 처음: 표시 남기고 아래에서 시각 설정 */
/* USER CODE END Check_RTC_BKUP */
```

백업 레지스터 함수는 시뮬레이터 미지원입니다.
:::

## 웨이크업 타이머

RTC 웨이크업 타이머는 RTC 클럭으로 도는 16비트 다운카운터입니다. 0 이 되면 인터럽트(EXTI 22)를 내고 다시 채워집니다.

```c
HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 0, RTC_WAKEUPCLOCK_CK_SPRE_16BITS);   /* 1 Hz 클럭, 카운터 0 → (0+1) = 1 초마다 */
void HAL_RTCEx_WakeUpTimerEventCallback(RTC_HandleTypeDef *hrtc);          /* 사용자 정의 콜백 */
HAL_RTCEx_DeactivateWakeUpTimer(&hrtc);                                     /* 끄기 */
```

@table[api]
| WakeUpClock | 한 칸 | 범위 |
|---|---|---|
| `RTC_WAKEUPCLOCK_RTCCLK_DIV16` | 16 / 32768 Hz ≈ 488 µs | 488 µs ~ 32 s |
| `RTC_WAKEUPCLOCK_CK_SPRE_16BITS` | 1 s | 1 s ~ 18.2 시간 (카운터 + 1 초) |
| `RTC_WAKEUPCLOCK_CK_SPRE_17BITS` | 1 s | 18.2 ~ 36.4 시간 |

## 저전력 모드 비교

배터리로 몇 달씩 동작하는 장치는 대부분의 시간을 잠들어 있다가, 필요할 때만 깨어나 일하고 다시 잡니다.
STM32F4 의 세 가지 모드는 다음과 같습니다.

@table[api]
| 모드 | 들어가는 함수 | 멈추는 것 | 유지되는 것 | 깨우는 원인 | 깨어난 뒤 | 대표 전류 |
|---|---|---|---|---|---|---|
| **SLEEP** | `HAL_PWR_EnterSLEEPMode(PWR_MAINREGULATOR_ON, PWR_SLEEPENTRY_WFI)` | CPU 클럭만 | 모든 주변장치 · 클럭 · RAM | **아무 인터럽트** (SysTick 포함) | 다음 줄부터 바로 | 수 mA (데이터시트 확인) |
| **STOP** | `HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI)` | PLL · HSI · HSE, 거의 모든 클럭 (SysTick · 타이머 · UART 멈춤) | RAM · 레지스터 · GPIO 상태, LSE · RTC · IWDG | **EXTI 라인** (GPIO EXTI, RTC 웨이크업 · 알람) | 다음 줄부터, 클럭은 **HSI** → `SystemClock_Config()` | 수~수십 µA (데이터시트 확인) |
| **STANDBY** | `HAL_PWR_EnterSTANDBYMode()` | 1.2 V 영역 전체 | 백업 도메인(RTC, 백업 레지스터)만 | WKUP 핀(PA0) 상승, RTC 알람 · 웨이크업, NRST, IWDG | **리셋** — `main()` 처음부터, `PWR_FLAG_SB` 로 확인 | 수 µA (데이터시트 확인) |

- 전류 값은 칩 · 온도 · 전압 · 설정에 따라 크게 다르므로 **반드시 데이터시트의 전기적 특성 표**에서 확인합니다. L0 · L4 · U5 같은 저전력 제품군은 STOP 에서 1 µA 안팎까지 내려갑니다.
- 시뮬레이터 런타임은 모드마다 머문 시간으로 평균 전류를 **대략** 추정합니다(제품군 대표값 기준). 실제 설계는 실측으로 확인합니다.

### SLEEP 과 SysTick

HAL 은 1 ms 마다 SysTick 인터럽트를 냅니다. SLEEP 에 들어가도 1 ms 뒤 SysTick 이 깨우므로 잠든 효과가 거의 없습니다.
그래서 잠들기 전에 `HAL_SuspendTick()`, 깨어난 뒤 `HAL_ResumeTick()` 을 부릅니다. STOP 에서도 같은 짝을 씁니다.

### STOP 에서 깨어나면 클럭부터

STOP 모드는 PLL 을 끄므로, 깨어난 직후 시스템 클럭은 **HSI 16 MHz** 입니다. 그대로 두면 84 MHz 기준으로 계산한
UART 보레이트 · 타이머 주기 · `HAL_Delay` 가 모두 틀어집니다. 깨어나자마자 CubeMX 가 만든 `SystemClock_Config()` 를 다시 부릅니다.

## 예제 2 — STOP 모드 + RTC 1초 웨이크업 + B1

RTC 가 1 초마다, B1(EXTI13)은 누를 때 MCU 를 깨웁니다. 깨어나면 원인과 시각을 출력하고 다시 잡니다.

@sim[l21-stop-wakeup] STOP + 웨이크업 열기

@code[l21-stop-wakeup] loop,u4

```text
[08:00:01] woke by RTC (rtc=1, btn=0)
[08:00:01] woke by B1 (rtc=1, btn=1)
[08:00:02] woke by RTC (rtc=2, btn=1)
```

- 버튼을 한 번 눌러도 채터링 때문에 두세 번 깰 수 있습니다(`btn` 이 여러 번 증가). 깨어난 뒤 20 ms 쯤 기다렸다 레벨을 다시 읽으면 걸러집니다.
- STOP 동안 UART 는 멈춥니다. `printf` 가 **끝난 뒤에** 잠들어야 마지막 글자가 잘리지 않습니다. `HAL_UART_Transmit` 은 전송이 끝날 때까지 기다리므로 안전합니다.
- 시뮬레이터의 콘솔(로그)에 `STOP 모드 진입` 이 찍히고, 잠든 동안에는 가상 시간이 다음 사건까지 건너뜁니다.

:::info STANDBY 를 쓰는 코드의 모양
```c
/* USER CODE BEGIN 2 */
if (__HAL_PWR_GET_FLAG(PWR_FLAG_SB)) {           /* STANDBY 에서 깨어난 리셋인가? */
  __HAL_PWR_CLEAR_FLAG(PWR_FLAG_SB);
  printf("wake from STANDBY\r\n");
}
/* ... 할 일 ... */
__HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);                /* 남아 있는 웨이크업 플래그를 지워야 곧바로 깨지 않음 */
HAL_PWR_EnableWakeUpPin(PWR_WAKEUP_PIN1);         /* PA0 상승 에지로 깨우기 */
HAL_PWR_EnterSTANDBYMode();                        /* 돌아오지 않음 — 다음은 main() 처음 */
```
STANDBY 는 RAM 이 지워지므로, 깨어난 뒤 이어서 할 정보는 RTC 백업 레지스터에 저장합니다.
:::

:::safety 실물에서 저전력 실험할 때
- **디버거 연결이 끊깁니다.** STOP · STANDBY 에서는 SWD 가 응답하지 않아 다시 플래시할 수 없게 보일 수 있습니다. 이때 CubeProgrammer 에서 *Connect under reset* 으로 연결합니다. 개발 중에는 부팅 직후 2~3 초 기다렸다가 잠들게 하면 안전합니다.
- 소비 전류는 Nucleo-64 의 **JP6(IDD) 점퍼**를 빼고 그 자리에 전류계를 직렬로 연결해 잽니다. 전류계 범위를 mA → µA 로 바꾸는 순간 전원이 끊기지 않게 주의하고, 측정 중 핀에 연결된 LED · 모듈 전류도 함께 잡힌다는 점을 기억하세요.
- 쓰지 않는 핀은 아날로그 입력으로 두면 누설 전류가 줄어듭니다. 떠 있는 디지털 입력은 µA 단위 누설을 만듭니다.
- 배선 변경은 USB 를 뽑은 상태에서 합니다.
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 시계가 멈춰 있음 | `GetDate` 를 부르지 않아 그림자 레지스터가 잠김 | `GetTime` 뒤 항상 `GetDate` |
| 시각이 이상한 숫자 (예: 35시) | BCD 값을 `%d` 로 출력 | `RTC_FORMAT_BIN` 으로 읽기 |
| 하루에 몇 분씩 틀림 | LSI 사용 | LSE 크리스털, RTC 클럭 Mux 확인 |
| 리셋할 때마다 시각이 초기화 | `MX_RTC_Init` 이 매번 설정 | 백업 레지스터 확인 후 건너뛰기 |
| STOP 뒤 UART 글자가 깨짐 | 클럭이 HSI 로 돌아옴 | 깨어난 뒤 `SystemClock_Config()` |
| SLEEP 에 들어가도 전류가 그대로 | SysTick 이 1 ms 마다 깨움 | `HAL_SuspendTick()` |
| STOP 에서 영원히 깨지 않음 | 깨울 EXTI · RTC 인터럽트가 NVIC 에서 꺼짐 | RTC_WKUP / EXTI15_10 켜기 |
| STANDBY 에 들어가자마자 깨어남 | WUF 플래그가 남아 있음 | `__HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU)` 뒤 진입 |
