## 학습 목표

- DMA 가 **CPU 개입 없이** 주변장치와 메모리 사이에서 데이터를 옮기는 원리를 설명합니다.
- STM32F4 의 **DMA 컨트롤러 · 스트림 · 채널** 구조와 ADC1 · USART2 의 DMA 연결을 찾습니다.
- **원형(Circular) 모드**와 **절반 완료 / 전체 완료 콜백**으로 ADC 다채널 값을 블록 단위로 처리합니다.
- UART **IDLE 감지**(`HAL_UARTEx_ReceiveToIdle_IT` / `_DMA`)로 길이를 모르는 명령을 받습니다.

## DMA 란

폴링이나 인터럽트 방식에서는 바이트 하나, 변환 값 하나마다 **CPU 가 직접** 읽어서 메모리에 씁니다.
DMA(Direct Memory Access)는 이 복사를 전담하는 하드웨어입니다. CPU 는 "어디서, 어디로, 몇 개" 만 알려 주고 다른 일을 합니다.

```text
폴링/인터럽트:  ADC ──► CPU(읽기) ──► CPU(쓰기) ──► RAM      값마다 CPU 가 일함
DMA           :  ADC ──────── DMA ──────────────► RAM      CPU 는 끝났다는 알림만 받음
```

@table[api]
| 방식 | CPU 부담 | 알맞은 곳 |
|---|---|---|
| 폴링 | 기다리는 동안 CPU 전부 | 간단한 1회성 측정 |
| 인터럽트 | 값(바이트)마다 ISR 한 번 | 느린 입력, 짧은 명령 |
| DMA | 블록 끝(또는 절반)마다 ISR 한 번 | ADC 연속 샘플링, UART 대량 송수신, SPI 디스플레이 |

### 스트림과 채널 (STM32F4)

F4 에는 DMA1 · DMA2 두 컨트롤러가 있고, 각각 **스트림 8개(Stream0~7)** 를 가집니다. 스트림마다 **채널 8개** 중 하나를 골라
어느 주변장치의 요청을 받을지 정합니다. 조합은 레퍼런스 매뉴얼의 DMA 요청 표에 고정되어 있습니다.

@table[regmap]
| 요청 | 컨트롤러 | 스트림 | 채널 | 방향 |
|---|---|---|---|---|
| ADC1 | DMA2 | Stream0 (또는 Stream4) | Channel 0 | 주변장치 → 메모리 |
| USART2_RX | DMA1 | Stream5 | Channel 4 | 주변장치 → 메모리 |
| USART2_TX | DMA1 | Stream6 | Channel 4 | 메모리 → 주변장치 |

F1 · F0 · L0 등은 스트림 없이 **채널 번호가 요청마다 정해져** 있고(예: F103 의 ADC1 = DMA1 Channel1), G0 · G4 · L4+ · U5 는 DMAMUX 로 아무 채널에나 요청을 연결합니다.
CubeMX 의 **DMA Settings → Add** 가 이 선택을 대신해 주므로 표를 외울 필요는 없습니다.

### DMA 설정 항목

- **Direction**: Peripheral → Memory(수신·ADC), Memory → Peripheral(송신)
- **Mode**: Normal(한 번 옮기고 멈춤) / **Circular**(끝나면 처음부터 다시, 멈추지 않음)
- **Increment**: 주변장치 주소는 고정, 메모리 주소는 증가(배열을 채움)
- **Data width**: Byte / Half Word(16비트, ADC) / Word
- **인터럽트**: 전송의 **절반**(HT, Half Transfer)과 **전체**(TC, Transfer Complete)에서 발생

## 원형 DMA 와 절반 / 전체 콜백

원형 모드에서 DMA 는 배열 끝에 닿으면 곧바로 앞에서부터 다시 씁니다. 그래서 CPU 가 배열을 읽는 동안에도 값이 계속 바뀝니다.
이 문제는 배열을 반으로 나누어 해결합니다(핑퐁 버퍼).

```text
adc_buf[32]:  [ 앞 절반 0~15 ][ 뒤 절반 16~31 ]
                DMA 가 채우는 중 ─────►
HT 인터럽트:  앞 절반이 찼다 → CPU 는 앞 절반 처리  (DMA 는 뒤 절반을 채우는 중)
TC 인터럽트:  뒤 절반이 찼다 → CPU 는 뒤 절반 처리  (DMA 는 다시 앞 절반을 채우는 중)
```

HAL 은 HT 에서 `HAL_ADC_ConvHalfCpltCallback`, TC 에서 `HAL_ADC_ConvCpltCallback` 을 부릅니다.
CPU 가 반쪽을 처리하는 시간이 DMA 가 다른 반쪽을 채우는 시간보다 짧으면 값이 섞이지 않습니다.

## 예제 1 — ADC 2채널 + 원형 DMA

L09 의 DMA 예제는 배열의 최신 값만 읽었습니다. 이번에는 채널마다 16개씩 모아 **평균**을 냅니다.

### CubeMX 설정

1. **Analog → ADC1**: IN0, IN1 체크. Scan Conversion **Enabled**, Continuous Conversion **Enabled**, **DMA Continuous Requests Enabled**
2. Rank 1 = Channel 0, Rank 2 = Channel 1 (Number Of Conversion 2)
3. **DMA Settings → Add → ADC1**: DMA2 Stream0, Mode **Circular**, Data Width **Half Word**
4. **NVIC**: *DMA2 stream0 global interrupt* 가 켜져 있는지 확인 (DMA 를 추가하면 자동으로 켜짐)

@sim[l18-adc-dma] ADC + 원형 DMA 열기

@code[l18-adc-dma] pv,u0,u2,u4

- 배열은 `[IN0, IN1, IN0, IN1, …]` 순서로 채워집니다. rank 순서가 곧 배열 순서입니다.
- `HAL_ADC_Start_DMA` 를 한 번 부르면 끝입니다. 메인 루프에는 ADC 코드가 없습니다.
- 콜백은 인터럽트 문맥이므로 평균 계산처럼 **짧은 일만** 하고, `printf` 는 메인 루프에서 합니다.
- 시뮬레이터에서 가변저항 · 조도센서 값을 바꾸면 평균이 바로 따라옵니다.

### 실물에서는 콜백이 얼마나 자주 불릴까

F411 기본 설정(ADC 클럭 = 84 MHz / 4 = 21 MHz, 샘플링 84 사이클 + 변환 12 사이클)이면 변환 한 번에
$96 사이클 / 21 MHz ≈ 4.57 µs$ 입니다. 32칸을 한 바퀴 도는 데 약 146 µs, **HT · TC 콜백이 73 µs 마다** 불립니다.

- 이 정도는 괜찮지만, 채널이 적고 샘플링 시간이 짧으면 콜백이 수 µs 마다 불려 CPU 가 콜백만 처리하게 됩니다.
- 샘플링 주기를 정확히 정하려면 **연속 변환을 끄고 타이머 트리거**(예: TIM3 TRGO 1 kHz)로 변환을 시작합니다. 오디오 · 진동 측정의 표준 구조입니다.
- 시뮬레이터는 DMA 배열을 1 ms 마다 채우고 콜백을 부르므로, 콜백 횟수(`blocks`)는 실물과 다릅니다.

:::info F7 · H7 의 D-캐시
Cortex-M7(F7 · H7)은 데이터 캐시가 있어 DMA 가 RAM 에 쓴 값을 CPU 가 캐시의 옛 값으로 읽을 수 있습니다.
DMA 버퍼를 캐시하지 않는 영역(MPU 설정)에 두거나, 읽기 전에 `SCB_InvalidateDCache_by_Addr()` 로 캐시를 무효화합니다. F4 에는 SRAM 용 데이터 캐시가 없어(ART 가속기는 플래시 읽기용) 신경 쓰지 않아도 됩니다.
:::

## UART 가변 길이 수신 — IDLE 감지

L06 의 `HAL_UART_Receive_IT(&huart2, buf, n)` 은 **정확히 n 바이트**가 와야 콜백이 불립니다. 명령 길이가 제각각이면 1바이트씩 받아 줄 끝을 찾아야 했습니다.

USART 는 수신선이 **1문자 시간 동안 조용하면 IDLE 플래그**를 세웁니다(115200 bps 에서 10비트 = 약 87 µs).
`HAL_UARTEx_ReceiveToIdle_IT` / `_DMA` 는 이 IDLE 을 이용해 "한 덩어리가 끝났다" 는 순간에 콜백을 부르고, **받은 길이**를 알려 줍니다.

```c
HAL_StatusTypeDef HAL_UARTEx_ReceiveToIdle_IT (UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size);
HAL_StatusTypeDef HAL_UARTEx_ReceiveToIdle_DMA(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size);
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size);   /* Size = 받은 바이트 수 */
```

콜백은 ① IDLE 이 감지될 때, ② 버퍼(Size)가 가득 찰 때 불립니다. DMA 판에서는 ③ DMA 절반 완료 때도 불립니다.

## 예제 2 — 명령 한 줄 받기

터미널에서 `led on`, `led off`, `status` 를 입력해 보세요. 한 줄을 통째로 받아 처리합니다.

@sim[l18-uart-idle] ReceiveToIdle 명령 수신 열기

@code[l18-uart-idle] pv,u2,loop,u4

- 콜백은 길이만 저장하고, 복사 · 문자열 비교 · 응답은 메인 루프에서 합니다.
- 수신은 한 번 끝나면 멈추므로, 처리 전에 **다시 `ReceiveToIdle_IT` 를 불러** 다음 줄을 받을 준비를 합니다. 버퍼를 먼저 `cmd` 로 복사해 두었으므로 덮어써도 안전합니다.
- 터미널이 `\r\n` 을 보내므로 끝의 줄바꿈을 지우고 비교합니다.

### DMA 판으로 바꾸기 (실물)

바이트가 많거나 보레이트가 높으면 `_DMA` 판이 CPU 부담이 적습니다.

1. **USART2 → DMA Settings → Add → USART2_RX**: DMA1 Stream5, Mode Normal, Data Width Byte
2. **NVIC**: *USART2 global interrupt* 를 켭니다. IDLE 은 UART 인터럽트로 알립니다.
3. 코드에서 `_IT` 를 `_DMA` 로 바꾸고, 시작 직후 절반 완료 인터럽트를 끕니다.

```c
HAL_UARTEx_ReceiveToIdle_DMA(&huart2, rx_buf, RX_BUF_SIZE);
__HAL_DMA_DISABLE_IT(&hdma_usart2_rx, DMA_IT_HT);   /* 절반 완료 때 콜백이 불리지 않게 */
```

:::info 시뮬레이터
시뮬레이터의 `HAL_UARTEx_ReceiveToIdle_DMA` 는 `_IT` 판과 같게 동작하고, CubeMX 화면에 UART 용 DMA 설정은 아직 없습니다.
그래서 예제는 실물에서도 추가 설정 없이 동작하는 `_IT` 판으로 작성했습니다. `hdma_usart2_rx`, `__HAL_DMA_DISABLE_IT` 는 실물 CubeIDE 에서 씁니다.
:::

## DMA 송신

`HAL_UART_Transmit_DMA(&huart2, buf, len)` 은 전송을 시작하자마자 돌아오고, 끝나면 `HAL_UART_TxCpltCallback` 이 불립니다.
**전송이 끝나기 전에 `buf` 를 바꾸면 바뀐 내용이 나갑니다.** 지역 배열을 넘기면 함수가 끝나면서 사라지므로 전역(또는 static) 버퍼를 씁니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| DMA 배열이 계속 0 | `MX_DMA_Init()` 이 `MX_ADC1_Init()` 보다 뒤에 있음, DMA Continuous Requests 꺼짐 | 초기화 순서(L09), ADC 설정 확인 |
| 한 번만 채워지고 멈춤 | DMA Mode 가 Normal | Circular 로 변경 |
| 배열 값이 뒤섞여 보임 | Data Width 가 Word 인데 배열은 `uint16_t` | ADC 는 Half Word 와 `uint16_t` |
| 메인 루프가 거의 돌지 않음 | 연속 변환 + 짧은 배열로 콜백이 너무 자주 불림 | 배열을 키우거나 타이머 트리거 사용 |
| `RxEventCallback` 이 한 번만 불림 | 콜백 뒤 수신을 다시 시작하지 않음 | 처리 후 `ReceiveToIdle_IT` 다시 호출 |
| DMA 판에서 명령이 반으로 잘려 옴 | 절반 완료(HT) 때도 콜백이 불림 | `__HAL_DMA_DISABLE_IT(&hdma_usart2_rx, DMA_IT_HT)` |
| 콜백이 전혀 불리지 않음 | USART2 global interrupt 꺼짐 | NVIC 에서 켜기 |
