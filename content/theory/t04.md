## 학습 목표

- HSI · HSE · LSI · LSE 네 클럭 소스의 주파수 · 정확도 · 용도를 구분합니다.
- PLL 의 M · N · P · Q 분주 · 체배를 계산해 원하는 SYSCLK 을 만들고, 제약 조건(VCO 범위, 최대 클럭)을 검사할 수 있습니다.
- AHB · APB 프리스케일러와 **타이머 클럭 ×2 규칙**, 플래시 대기 상태(latency)와 전압 스케일의 관계를 설명할 수 있습니다.
- SysTick 이 어떻게 1 ms 틱을 만들고 `HAL_Delay` · `HAL_GetTick` 이 그 위에서 동작하는지 압니다.
- MCO 와 클럭 보안 시스템(CSS), 리셋의 종류와 `RCC->CSR` 로 리셋 원인을 읽는 법, Sleep · Stop · Standby 저전력 모드의 차이를 압니다.

## 클럭 소스 네 가지

@table[regmap]
| 소스 | 주파수 (F411) | 정확도 | 켜는 데 걸리는 시간 | 용도 |
|---|---|---|---|---|
| **HSI** | 16 MHz 내부 RC | ±1 % (25 °C, 공장 보정), −10~85 °C 에서 ±4 %, −40~105 °C 에서 −8~+4.5 % | 수 µs | 리셋 직후 기본 클럭, 외부 부품 없이 동작, PLL 입력 |
| **HSE** | 4 ~ 26 MHz 외부 크리스털 (바이패스 시 50 MHz) | 크리스털 ±20~50 ppm | 수 ms | USB · 정밀 UART · CAN 처럼 정확한 클럭이 필요할 때, PLL 입력 |
| **LSI** | 약 32 kHz 내부 RC (17~47 kHz) | 매우 낮음 | 수십 µs | IWDG 워치독, Standby 에서 RTC 임시 |
| **LSE** | 32.768 kHz 외부 크리스털 | ±20 ppm | 수백 ms ~ 1 s | RTC 시계, 저전력 모드에서 깨우기 |

F103 은 HSI 가 **8 MHz** 이고 나머지는 비슷합니다. G0 · L4 · U5 등 신형은 HSI 16 MHz 에 더해 MSI(다중 속도 내부 RC), HSI48(USB 용) 이 있습니다.

Nucleo-64 보드에는 HSE 용 크리스털 X3 자리가 있지만 **기본으로 미장착**이고, ST-Link 의 MCU 가 내보내는 8 MHz MCO 신호가 솔더 브리지를 거쳐 HSE 입력(PH0)으로 들어갈 수 있게 되어 있습니다(UM1724 의 보드별 기본 설정 표를 확인하세요).
이 강좌의 시뮬레이터와 예제는 외부 부품에 의존하지 않도록 **HSI → PLL → 84 MHz** 를 씁니다.

:::info 왜 굳이 PLL 을 쓰는가
HSI 16 MHz 로도 동작은 합니다. 그러나 84 MHz 로 올리면 같은 일을 5배 빨리 끝내고, 타이머 분해능이 높아지며, UART 보레이트 오차가 줄어듭니다.
소비 전력은 대략 클럭에 비례하므로(F411 약 100 µA/MHz 급) 배터리 기기는 필요한 만큼만 올립니다.
:::

## PLL 계산

@fig[clock-tree] STM32F411 클럭 트리. 이 강좌의 기본 설정(HSI 16 MHz, M = 16, N = 336, P = 4, Q = 7)을 값으로 적었습니다. 시뮬레이터의 클럭 & 프로젝트 탭이 같은 그림을 보여 줍니다.

F4 의 메인 PLL 은 네 개의 값으로 정해집니다.

$f_{VCO,in} = f_{PLL,src} / M$, $f_{VCO,out} = f_{VCO,in} × N$, $f_{PLLCLK} = f_{VCO,out} / P$, $f_{PLL48} = f_{VCO,out} / Q$

| 값 | 범위 (F411) | 제약 | 뜻 |
|---|---|---|---|
| M | 2 ~ 63 | VCO 입력 **1 ~ 2 MHz** (지터를 줄이려면 2 MHz 권장, HSI 는 1 MHz 도 흔함) | 입력 분주 |
| N | 50 ~ 432 | VCO 출력 **100 ~ 432 MHz** | 체배 |
| P | 2, 4, 6, 8 | SYSCLK **≤ 100 MHz** | 시스템 클럭용 분주 |
| Q | 2 ~ 15 | USB OTG FS 는 **정확히 48 MHz** 필요, SDIO ≤ 48 MHz | USB · SDIO · RNG 용 분주 |

이 강좌의 84 MHz 설정을 따라가 봅시다.

$16 MHz / 16 = 1 MHz$ → $1 MHz × 336 = 336 MHz$ (100~432 안) → $336 / 4 = 84 MHz$ (SYSCLK) → $336 / 7 = 48 MHz$ (USB)

100 MHz 를 만들려면 N = 400, P = 4 (VCO 400 MHz) 로 하면 되지만, 400 을 정수로 나눠 48 이 나오지 않으므로 **USB 를 쓸 수 없습니다.**
그래서 F411 에서 USB 가 필요하면 96 MHz (N = 192, P = 2, Q = 4 → 48 MHz) 나 84 MHz 를 고릅니다. CubeMX 의 클럭 탭은 이런 제약을 자동으로 검사해 빨간색으로 표시합니다.

F103 의 PLL 은 훨씬 단순해서 입력(HSI/2 = 4 MHz 또는 HSE) × 2~16 뿐입니다. 72 MHz = 8 MHz HSE × 9 이고, HSI 만으로는 4 × 16 = 64 MHz 가 최대입니다.

### CubeMX 가 만드는 코드

```c
void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  __HAL_RCC_PWR_CLK_ENABLE();
  __HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE2);   /* 84 MHz 까지는 스케일 2 */

  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSI;
  RCC_OscInitStruct.HSIState = RCC_HSI_ON;
  RCC_OscInitStruct.HSICalibrationValue = RCC_HSICALIBRATION_DEFAULT;
  RCC_OscInitStruct.PLL.PLLState = RCC_PLL_ON;
  RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSI;
  RCC_OscInitStruct.PLL.PLLM = 16;
  RCC_OscInitStruct.PLL.PLLN = 336;
  RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV4;
  RCC_OscInitStruct.PLL.PLLQ = 7;
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK) Error_Handler();   /* PLL 잠금 대기 포함 */

  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource = RCC_SYSCLKSOURCE_PLLCLK;
  RCC_ClkInitStruct.AHBCLKDivider = RCC_SYSCLK_DIV1;      /* HCLK  = 84 MHz */
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;       /* PCLK1 = 42 MHz (최대 50) */
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;       /* PCLK2 = 84 MHz (최대 100) */
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_2) != HAL_OK) Error_Handler();
}
```

`HAL_RCC_ClockConfig` 는 대기 상태를 늘릴 때는 클럭을 올리기 **전에**, 줄일 때는 **후에** FLASH->ACR 을 고칩니다. 순서가 틀리면 플래시를 읽을 수 없어 HardFault 가 납니다. 레지스터를 직접 다룰 때 자주 놓치는 부분입니다.

## 버스 클럭과 타이머 ×2 규칙

| 클럭 | 계산 | F411 (이 강좌) | F103 (72 MHz) | 최대 (F411 / F103) |
|---|---|---|---|---|
| SYSCLK | PLL 출력 | 84 MHz | 72 MHz | 100 / 72 |
| HCLK (AHB) | SYSCLK ÷ AHB 프리스케일러 (1~512) | 84 MHz | 72 MHz | 100 / 72 |
| PCLK1 (APB1) | HCLK ÷ 1·2·4·8·16 | 42 MHz | 36 MHz | 50 / 36 |
| PCLK2 (APB2) | HCLK ÷ 1·2·4·8·16 | 84 MHz | 72 MHz | 100 / 72 |
| APB1 타이머 | PCLK1 × 2 (분주비 ≠ 1 일 때) | **84 MHz** | **72 MHz** | |
| APB2 타이머 | PCLK2 × 1 (분주비 = 1 일 때) | 84 MHz | 72 MHz | |
| ADC (F411) | PCLK2 ÷ 2·4·6·8 | 21 MHz (÷4) | 12 MHz (PCLK2 ÷ 6, 최대 14) | 36 / 14 |
| SysTick | HCLK 또는 HCLK ÷ 8 | 84 MHz | 72 MHz | |

**타이머 ×2 규칙**: APB 프리스케일러가 1 이면 타이머 클럭 = PCLK, 1 이 아니면 **타이머 클럭 = PCLK × 2** 입니다.
APB1 이 최대 50 MHz 로 제한되어 있어 HCLK 84 MHz 를 2 로 나눠야 하는데, 그러면 타이머 분해능까지 떨어지므로 ST 가 타이머에만 두 배를 돌려주는 것입니다.
그래서 이 강좌의 F411 설정에서는 APB1 의 TIM2~5 도, APB2 의 TIM1 · 9~11 도 **모두 84 MHz** 를 받습니다. [L07](l07.html) 의 PSC · ARR 계산이 84 MHz 로 시작하는 이유입니다.

반면 USART2 · I2C1 · SPI2 는 APB1 에 있어 **42 MHz** 를 받습니다. [T08](t08.html) 의 보레이트 계산에서 USART2 는 42 MHz, USART1 은 84 MHz 로 계산해야 하는 이유입니다.

@sim[l07-timer] 클럭 탭에서 타이머 클럭 확인하기

시뮬레이터의 **클럭 & 프로젝트** 탭에서 SYSCLK 을 바꾸면 PCLK1 · PCLK2 · 타이머 클럭이 함께 바뀌고, 타이머 Properties 의 "주기" 계산이 달라지는 것을 볼 수 있습니다.

## 플래시 대기 상태와 전압 스케일

플래시 메모리는 코어보다 느립니다. F411 의 플래시 접근 시간은 수십 ns 이므로 HCLK 이 빠를수록 **대기 상태(wait state, latency)** 를 넣어야 합니다.

| 전압 | 0 WS | 1 WS | 2 WS | 3 WS |
|---|---|---|---|---|
| 2.7 ~ 3.6 V (Nucleo) | ≤ 30 MHz | ≤ 64 MHz | **≤ 90 MHz** | ≤ 100 MHz |
| 2.4 ~ 2.7 V | ≤ 24 MHz | ≤ 48 MHz | ≤ 72 MHz | ≤ 96 MHz |
| 1.71 ~ 2.1 V | ≤ 16 MHz | ≤ 32 MHz | ≤ 48 MHz | ≤ 64 MHz |

84 MHz 는 3.3 V 에서 2 WS 이므로 `FLASH_LATENCY_2` 입니다. F103 은 0 WS ≤ 24 MHz, 1 WS ≤ 48 MHz, 2 WS ≤ 72 MHz 입니다.

대기 상태가 2 라는 것은 플래시에서 한 워드를 읽을 때 3 사이클이 걸린다는 뜻인데, 그러면 84 MHz 코어가 사실상 28 MHz 처럼 동작할 것 같습니다.
ST 는 이를 **ART Accelerator**(128비트 프리페치 + 명령 캐시 64줄 + 데이터 캐시 8줄)로 가립니다. `HAL_Init()` 이 `FLASH->ACR` 의 PRFTEN · ICEN · DCEN 을 켭니다.
순차 실행 코드는 거의 0 WS 처럼 돌지만, 분기가 많은 코드는 조금 느려집니다. 정밀한 시간이 필요한 루프는 그래서 타이머로 재야 합니다.

**전압 스케일**은 코어 내부 전압 조정기(1.2 V 도메인)의 출력을 낮춰 전력을 아끼는 기능입니다. F411 은 스케일 3 (≤ 64 MHz), 스케일 2 (≤ 84 MHz), 스케일 1 (≤ 100 MHz) 이고, 위 코드의 `PWR_REGULATOR_VOLTAGE_SCALE2` 가 그것입니다.
클럭을 100 MHz 로 올릴 때 스케일 1 로 바꾸지 않으면 동작이 불안정해집니다. CubeMX 는 자동으로 맞춥니다.

## SysTick 과 HAL_Delay

SysTick 은 Cortex-M 코어에 내장된 24비트 다운카운터입니다. `HAL_Init()` 안의 `HAL_InitTick()` 이 이렇게 설정합니다.

```c
/* HAL_InitTick (stm32f4xx_hal.c) 의 핵심 */
HAL_SYSTICK_Config(SystemCoreClock / (1000U / uwTickFreq));   /* 84 000 000 / 1000 = 84 000 → 1 ms 마다 */
HAL_NVIC_SetPriority(SysTick_IRQn, TickPriority, 0U);         /* TICK_INT_PRIORITY (hal_conf.h) */

/* stm32f4xx_it.c */
void SysTick_Handler(void) { HAL_IncTick(); }                 /* uwTick++ */

/* stm32f4xx_hal.c */
__weak void HAL_Delay(uint32_t Delay)
{
  uint32_t tickstart = HAL_GetTick();
  uint32_t wait = Delay;
  if (wait < HAL_MAX_DELAY) wait += (uint32_t)uwTickFreq;     /* 최소 대기 시간 보장을 위해 +1 */
  while ((HAL_GetTick() - tickstart) < wait) { }
}
```

- SysTick 은 HCLK (84 MHz) 을 세므로 리로드 값 83 999 → 1 ms 입니다. 리로드는 24비트(최대 16 777 215)라 84 MHz 에서 약 200 ms 까지 가능합니다.
- `HAL_Delay(1)` 은 **1 ~ 2 ms** 를 기다립니다 (호출 시점이 틱 경계 어디인지 모르므로 +1). 정확한 1 ms 가 필요하면 타이머를 씁니다.
- `HAL_GetTick()` 은 32비트 `uwTick` 을 돌려주므로 약 49.7 일마다 0 으로 돌아옵니다. `(now - start) >= period` 처럼 **뺄셈으로 비교**하면 넘어가도 문제없습니다. `now >= start + period` 는 틀립니다.
- `SystemCoreClock` 은 전역 변수이며 `HAL_RCC_ClockConfig` 가 갱신합니다. 클럭을 바꾼 뒤 `HAL_InitTick` 을 다시 부르지 않으면 틱이 틀어집니다 (HAL 이 자동으로 부릅니다).

인터럽트 핸들러 안에서 `HAL_Delay` 를 부르면 그 핸들러의 우선순위가 SysTick 보다 높거나 같을 때 `uwTick` 이 멈춰 **영원히 기다립니다.** 이 함정은 [T06](t06.html) 에서 우선순위와 함께 다룹니다.

## MCO 와 클럭 보안

- **MCO(Microcontroller Clock Output)**: 내부 클럭을 핀으로 내보냅니다. F411 은 MCO1 (PA8: HSI · LSE · HSE · PLL 중 하나, 1~5 분주) 과 MCO2 (PC9: SYSCLK · PLLI2S · HSE · PLL) 가 있습니다. 오실로스코프로 "정말 84 MHz 인가" 를 확인하거나 다른 칩에 클럭을 공급할 때 씁니다. Nucleo 의 ST-Link 가 8 MHz 를 내보내는 것도 ST-Link MCU 의 MCO 입니다.
- **CSS(Clock Security System)**: HSE 를 쓰다가 크리스털이 멈추면(납땜 불량, 충격) 하드웨어가 자동으로 HSI 로 바꾸고 **NMI** 를 일으킵니다. `HAL_RCC_EnableCSS()` 로 켜고 `NMI_Handler` 에서 `HAL_RCC_NMI_IRQHandler()` → `HAL_RCC_CSSCallback()` 으로 알 수 있습니다. HSE 를 쓰는 제품에서는 켜 두는 것이 안전합니다.
- **HSI 트리밍**: `RCC->CR` 의 HSITRIM (5비트) 로 HSI 를 ±수 % 미세 조정할 수 있습니다. HSE 없이 UART 오차를 줄일 때 씁니다.

## 리셋의 종류와 원인 읽기

STM32 의 리셋은 세 겹입니다.

| 리셋 | 원인 | 초기화되는 것 |
|---|---|---|
| **시스템 리셋** | NRST 핀 LOW, 워치독(IWDG · WWDG), 소프트웨어(`NVIC_SystemReset()`), 저전력 모드 진입 오류, 옵션 바이트 로드 | 코어 · 모든 주변장치 (RTC · 백업 영역 · RCC->CSR 플래그 제외) |
| **전원 리셋** | POR/PDR (전원 인가 · 차단), BOR (전압 강하), Standby 에서 복귀 | 시스템 리셋 + 백업 도메인 일부 |
| **백업 도메인 리셋** | `RCC->BDCR` 의 BDRST 비트, VBAT · VDD 모두 차단 | RTC · 백업 레지스터 · LSE |

- **NRST** 핀은 내부 풀업(약 40 kΩ)이 있고, 내부 리셋이 일어나면 칩이 NRST 를 밖으로 LOW 로 끌어내리므로(양방향) 외부 회로에 리셋을 알릴 수도 있습니다. Nucleo 의 검은색 버튼 B2 가 NRST 입니다.
- **BOR(Brown-Out Reset)**: 옵션 바이트로 문턱을 정합니다 (F411: 꺼짐(기본값) / 레벨 1 약 2.2 V / 레벨 2 약 2.5 V / 레벨 3 약 2.8 V — 하강 시 typ 2.19 · 2.50 · 2.83 V, DS10314 의 *Embedded reset and power control block characteristics* 표). 전압이 그 아래로 떨어지면 리셋 상태로 붙들어 플래시가 깨지는 것을 막습니다.

리셋 후 `RCC->CSR` 의 상위 비트를 읽으면 **직전 리셋의 원인**을 알 수 있습니다. 플래그는 다음 리셋까지 유지되므로 읽은 뒤 RMVF 로 지웁니다.

```c
/* main() 첫머리 — 어떤 리셋으로 시작했는지 UART 로 기록 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST)) printf("reset: IWDG watchdog\r\n");   /* CSR bit 29 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST)) printf("reset: WWDG\r\n");            /* bit 30 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_SFTRST))  printf("reset: software\r\n");        /* bit 28 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_PORRST))  printf("reset: power-on\r\n");        /* bit 27 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_PINRST))  printf("reset: NRST pin\r\n");        /* bit 26 (다른 리셋과 함께 서기도 함) */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_BORRST))  printf("reset: brown-out\r\n");       /* bit 25 */
if (__HAL_RCC_GET_FLAG(RCC_FLAG_LPWRRST)) printf("reset: low-power\r\n");       /* bit 31 */
__HAL_RCC_CLEAR_RESET_FLAGS();                                                   /* RMVF = 1 */
```

제품이 "가끔 재부팅된다" 는 문제를 추적할 때 이 코드가 첫 단서가 됩니다. IWDG 플래그가 서 있으면 어딘가에서 루프가 멈춘 것이고, BOR 이면 전원이 약한 것입니다.

| **Run** | — | — | — | — | 약 100 µA/MHz (84 MHz 에서 10 mA 안팎) |
| **Sleep** | `__WFI()` 또는 `HAL_PWR_EnterSLEEPMode` | 코어 클럭만 | 모든 주변장치 · SRAM · 레지스터 | 아무 인터럽트 | 수 mA (주변장치에 따라) |
| **Stop** | `HAL_PWR_EnterSTOPMode` | 1.2 V 도메인 클럭 전부, HSI · HSE · PLL | SRAM · 레지스터 · GPIO 상태 | EXTI (핀 · RTC 알람 · RTC 웨이크업) | 약 42 µA typ (플래시 Stop), 플래시 Deep power-down 이면 약 9 µA (25 °C) |
| **Standby** | `HAL_PWR_EnterSTANDBYMode` | 1.2 V 도메인 전원 자체 | RTC · 백업 레지스터 · 백업 SRAM (없음, F411) | WKUP 핀 (PA0), RTC, NRST, IWDG | 약 1.8 µA (25 °C, 1.7 V, RTC 끔) |

- Stop 에서 깨어나면 클럭이 **HSI 16 MHz** 로 돌아오므로 `SystemClock_Config()` 를 다시 불러 PLL 을 켜야 합니다. SysTick 도 멈춰 있었으므로 `HAL_GetTick()` 은 Stop 동안의 시간을 모릅니다 — 시간이 필요하면 RTC 를 씁니다.
- Standby 에서 깨어나는 것은 **리셋과 같습니다.** `main()` 처음부터 다시 시작하며, 변수는 모두 사라집니다. 상태를 남기려면 RTC 백업 레지스터(20 × 32비트)를 씁니다.
- 실제 전류는 GPIO 설정(플로팅 입력이 있으면 전류 증가), 풀업, 외부 회로가 좌우합니다. 데이터시트 값은 모든 핀을 아날로그 모드로 두고 잰 것입니다.
- 디버거가 붙어 있으면 저전력 모드에서 클럭이 계속 돌기도 합니다 (`DBGMCU->CR`). 전류 측정은 디버거를 떼고 하세요.

:::check 스스로 확인
- HSE 8 MHz 로 84 MHz 를 만드는 M · N · P 를 하나 고르고 VCO 범위를 확인하세요.
- PCLK1 을 21 MHz (÷4) 로 바꾸면 TIM3 클럭은 얼마가 됩니까?
- 3.3 V 에서 100 MHz 로 올리려면 대기 상태와 전압 스케일을 어떻게 해야 합니까?
- `HAL_Delay(10)` 이 실제로는 몇 ms 를 기다립니까?
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `SystemClock_Config` 에서 `Error_Handler()` 로 감 | HSE 를 골랐는데 크리스털이 없음 (Nucleo 기본), PLL 값이 범위 밖 | HSI 로 바꾸거나 UM1724 의 솔더 브리지 확인. CubeMX 클럭 탭의 빨간 표시 해결 |
| 타이머 · UART 속도가 정확히 2배 · ½ | 타이머 ×2 규칙을 빠뜨림, USART2 (42 MHz) 와 USART1 (84 MHz) 을 혼동 | 클럭 트리에서 해당 주변장치의 실제 클럭 확인 |
| 클럭을 올리니 HardFault 또는 멈춤 | 플래시 대기 상태 · 전압 스케일 미설정 | `HAL_RCC_ClockConfig(..., FLASH_LATENCY_n)` 의 n 을 표에 맞춤, `PWR_REGULATOR_VOLTAGE_SCALE1` |
| `HAL_Delay` 가 끝나지 않음 | 인터럽트 안에서 호출, `__disable_irq()` 상태, SysTick 우선순위가 낮음 | ISR 에서 HAL_Delay 금지, 우선순위 정리 ([T06](t06.html)) |
| UART 가 가끔 깨진 글자를 받음 | HSI 오차 (25 °C ±1 %, 온도에 따라 수 %) 에 보레이트 오차가 더해짐 | HSE 사용, 낮은 보레이트, HSITRIM 조정 |
| Stop 에서 깨어난 뒤 모든 것이 느림 | 클럭이 HSI 16 MHz 로 복귀 | 깨어난 직후 `SystemClock_Config()` 재호출 |
| 이유 없이 재부팅 | 워치독, BOR, 전원 불량 | `RCC->CSR` 플래그 출력으로 원인 확인 |
| USB 가 인식되지 않음 | PLLQ 가 48 MHz 가 아님 | N · Q 를 48 MHz 가 나오도록 (84 MHz: 336/7, 96 MHz: 192/4) |

## 과제

1. HSE 25 MHz (BlackPill F411) 로 96 MHz SYSCLK 과 48 MHz USB 클럭을 동시에 만드는 M · N · P · Q 를 구하고 VCO 범위를 검산하세요.
2. 아래 표를 F411 (HCLK 84 MHz, APB1 ÷2, APB2 ÷1) 과 F103 (72 MHz, APB1 ÷2, APB2 ÷1) 에 대해 채우세요: TIM2, TIM1, USART2, USART1, SPI1, I2C1 의 클럭.
3. 시뮬레이터에서 L07 예제를 열고 클럭 & 프로젝트 탭에서 SYSCLK 을 바꿔 가며 타이머 주기가 어떻게 변하는지 기록하세요. 코드를 바꾸지 않았는데 LED 주기가 바뀌는 이유를 쓰세요.
4. 위의 리셋 원인 출력 코드를 L06 printf 예제에 넣고 (실물이라면) NRST 버튼, `NVIC_SystemReset()`, 전원 재인가 세 경우의 출력을 비교하세요. 시뮬레이터에서는 어떤 플래그가 서는지 예상해 보세요.
5. RM0383 의 "Stop mode" 절을 읽고, Stop 에서 깨어난 뒤 반드시 해야 하는 일 두 가지를 적으세요.
