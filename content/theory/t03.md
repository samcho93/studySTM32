## 학습 목표

- Cortex-M 의 4 GB 주소 공간이 Code · SRAM · Peripheral · System 으로 어떻게 나뉘는지, STM32F411 에서 각 구획의 **실제 주소**가 무엇인지 압니다.
- BOOT 핀에 따라 0x0000_0000 에 무엇이 비치는지, `Reset_Handler` 가 어디에서 시작하는지 설명할 수 있습니다.
- AHB1 · AHB2 · APB1 · APB2 버스와 버스 매트릭스를 이해하고, `__HAL_RCC_GPIOA_CLK_ENABLE()` 이 실제로 어느 레지스터의 어느 비트를 세우는지 압니다.
- `GPIO_TypeDef` 구조체와 `#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)` 가 어떻게 C 포인터로 레지스터에 닿는지 설명할 수 있습니다.
- 리틀 엔디언 · 정렬 · 비트밴딩 · DMA 의 개념을 알고, 링커 스크립트의 `.isr_vector` `.text` `.data` `.bss` 와 빌드 로그의 `text / data / bss` 숫자를 읽을 수 있습니다.

## 4 GB 주소 공간

Cortex-M 은 32비트 주소를 쓰므로 2^32 = 4 GB 의 주소 공간이 있습니다. Arm 은 이 공간을 **0.5 GB 단위의 큰 구획**으로 미리 나눠 두었고, 모든 Cortex-M MCU 가 이 배치를 따릅니다.

@fig[memory-map] 왼쪽은 Armv7-M 이 정한 구획, 오른쪽은 STM32F411 에서 실제로 쓰이는 주소입니다. 회색 구획(외부 메모리)은 F411 에 외부 버스가 없어 비어 있습니다.

| 구획 | 시작 주소 | 크기 | STM32 에서 | 실행 가능 |
|---|---|---|---|---|
| **Code** | 0x0000_0000 | 0.5 GB | 플래시, 시스템 메모리(부트로더), 옵션 바이트 | 예 (I-Code 버스) |
| **SRAM** | 0x2000_0000 | 0.5 GB | 내장 SRAM, 비트밴드 별칭 | 예 (System 버스) |
| **Peripheral** | 0x4000_0000 | 0.5 GB | APB1 · APB2 · AHB1 · AHB2 주변장치, 비트밴드 별칭 | 아니오 (XN) |
| External RAM | 0x6000_0000 | 1 GB | FSMC/FMC 외부 SRAM · LCD (F411 없음) | 예 |
| External device | 0xA000_0000 | 1 GB | QSPI 등 (F411 없음) | 아니오 |
| **PPB / System** | 0xE000_0000 | 0.5 GB | SysTick · NVIC · SCB · MPU · 디버그 (코어 내부) | 아니오 |

주소만 봐도 어디를 가리키는지 알 수 있습니다. `0x0800_xxxx` 는 플래시, `0x2000_xxxx` 는 SRAM, `0x4002_0xxx` 는 GPIO, `0xE000_Exxx` 는 코어 내부입니다.
디버거에서 변수 주소가 `0x2000_0134` 로 보이면 SRAM 시작에서 0x134 = 308 바이트 뒤라는 뜻입니다.

### STM32F411 의 실제 메모리

@table[regmap]
| 이름 | 주소 범위 | 크기 | 내용 |
|---|---|---|---|
| 메인 플래시 | 0x0800_0000 ~ 0x0807_FFFF | 512 KB | 프로그램 · 상수 · `.data` 초기값. 섹터 8개 (16 KB × 4, 64 KB, 128 KB × 3) |
| 시스템 메모리 | 0x1FFF_0000 ~ 0x1FFF_77FF | 30 KB | ST 가 구워 둔 부트로더 (USART · USB DFU 로 플래시 쓰기), 지울 수 없음 |
| OTP | 0x1FFF_7800 ~ 0x1FFF_7A0F | 528 B | 한 번만 쓸 수 있는 영역 (일련번호 등) |
| 옵션 바이트 | 0x1FFF_C000 ~ 0x1FFF_C00F | 16 B | 읽기 보호(RDP), 쓰기 보호, BOR 레벨, 워치독 설정 |
| SRAM | 0x2000_0000 ~ 0x2001_FFFF | 128 KB | `.data` `.bss` 힙 스택 |
| 별칭 | 0x0000_0000 ~ | | BOOT 핀에 따라 플래시 · 시스템 메모리 · SRAM 중 하나가 비침 |

F103C8(BluePill) 은 플래시 0x0800_0000 부터 64 KB (1 KB 페이지 64개), SRAM 0x2000_0000 부터 20 KB 입니다. 주소 체계는 같고 크기만 다릅니다.

플래시가 **섹터 단위**로만 지워진다는 점은 나중에 설정값을 플래시에 저장할 때 중요합니다. F411 은 가장 작은 섹터가 16 KB 이므로 EEPROM 처럼 바이트 단위로 자주 고쳐 쓰기에 알맞지 않습니다 (L0 · L1 은 진짜 EEPROM 이 내장되어 있습니다).

## 부트 매핑

리셋 후 코어는 0x0000_0000 에서 초기 SP 를, 0x0000_0004 에서 리셋 벡터를 읽습니다. 그런데 0x0000_0000 에는 실제 메모리가 없고, **BOOT 핀 상태에 따라 다른 메모리가 비칩니다(aliasing).**

| BOOT0 | BOOT1 (F4: PB2) | 0x0000_0000 에 비치는 것 | 용도 |
|---|---|---|---|
| 0 | × | 메인 플래시 0x0800_0000 | 보통 실행 (Nucleo 기본, BOOT0 이 GND 로 당겨짐) |
| 1 | 0 | 시스템 메모리 0x1FFF_0000 | ST 부트로더로 플래시 쓰기 (USART1 PA9/PA10, USB DFU 등, AN2606) |
| 1 | 1 | SRAM 0x2000_0000 | 디버거가 SRAM 에 넣은 코드 실행 (드묾) |

BluePill 의 BOOT0 · BOOT1 점퍼가 이것입니다. BOOT0 을 1 로 두고 리셋하면 부트로더가 실행되어 USB-시리얼 어댑터로 플래시를 쓸 수 있습니다.
Nucleo 는 ST-Link 가 SWD 로 직접 플래시를 쓰므로 BOOT0 을 건드릴 일이 거의 없습니다. 예외는 [T08](t08.html) 에서 다루는 "디버그 핀을 잘못 설정해 ST-Link 가 연결되지 않을 때" 입니다.

리셋 벡터는 0x0000_0004 에서 읽지만, 이후에는 별칭이 아닌 **진짜 주소 0x0800_0000** 에서 실행합니다.
`SystemInit()` 이 SCB->VTOR 에 0x0800_0000 을 써서 벡터 테이블 위치를 못 박기 때문에, 이후 인터럽트가 나면 코어는 0x0800_0000 + 4 × 번호 에서 핸들러 주소를 읽습니다.
부트로더를 직접 만들 때는 애플리케이션이 시작하면서 VTOR 를 자기 주소(예: 0x0800_8000)로 바꿔야 합니다.

## 버스 매트릭스와 클럭 게이팅

@table[regmap]
| 버스 | 최대 클럭 (F411) | 붙어 있는 주변장치 | 주소 시작 |
|---|---|---|---|
| **AHB1** | 100 MHz (= HCLK) | GPIOA~E · H, RCC, Flash 인터페이스, CRC, DMA1 · DMA2 | 0x4002_0000 |
| **AHB2** | 100 MHz | USB OTG FS | 0x5000_0000 |
| **APB1** | 50 MHz (PCLK1) | TIM2~5, USART2, I2C1~3, SPI2 · SPI3, WWDG, RTC, PWR | 0x4000_0000 |
| **APB2** | 100 MHz (PCLK2) | TIM1, TIM9~11, USART1 · USART6, ADC1, SPI1 · SPI4 · SPI5, SDIO, SYSCFG, EXTI | 0x4001_0000 |

**AHB(Advanced High-performance Bus)** 는 코어와 DMA 가 직접 쓰는 빠른 버스이고, **APB(Advanced Peripheral Bus)** 는 AHB 에서 브리지를 거쳐 나온 느린 버스입니다.
GPIO 가 F4 부터 AHB 에 붙은 이유는 핀 토글 속도를 높이기 위해서입니다 (F1 은 GPIO 가 APB2 에 있어 최대 18 MHz 토글이 한계였습니다).

코어 · DMA1 · DMA2 가 **마스터**, 플래시 · SRAM · 각 버스가 **슬레이브**이고, 이들을 잇는 **버스 매트릭스**가 서로 다른 슬레이브에 대한 접근을 동시에 처리합니다.
예를 들어 코어가 플래시에서 명령을 가져오는 동안 DMA 가 SRAM 에서 USART2 로 데이터를 옮길 수 있습니다. 같은 SRAM 을 두 마스터가 동시에 원하면 라운드 로빈으로 번갈아 씁니다.

### 클럭 게이팅

STM32 의 모든 주변장치는 **리셋 직후 클럭이 꺼져 있습니다.** 전력을 아끼기 위해서인데, 클럭이 꺼진 주변장치의 레지스터는 읽으면 0, 써도 무시됩니다(또는 BusFault).
그래서 GPIO 하나를 쓰려 해도 먼저 RCC 의 인에이블 비트를 세워야 합니다. CubeMX 가 만든 `MX_GPIO_Init()` 첫 줄이 그것입니다.

```c
__HAL_RCC_GPIOA_CLK_ENABLE();
/* stm32f4xx_hal_rcc.h 에서 이 매크로는 다음으로 펼쳐집니다 */
do {
  __IO uint32_t tmpreg = 0x00U;
  SET_BIT(RCC->AHB1ENR, RCC_AHB1ENR_GPIOAEN);   /* RCC->AHB1ENR |= (1 << 0);  주소 0x4002_3830 */
  tmpreg = READ_BIT(RCC->AHB1ENR, RCC_AHB1ENR_GPIOAEN);   /* 읽어서 쓰기가 반영될 시간을 벎 */
  UNUSED(tmpreg);
} while (0U);
```

- `RCC->AHB1ENR` 은 RCC(0x4002_3800) 의 오프셋 0x30 에 있는 AHB1 주변장치 클럭 인에이블 레지스터입니다. bit 0 = GPIOA, bit 1 = GPIOB, … bit 21 = DMA1, bit 22 = DMA2.
- APB1 장치는 `RCC->APB1ENR` (TIM2 = bit 0, USART2 = bit 17, I2C1 = bit 21), APB2 장치는 `RCC->APB2ENR` (TIM1 = bit 0, USART1 = bit 4, ADC1 = bit 8, SPI1 = bit 12, SYSCFG = bit 14) 입니다.
- 읽기 한 번을 끼워 넣는 이유는 F4 에러타에 있는 **"클럭 인에이블 직후 바로 접근하면 반영이 안 될 수 있다"** 는 문제 때문입니다. 레지스터를 직접 다룰 때는 이 매크로를 그대로 쓰는 것이 안전합니다.

@sim[l03-bsrr] 레지스터 직접 접근 예제 열기

시뮬레이터에서 이 예제의 `MX_GPIO_Init()` 을 보면 `__HAL_RCC_GPIOA_CLK_ENABLE()` 이 `GPIOA->MODER` 설정보다 먼저 옵니다. 순서를 바꾸면 실물에서는 MODER 쓰기가 사라져 LED 가 켜지지 않습니다.

## 레지스터 구조체: GPIO_TypeDef 와 GPIOA

주변장치의 레지스터는 **베이스 주소부터 일정한 오프셋**에 놓여 있습니다. ST 는 이것을 C 구조체로 표현합니다 (`stm32f411xe.h`).

```c
typedef struct {
  __IO uint32_t MODER;    /* 0x00  모드 (입력·출력·AF·아날로그) */
  __IO uint32_t OTYPER;   /* 0x04  출력 종류 (푸시풀·오픈드레인) */
  __IO uint32_t OSPEEDR;  /* 0x08  출력 속도 */
  __IO uint32_t PUPDR;    /* 0x0C  풀업·풀다운 */
  __IO uint32_t IDR;      /* 0x10  입력 데이터 (읽기 전용) */
  __IO uint32_t ODR;      /* 0x14  출력 데이터 */
  __IO uint32_t BSRR;     /* 0x18  비트 set/reset (쓰기 전용) */
  __IO uint32_t LCKR;     /* 0x1C  설정 잠금 */
  __IO uint32_t AFR[2];   /* 0x20, 0x24  대체 기능 (AFRL: 핀 0~7, AFRH: 핀 8~15) */
} GPIO_TypeDef;

#define PERIPH_BASE       0x40000000UL
#define AHB1PERIPH_BASE   (PERIPH_BASE + 0x00020000UL)    /* 0x4002_0000 */
#define GPIOA_BASE        (AHB1PERIPH_BASE + 0x0000UL)    /* 0x4002_0000 */
#define GPIOB_BASE        (AHB1PERIPH_BASE + 0x0400UL)    /* 0x4002_0400 */
#define GPIOC_BASE        (AHB1PERIPH_BASE + 0x0800UL)    /* 0x4002_0800 */
#define GPIOA             ((GPIO_TypeDef *) GPIOA_BASE)
#define GPIOB             ((GPIO_TypeDef *) GPIOB_BASE)
```

- `__IO` 는 `volatile` 의 별칭입니다. 컴파일러가 "방금 썼으니 다시 읽을 필요 없다" 고 최적화하지 못하게 합니다. 하드웨어가 값을 바꾸는 IDR 을 두 번 읽으면 두 번 모두 실제로 버스에 접근해야 하기 때문입니다.
- `GPIOA` 는 **정수 0x4002_0000 을 구조체 포인터로 캐스팅한 것**입니다. 변수가 아니라 상수이므로 메모리를 차지하지 않습니다.
- `GPIOA->ODR` 은 컴파일러가 `*(volatile uint32_t *)(0x40020000 + 0x14)` 로 바꿉니다. 어셈블리로는 `ldr r3, [r2, #20]` 한 명령입니다 ([T02](t02.html) 의 예).
- 포트끼리 간격이 0x400 (1 KB) 이므로 `GPIOA + 1` 같은 포인터 산술은 하면 안 됩니다 (구조체 크기 0x28 만큼 움직임). 반드시 `GPIOB` 매크로를 쓰세요.

같은 방식으로 `RCC_TypeDef`, `USART_TypeDef`, `TIM_TypeDef` 가 정의되어 있고, HAL 핸들의 `Instance` 멤버가 이 포인터입니다. `huart2.Instance == USART2` 는 "핸들이 0x4000_4400 을 가리키는가" 를 묻는 것입니다.

:::tip 레퍼런스 매뉴얼 읽는 법
RM0383 의 각 주변장치 장 끝에는 "register map" 표가 있습니다. 표의 오프셋 열이 구조체 멤버 순서와 같고, 각 레지스터 절에는 비트별 뜻과 리셋값이 있습니다.
HAL 함수가 무엇을 하는지 궁금하면 `stm32f4xx_hal_gpio.c` 의 `HAL_GPIO_Init()` 을 열어 `GPIOx->MODER` 를 어떻게 고치는지와 RM0383 의 MODER 설명을 나란히 놓고 보세요.
:::

## 리틀 엔디언과 정렬

Cortex-M 은 **리틀 엔디언**입니다. 32비트 값 `0x12345678` 을 주소 0x2000_0000 에 쓰면 바이트 순서는 다음과 같습니다.

| 주소 | 0x2000_0000 | 0x2000_0001 | 0x2000_0002 | 0x2000_0003 |
|---|---|---|---|---|
| 값 | 0x78 | 0x56 | 0x34 | 0x12 |

- `uint8_t *p = (uint8_t *)&x;` 로 첫 바이트를 읽으면 0x78 (최하위)이 나옵니다.
- UART 로 `uint16_t` 를 두 바이트로 보낼 때 어느 쪽을 먼저 보낼지 프로토콜과 맞춰야 합니다. 네트워크 · 많은 센서(빅 엔디언)와 반대이므로 `__REV16()` 같은 명령으로 뒤집습니다.
- 구조체를 통째로 메모리에 저장하거나 통신으로 보내면 엔디언과 패딩이 그대로 실리므로, 다른 아키텍처와 주고받을 때 주의합니다.

**정렬(alignment)** 은 4바이트 값은 4 의 배수 주소에, 2바이트 값은 2 의 배수 주소에 두는 규칙입니다.
Cortex-M3/M4 는 SRAM 에서 정렬되지 않은 `ldr`/`str` 을 하드웨어가 처리해 주지만(여러 사이클), **주변장치 영역과 `ldm`/`stm` 계열 명령은 정렬을 요구**하며 위반하면 UsageFault 입니다.
M0/M0+ 는 모든 비정렬 접근이 폴트입니다. `uint8_t buf[6]` 의 `buf+1` 을 `uint32_t *` 로 캐스팅해 읽는 코드가 M0 에서 죽는 흔한 이유입니다.
컴파일러는 구조체 멤버 사이에 패딩을 넣어 정렬을 맞추므로 `sizeof(struct { uint8_t a; uint32_t b; })` 는 5 가 아니라 8 입니다.

## 비트밴딩 (F1 · F4)

Cortex-M3/M4 에는 **비트밴딩(bit-banding)** 이라는 기능이 있습니다. SRAM 의 처음 1 MB 와 주변장치 영역의 처음 1 MB 에 대해, **각 비트마다 32비트 주소 하나가 별칭으로 배정**됩니다.

$별칭 주소 = 별칭 시작 + (바이트 오프셋 × 32) + (비트 번호 × 4)$

| 영역 | 비트밴드 영역 | 별칭 영역 |
|---|---|---|
| SRAM | 0x2000_0000 ~ 0x200F_FFFF | 0x2200_0000 ~ 0x23FF_FFFF |
| Peripheral | 0x4000_0000 ~ 0x400F_FFFF | 0x4200_0000 ~ 0x43FF_FFFF |

예를 들어 `GPIOA->ODR` (0x4002_0014) 의 비트 5 (PA5) 는 바이트 오프셋 0x20014 이므로 별칭 주소는 0x4200_0000 + 0x20014 × 32 + 5 × 4 = **0x4240_0294** 입니다.
이 주소에 1 을 쓰면 PA5 만 1 이 되고, 0 을 쓰면 0 이 됩니다. 읽기-수정-쓰기 세 명령이 아니라 **쓰기 한 명령**이므로 원자적입니다.

```c
#define BITBAND_PERI(addr, bit)  (*(volatile uint32_t *)(0x42000000 + ((addr) - 0x40000000) * 32 + (bit) * 4))
BITBAND_PERI(0x40020014, 5) = 1;    /* PA5 = 1 (GPIOA->ODR bit 5) */
```

M0 · M0+ · M7 · M33 에는 비트밴딩이 없으므로 이식성이 있는 코드에서는 쓰지 않습니다. GPIO 는 BSRR 이 같은 목적을 더 이식성 있게 해결합니다 ([T05](t05.html)).

## DMA 개념

**DMA(Direct Memory Access)** 는 코어를 거치지 않고 메모리 ↔ 주변장치, 메모리 ↔ 메모리 사이에서 데이터를 옮기는 별도의 마스터입니다.
F411 에는 DMA1 · DMA2 두 컨트롤러가 있고 각각 **8개 스트림**, 스트림마다 **8개 채널** 중 하나를 고릅니다. 어떤 주변장치가 어느 스트림 · 채널에 붙는지는 RM0383 의 DMA 요청 매핑 표에 고정되어 있습니다.

| 주변장치 요청 | 컨트롤러 | 스트림 | 채널 |
|---|---|---|---|
| USART2_RX | DMA1 | 5 | 4 |
| USART2_TX | DMA1 | 6 | 4 |
| I2C1_RX | DMA1 | 0 또는 5 | 1 |
| SPI2_TX | DMA1 | 4 | 0 |
| ADC1 | DMA2 | 0 또는 4 | 0 |
| TIM3_CH1 | DMA1 | 4 | 5 |
| 메모리 → 메모리 | DMA2 만 | 아무 스트림 | — |

DMA1 은 APB1 주변장치, DMA2 는 APB2 주변장치와 메모리 간 복사를 맡습니다. CubeMX 의 DMA 탭에서 "USART2_RX" 를 추가하면 이 표에 따라 스트림이 자동으로 정해집니다.

전송이 끝나면 인터럽트(전송 완료 TC, 절반 완료 HT)가 나고, HAL 은 `HAL_UART_RxCpltCallback` 같은 콜백으로 알려 줍니다.
[L09](l09.html) 의 ADC 순환 DMA 가 대표적인 예입니다. ADC 가 변환할 때마다 DMA 가 `adc_buf[]` 에 값을 써 주므로 메인 루프는 배열만 읽으면 됩니다.

:::warn DMA 와 캐시 · 정렬
DMA 는 코어 레지스터가 아니라 **메모리 주소**를 봅니다. 그래서 DMA 버퍼는 지역 변수(스택, 함수가 끝나면 사라짐)가 아니라 전역 · `static` 으로 두고, 코어가 읽을 때는 `volatile` 로 선언합니다.
Cortex-M7(F7 · H7)에서는 데이터 캐시 때문에 DMA 가 쓴 값이 코어에 보이지 않는 문제가 추가로 생기며, 캐시 무효화나 비캐시 영역(MPU)이 필요합니다. F4 에는 데이터 캐시가 없어 이 문제가 없습니다.
:::

## 링커 스크립트와 메모리 섹션

컴파일러가 만든 오브젝트 파일에는 코드와 데이터가 **섹션** 단위로 들어 있고, 링커 스크립트(`STM32F411RETX_FLASH.ld`)가 각 섹션을 플래시와 SRAM 의 어느 주소에 놓을지 정합니다.

```text STM32F411RETX_FLASH.ld (요약)
_estack = ORIGIN(RAM) + LENGTH(RAM);     /* 0x2002_0000 = 스택 시작 (SRAM 끝) */
_Min_Heap_Size  = 0x200;                 /* 힙 최소 512 B  (malloc 을 쓰면 늘려야 함) */
_Min_Stack_Size = 0x400;                 /* 스택 최소 1 KB (링크 시 검사용) */

MEMORY {
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
  FLASH (rx)  : ORIGIN = 0x8000000,  LENGTH = 512K
}

SECTIONS {
  .isr_vector : { KEEP(*(.isr_vector)) } > FLASH      /* 벡터 테이블, 반드시 플래시 맨 앞 */
  .text       : { *(.text*) }            > FLASH      /* 코드 */
  .rodata     : { *(.rodata*) }          > FLASH      /* const 상수, 문자열 리터럴 */
  _sidata = LOADADDR(.data);                          /* .data 초기값이 놓인 플래시 주소 */
  .data       : { _sdata = .; *(.data*); _edata = .; } > RAM AT> FLASH   /* 초기값 있는 전역 변수 */
  .bss        : { _sbss = .;  *(.bss*);  _ebss = .;  } > RAM             /* 초기값 0 인 전역 변수 */
  ._user_heap_stack : { . += _Min_Heap_Size; . += _Min_Stack_Size; } > RAM
}
```

| 섹션 | 무엇이 들어가나 | 어디에 | 예 |
|---|---|---|---|
| `.isr_vector` | 벡터 테이블 (초기 SP + 핸들러 주소들) | 플래시 맨 앞 | `g_pfnVectors` |
| `.text` | 기계어 코드 | 플래시 | 모든 함수, HAL 라이브러리 |
| `.rodata` | 읽기 전용 데이터 | 플래시 | `const uint8_t seg[10]`, `"Hello\r\n"` |
| `.data` | 초기값이 0 이 아닌 전역 · static 변수 | SRAM (초기값은 플래시에) | `int count = 5;` |
| `.bss` | 초기값이 0 이거나 없는 전역 · static 변수 | SRAM (시작 때 0 으로 채움) | `uint8_t rx_buf[64];` |
| 힙 | `malloc` 이 쓰는 영역 | SRAM, `.bss` 뒤 | `printf` 의 `%f` 가 쓰기도 함 |
| 스택 | 지역 변수, 복귀 주소, 예외 프레임 | SRAM 끝에서 아래로 | |

`Reset_Handler` 가 `_sidata` 에서 `_sdata`~`_edata` 로 복사하고 `_sbss`~`_ebss` 를 0 으로 채우는 코드가 바로 이 심볼들을 씁니다 ([T02](t02.html) 리셋 절).
힙과 스택은 같은 빈 공간을 양쪽에서 쓰기 때문에, 스택이 깊어지거나 `malloc` 을 많이 하면 서로 침범합니다. 링커는 최소 크기만 검사할 뿐 실행 중 침범은 잡지 못합니다.

### 빌드 로그의 text · data · bss

CubeIDE 빌드 끝에 `arm-none-eabi-size` 가 이런 줄을 찍습니다. 시뮬레이터의 빌드 로그도 같은 형식을 흉내 냅니다.

```text
   text    data     bss     dec     hex filename
  10236     116    1764   12116    2f54 project.elf
```

| 항목 | 뜻 | 차지하는 곳 |
|---|---|---|
| **text** | `.isr_vector` + `.text` + `.rodata` | 플래시 |
| **data** | `.data` (초기값 있는 변수) | 플래시(초기값) **와** SRAM(실행 중) 둘 다 |
| **bss** | `.bss` (0 초기화 변수) | SRAM 만 |
| dec / hex | 세 값의 합 (10진 · 16진), 실용적 의미는 적음 | |

그러므로 **플래시 사용량 = text + data**, **SRAM 사용량(정적) = data + bss** 이고, 여기에 실행 중 힙과 스택이 더해집니다.
위 예라면 플래시 10,352 B (512 KB 의 2 %), SRAM 정적 1,880 B (128 KB 의 1.4 %) 입니다.
`uint8_t big[100000];` 을 전역으로 선언하면 bss 가 100 KB 로 뛰고, 128 KB 를 넘으면 링커가 `region 'RAM' overflowed` 오류를 냅니다.

:::check 스스로 확인
- `const char msg[] = "hi";` 와 `char msg[] = "hi";` 는 각각 어느 섹션에 들어갑니까? 플래시 · SRAM 사용량은 어떻게 다릅니까?
- `GPIOC->IDR` 의 절대 주소는? (GPIOC 베이스 + 오프셋)
- `RCC->APB1ENR` 의 bit 17 을 세우지 않고 `USART2->CR1` 에 쓰면 어떻게 됩니까?
- `int x = 0;` 을 전역으로 선언하면 data 와 bss 중 어디에 들어갑니까?
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 레지스터에 값을 써도 0 으로 읽힘, 또는 HardFault | 해당 주변장치 클럭(RCC->xxxENR)을 켜지 않음 | `__HAL_RCC_xxx_CLK_ENABLE()` 을 먼저. CubeMX 는 `MX_xxx_Init` 안에서 자동 처리 |
| 링크 오류 `region 'RAM' overflowed by N bytes` | 전역 배열 · 버퍼가 SRAM 보다 큼 | 배열 크기 줄이기, 상수는 `const` 로 플래시에, 더 큰 칩 선택 |
| 링크 오류 `region 'FLASH' overflowed` | 코드 + 상수가 플래시 초과 (`-O0`, printf float, 큰 폰트 · 이미지) | `-Os`/`-O2`, 사용하지 않는 HAL 모듈 제외, 이미지는 압축 |
| 전역 변수 초기값이 이상함 | 링커 스크립트나 startup 을 다른 칩 것으로 씀 (`_sidata` 불일치) | CubeMX 가 만든 `.ld` · `startup_*.s` 를 그대로 사용 |
| DMA 버퍼에 값이 안 들어옴 | 지역 변수(스택) 버퍼, 스트림 · 채널 매핑 오류 | 전역 · static `volatile` 버퍼, RM0383 DMA 매핑 표 확인 |
| 부트로더가 실행되지 않음 | BOOT0 이 0 으로 고정 (Nucleo 는 CN7 의 BOOT0 핀을 VDD 에 연결해야 함) | BOOT0 = 1 로 두고 리셋, AN2606 의 부트로더 인터페이스 확인 |
| 애플리케이션 점프 후 인터럽트가 엉뚱한 곳으로 | VTOR 를 새 벡터 테이블 주소로 바꾸지 않음 | `SCB->VTOR = APP_ADDR;` 후 `__DSB(); __ISB();` |

## 과제

1. `GPIOB->BSRR`, `USART2->DR` (오프셋 0x04), `TIM3->CNT` (TIM3 베이스 0x4000_0400, CNT 오프셋 0x24), `RCC->AHB1ENR` 의 절대 주소를 계산하세요.
2. `GPIOA->ODR` 비트 5 의 비트밴드 별칭 주소 계산을 직접 따라 하고, `GPIOC->ODR` 비트 13 (BluePill LED) 의 별칭 주소를 구하세요.
3. 시뮬레이터에서 L03 예제를 빌드해 로그의 text · data · bss 를 적은 뒤, `uint32_t table[256] = {1};` 을 전역에 추가해 다시 빌드하고 어느 값이 얼마나 늘었는지, 왜 그런지 설명하세요. `static const` 로 바꾸면 어떻게 달라집니까?
4. RM0383 의 "Memory map" 표에서 I2C1, SPI1, ADC1, EXTI, SYSCFG 의 베이스 주소와 버스를 찾아 표로 정리하세요.
