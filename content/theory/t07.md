## 학습 목표

- 고급(advanced) · 범용(general-purpose) · 기본(basic) 타이머의 차이와 F411 · F103 에 어떤 타이머가 몇 비트로 있는지 압니다.
- PSC · CNT · ARR 과 업데이트 이벤트(UEV)로 이루어진 카운터 블록을 이해하고, 84 MHz 에서 원하는 주기의 값을 계산할 수 있습니다.
- 프리로드 · 섀도 레지스터가 왜 있는지, 출력 비교와 PWM 모드 1/2 · 듀티 · 극성이 어떻게 파형을 만드는지 설명할 수 있습니다.
- 입력 캡처로 주파수 · 펄스 폭을 재는 원리, 인코더 모드, 원샷, 데드타임, 마스터/슬레이브 트리거의 개념을 압니다.
- IWDG · WWDG 워치독과 RTC 가 어떤 타이머인지, 언제 쓰는지 압니다.

## 타이머의 종류

STM32 의 타이머는 세 등급이고, 위 등급은 아래 등급의 기능을 모두 포함합니다.

@table[regmap]
| 등급 | F411 | F103 (C8 · RB) | 비트 | 채널 | 특징 |
|---|---|---|---|---|---|
| **고급 (advanced)** | TIM1 | TIM1 | 16 | 4 + 상보 3 | 상보 출력 · 데드타임 · 브레이크 입력 · 반복 카운터 → 3상 모터, 디지털 전원 |
| **범용 (general-purpose)** | TIM2, TIM5 | — | **32** | 4 | 긴 주기, 입력 캡처 · 인코더 |
| | TIM3, TIM4 | TIM2, TIM3, TIM4 | 16 | 4 | 가장 많이 쓰는 타이머 |
| | TIM9 | — | 16 | 2 | 마스터/슬레이브 일부 |
| | TIM10, TIM11 | — | 16 | 1 | 단순 PWM · 시간 기준 |
| **기본 (basic)** | (없음) | (없음, F103 고밀도부터 TIM6 · 7) | 16 | 0 | 입출력 없음. DAC 트리거 · 시간 기준 전용 |

- F411 의 TIM1 · TIM9~11 은 APB2, TIM2~5 는 APB1 에 있지만 [T04](t04.html) 의 ×2 규칙으로 **이 강좌 설정에서는 모두 84 MHz** 를 받습니다.
- 16비트 타이머는 PSC · ARR · CCR 이 0~65535, 32비트(TIM2 · TIM5)는 ARR · CCR 이 0~4 294 967 295 입니다. PSC 는 항상 16비트입니다.
- F103 (C8 · RB) 에는 TIM5 · TIM9 이상이 없고 TIM2 가 16비트입니다. 코드를 옮길 때 32비트 ARR 을 믿고 쓴 긴 주기가 깨질 수 있습니다.
- 그 밖에 코어의 **SysTick**(24비트 다운카운터, [T04](t04.html)), **IWDG · WWDG**(워치독), **RTC** 가 시간 관련 블록입니다.

## 카운터 블록

@fig[timer-block] 위: 클럭 → PSC → CNT → ARR 비교 → UEV, 그리고 CCR1 비교 → 출력. 아래: TIM3 을 PSC 83, ARR 999, CCR1 600 으로 두었을 때의 CNT 와 CH1 파형.

타이머의 심장은 **프리스케일러(PSC) → 카운터(CNT) → 자동 재장전(ARR)** 세 레지스터입니다.

1. 입력 클럭 CK_INT (84 MHz) 를 PSC + 1 로 나눠 CK_CNT 를 만듭니다. PSC = 83 이면 1 MHz.
2. CNT 가 CK_CNT 마다 1 씩 셉니다.
3. CNT 가 ARR 에 이르면 다음 클럭에 **0 으로 돌아가며 업데이트 이벤트(UEV)** 를 냅니다. ARR = 999 면 1000 틱마다.
4. UEV 는 UIF 플래그를 세우고(인터럽트 · DMA 요청), 프리로드된 값을 섀도 레지스터로 옮깁니다.

$f_{UEV} = f_{CK\_INT} / ((PSC + 1) × (ARR + 1))$, $T_{UEV} = (PSC + 1)(ARR + 1) / f_{CK\_INT}$

## 프리로드와 섀도 레지스터

ARR · PSC · CCRx 에는 각각 **섀도(shadow) 레지스터**가 붙어 있습니다. 실제로 카운터와 비교되는 것은 섀도이고, 소프트웨어가 쓰는 것은 프리로드 레지스터입니다.

- **ARPE = 0 (프리로드 끔)**: ARR 에 쓰면 즉시 섀도에 반영됩니다. 주기 도중에 ARR 을 CNT 보다 작게 바꾸면 CNT 가 ARR 을 지나쳐 65535 까지 한 바퀴 돌아야 하는 사고가 납니다.
- **ARPE = 1 (프리로드 켬)**: ARR 에 쓴 값은 **다음 UEV 때** 섀도로 옮겨집니다. 주기가 깨지지 않고 다음 주기부터 바뀝니다. CubeMX 의 "auto-reload preload" 가 이것입니다.
- **OCxPE**: CCRx 의 프리로드. PWM 듀티를 바꿀 때 켜 두면 현재 펄스가 끝난 뒤 새 듀티가 적용되어 **글리치가 없습니다.** `HAL_TIM_PWM_Init` 이 켜 줍니다.
- **PSC 는 항상 프리로드**입니다. 언제 써도 다음 UEV 에 반영됩니다.
- 즉시 반영하고 싶으면 `TIMx->EGR = TIM_EGR_UG` (UG 비트) 로 소프트웨어 UEV 를 일으킵니다. 단, 이때 UIF 도 서기 때문에 인터럽트가 한 번 더 불립니다 — [L07](l07.html) 의 "시작하자마자 콜백" 현상이 이것입니다. URS = 1 로 두면 UG 는 UIF 를 세우지 않습니다.

`__HAL_TIM_SET_AUTORELOAD(&htim3, 4999)` 와 `__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 300)` 는 프리로드 레지스터에 쓰는 매크로입니다.

## 출력 비교와 PWM

각 채널에는 **CCRx(캡처/비교 레지스터)** 와 비교기가 있습니다. CNT 와 CCRx 의 관계에 따라 채널 출력 OCxREF 가 정해지고, 극성(CCxP)을 거쳐 핀으로 나갑니다.

| OCxM (CCMR) | 모드 | OCxREF |
|---|---|---|
| 000 | Frozen | 비교 결과가 출력에 영향 없음 (타이밍 기준용) |
| 001 / 010 | Set / Reset on match | CNT = CCR 일 때 1 / 0 으로 |
| 011 | Toggle | CNT = CCR 일 때 반전 → 주파수 = UEV / 2 의 구형파 |
| 100 / 101 | Force inactive / active | 강제 0 / 1 |
| **110** | **PWM 모드 1** | 업카운트: CNT < CCR 이면 1, 아니면 0 |
| **111** | **PWM 모드 2** | 업카운트: CNT < CCR 이면 0, 아니면 1 (모드 1 의 반전) |

PWM 모드 1 · 업카운트에서 듀티는 다음과 같습니다.

$듀티 = CCR / (ARR + 1)$

| CCR (ARR = 999) | 듀티 | 핀 파형 |
|---|---|---|
| 0 | 0 % | 항상 0 (CNT < 0 인 순간이 없음) |
| 1 | 0.1 % | 1 틱 펄스 |
| 500 | 50 % | |
| 999 | 99.9 % | |
| 1000 이상 | **100 %** | 항상 1 (CNT 는 999 를 넘지 않음) |

- **극성 CCxP = 1** 로 두면 파형이 반전됩니다. active-low LED 나 상보 출력을 맞출 때 씁니다. PWM 모드 2 와 결과는 같지만 의미가 다릅니다 (모드는 비교 논리, 극성은 출력단).
- 같은 타이머의 네 채널은 **주기(ARR)를 공유**하고 듀티(CCR)만 따로입니다. RGB LED 세 채널은 한 타이머로, 주파수가 다른 PWM 두 개는 타이머 두 개로.
- `HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1)` 은 CCER 의 CCxE 비트(출력 인에이블)와 CR1 의 CEN(카운터 인에이블)을 켭니다. 고급 타이머(TIM1)는 추가로 BDTR 의 **MOE** 를 켜야 핀이 나옵니다 — HAL 이 처리합니다.

@sim[l08-pwm-led] PWM 페이드 예제 열기

시뮬레이터의 파형 탭에서 PA6 을 보면 1 kHz 주기 안에서 HIGH 구간이 CCR 값을 따라 늘어나는 것이 보입니다. 타이머 Properties 에서 ARR 을 바꿔 주파수와 분해능이 어떻게 얽히는지 확인해 보세요.

## 입력 캡처

같은 채널을 **입력**으로 쓰면 CCRx 가 반대로 동작합니다. 핀에 에지가 들어오는 순간 **CNT 값을 CCRx 에 복사(캡처)** 하고 CCxIF 인터럽트를 냅니다.

| 설정 | 레지스터 | 뜻 |
|---|---|---|
| CCxS = 01 | CCMR | 채널을 입력으로, TIx 에 연결 |
| ICxF | CCMR | 디지털 필터 (N 샘플 연속 같을 때 인정) — 잡음 제거 |
| ICxPSC | CCMR | 에지 N 개마다 한 번 캡처 |
| CCxP · CCxNP | CCER | 상승 · 하강 · 양쪽 에지 |

- **주파수 측정**: 상승 에지마다 캡처하고 연속 두 캡처의 차(오버플로 고려)가 주기입니다. 1 µs 틱이면 1 kHz 신호에서 1000 틱, 분해능 0.1 %.
- **펄스 폭 측정 (PWM 입력 모드)**: TI1 하나를 IC1 (상승) 과 IC2 (하강) 두 채널에 동시에 연결하고, 슬레이브 리셋 모드로 상승 에지에서 CNT 를 0 으로 만들면 **CCR1 = 주기, CCR2 = 펄스 폭**이 자동으로 들어옵니다. CubeMX 의 "PWM Input on CH1" 이 이것입니다. 서보 신호 · 초음파 센서(HC-SR04) 에코 · RC 수신기 읽기에 씁니다.
- 낮은 주파수(수 Hz)는 캡처보다 **일정 시간 동안 에지 개수 세기**(외부 클럭 모드)가 낫고, 높은 주파수(MHz)는 반대입니다.

HAL 은 `HAL_TIM_IC_Start_IT` 와 `HAL_TIM_IC_CaptureCallback`, 값 읽기는 `HAL_TIM_ReadCapturedValue` 입니다 (시뮬레이터 미지원).

## 인코더 · 원샷 · 데드타임 · 트리거

### 인코더 모드

로터리 인코더의 A · B 상을 TI1 · TI2 에 넣고 SMS = 001 · 010 · 011 로 두면 **하드웨어가 방향을 판단해 CNT 를 올리거나 내립니다.** 소프트웨어 개입 없이 CNT 만 읽으면 위치가 나옵니다.
SMS = 011 (양쪽 상, 양쪽 에지) 이면 한 슬롯당 4 카운트 (×4 체배). 모터 축의 회전수 · 각도, 조작 노브에 씁니다. 32비트 TIM2 · 5 를 쓰면 오버플로 걱정이 없습니다.

### 원샷 (One-pulse mode)

CR1 의 **OPM** 비트를 켜면 한 번 UEV 가 난 뒤 CEN 이 자동으로 꺼집니다. 트리거(외부 에지 또는 소프트웨어)로 시작해 CCR 만큼 지연 후 ARR − CCR 폭의 펄스 하나를 내는 데 씁니다. 초음파 센서 트리거 10 µs 펄스, 정확한 지연 후 한 번만 실행 등에 알맞습니다.

### 데드타임과 브레이크 (고급 타이머)

TIM1 의 채널 1~3 은 **상보 출력 CHxN** 을 가집니다. 하프브리지의 위쪽 · 아래쪽 스위치를 한 채널로 몰 때, 두 스위치가 잠시라도 동시에 켜지면 전원이 단락(shoot-through)됩니다.
BDTR 의 **DTG[7:0]** 이 두 출력 사이에 데드타임을 넣습니다 (RM0383 12.4.18 TIMx_BDTR). CR1 의 CKD = 00 이라 tDTS = 1 / 84 MHz ≈ 11.9 ns 일 때,

| DTG[7:5] | 데드타임 | 범위 |
|---|---|---|
| 0xx | DTG[6:0] × tDTS | 0 ~ 1.51 µs (11.9 ns 단위) |
| 10x | (64 + DTG[5:0]) × 2 tDTS | 1.52 ~ 3.02 µs |
| 110 | (32 + DTG[4:0]) × 8 tDTS | 3.05 ~ 6.0 µs |
| 111 | (32 + DTG[4:0]) × 16 tDTS | 6.1 ~ 12.0 µs |

MOSFET 게이트 드라이버의 지연에 맞춰 보통 0.5 ~ 2 µs 를 넣습니다. **브레이크 입력(BKIN)** 은 과전류 비교기 출력 등을 받아 하드웨어가 즉시 모든 출력을 안전 상태로 끊는 기능이고, **반복 카운터(RCR)** 는 N 주기마다 한 번만 UEV 를 내 전류 제어 루프 주기를 PWM 주기의 배수로 만듭니다.

### 마스터 / 슬레이브 트리거

타이머는 서로 신호(TRGO)를 주고받을 수 있습니다.

| 역할 | 레지스터 | 선택 | 예 |
|---|---|---|---|
| 마스터 출력 TRGO | CR2 의 MMS | 리셋 · 인에이블 · **업데이트** · 비교 펄스 · OCxREF | TIM2 UEV 마다 ADC 변환 트리거 (정확한 샘플링 주기) |
| 슬레이브 입력 | SMCR 의 TS (ITR0~3, TI1, ETR) + SMS | 리셋 · 게이트 · 트리거 · 외부 클럭 | TIM1 이 TIM3 을 시작시켜 두 타이머를 동기 |

F411 에서 TIM2 의 ITR0 = TIM1, ITR2 = TIM3, ITR3 = TIM4 (ITR1 은 예약) 처럼 **어느 타이머가 어느 ITR 에 연결되는지는 RM0383 표에 고정**되어 있습니다 (13장 "TIMx internal trigger connection" 표).
가장 흔한 쓰임은 "타이머 → ADC 트리거" 입니다. [L09](l09.html) 의 연속 변환보다 정확한 간격으로 샘플링하고 싶을 때 ADC 의 외부 트리거를 TIM2 TRGO 로 설정합니다. **ETR** 핀으로 외부 신호를 타이머 클럭으로 쓰면 펄스 카운터(유량계, 회전수)가 됩니다.

## 워치독

워치독은 "프로그램이 살아 있는가" 를 감시하는 타이머입니다. 정해진 시간 안에 되살리지(refresh) 않으면 **리셋**을 겁니다. 코드가 무한 루프에 빠지거나 인터럽트가 멈춘 상황에서 스스로 회복하는 마지막 수단입니다.

| | IWDG (독립 워치독) | WWDG (윈도 워치독) |
|---|---|---|
| 클럭 | **LSI 32 kHz** (메인 클럭과 무관, 정확도 낮음) | PCLK1 / 4096 |
| 카운터 | 12비트 다운 (0~4095), 프리스케일러 4 ~ 256 | 7비트 다운 (0x7F → 0x3F 에서 리셋) |
| 시간 범위 (F411) | 125 µs ~ **32.8 s** | 약 97.5 µs ~ 49.9 ms (PCLK1 42 MHz, WDGTB 0~3) |
| 특징 | 한 번 켜면 **끌 수 없음**, Stop · Standby 에서도 계속 동작(F4 는 멈추는 옵션이 없음), 클럭이 죽어도 동작 | 되살리는 시점이 **윈도 안**이어야 함 (너무 빨라도 리셋) → 코드가 "너무 빨리 돌아도" 감지. 조기 경고 인터럽트 있음 |
| 쓰임 | 거의 모든 제품의 기본 안전장치 | 실행 시간이 엄격한 제어 루프 |

WWDG 타임아웃은 $t_{WWDG} = t_{PCLK1} × 4096 × 2^{WDGTB} × (T[5:0] + 1)$ 입니다 (RM0383 16.3). PCLK1 = 42 MHz 면 최소 4096 / 42 MHz ≈ 97.5 µs, 최대 × 8 × 64 ≈ 49.9 ms 입니다.
IWDG 타임아웃은 $T = 4 × 2^{PR} × (RLR + 1) / f_{LSI}$ 입니다. PR = 4 (÷64), RLR = 999 → 64 × 1000 / 32 000 = **2 s**.

```c
/* CubeMX: IWDG → Activated, Prescaler 64, Reload 999 */
HAL_IWDG_Init(&hiwdg);          /* MX_IWDG_Init 안. KR 에 0x5555(접근 허용) → PR·RLR 설정 → 0xCCCC(시작) */
while (1) {
  do_work();                    /* 2 s 안에 반드시 아래로 와야 함 */
  HAL_IWDG_Refresh(&hiwdg);     /* KR = 0xAAAA → 카운터를 RLR 로 되돌림 */
}
```

- 되살리는 코드는 **메인 루프의 한 곳**에만 둡니다. 타이머 ISR 에서 되살리면 메인이 멈춰도 워치독이 리셋하지 못해 의미가 없습니다.
- 디버그 중 중단점에서 멈추면 IWDG 가 리셋해 버리므로 `__HAL_DBGMCU_FREEZE_IWDG()` 로 디버그 중 정지시킵니다. CubeMX 의 SYS → "Debug" 옵션에 있습니다.
- LSI 가 17 ~ 47 kHz 로 흔들리므로 타임아웃은 여유 있게 잡습니다. 리셋 후 `RCC->CSR` 의 IWDGRSTF 로 원인을 알 수 있습니다 ([T04](t04.html)).

## RTC 개요

**RTC(Real-Time Clock)** 는 달력 · 시계용 저전력 타이머입니다. F4 의 RTC 는 F1 과 달리 **BCD 달력**(연 · 월 · 일 · 요일 · 시 · 분 · 초)을 하드웨어로 유지합니다.

- 클럭: LSE 32.768 kHz (권장) · LSI · HSE/RTCPRE (RCC_CFGR 의 RTCPRE 로 2 ~ 31 분주해 1 MHz 로 맞춤) 중 선택. 비동기 프리스케일러 128 × 동기 256 = 32768 → 정확히 1 Hz.
- 기능: 알람 A · B (특정 시각에 인터럽트 · 깨우기), 웨이크업 타이머 (주기적으로 Stop/Standby 에서 깨움), 타임스탬프 · 탬퍼 감지, 서브초 읽기, 보정 레지스터 (±0.95 ppm 단위).
- **백업 도메인**: RTC 와 20개의 32비트 백업 레지스터(F411, RTC_BKP0R ~ BKP19R = 80 바이트, RM0383 17장)는 VBAT 핀(코인 전지)으로 유지되어 메인 전원이 꺼져도 시계가 갑니다. Nucleo 는 VBAT 이 VDD 에 붙어 있어 전원을 끄면 시계도 멈춥니다.
- 배터리 기기의 기본 패턴: "RTC 웨이크업 1분 → Stop 에서 깨어남 → 센서 읽고 전송 → 다시 Stop". [T04](t04.html) 저전력 절과 함께 보세요.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| PWM 핀에 아무것도 안 나옴 | `HAL_TIM_PWM_Start` 누락, 핀 AF 설정 누락, TIM1 의 MOE | 채널 시작 확인, CubeMX 에서 핀이 TIMx_CHy 로 배정됐는지, 고급 타이머는 HAL 이 MOE 처리 |
| 듀티를 바꾸면 한 주기 파형이 깨짐 | OCxPE (CCR 프리로드) 꺼짐 | CubeMX "Output compare preload" Enable (기본) |
| 주기를 줄였더니 한참 뒤에 반영 | ARPE = 0 에서 CNT 가 새 ARR 을 지나침 | ARPE = 1, 또는 CNT 를 0 으로 리셋 후 변경 |
| 시작하자마자 콜백이 한 번 불림 | Init 의 UG 가 UIF 를 세움 | `__HAL_TIM_CLEAR_FLAG(&htim, TIM_FLAG_UPDATE)` 후 시작, 또는 URS = 1 |
| 주기가 정확히 2배 · ½ | 타이머 클럭 ×2 규칙, 센터 정렬 모드 | 클럭 트리 확인, 센터 정렬은 주기가 2 × ARR |
| 긴 주기(수십 초)가 이상함 | 16비트 ARR 초과 (65535) | 32비트 TIM2 · 5 사용, 또는 소프트웨어 카운터 |
| 입력 캡처 값이 튐 | 잡음, 필터 없음, 오버플로 미고려 | ICxF 필터, 두 캡처 차를 `uint16_t`/`uint32_t` 로 계산 (자동 wrap) |
| 상보 출력에서 MOSFET 이 뜨거움 | 데드타임 부족 (shoot-through) | DTG 값 증가, 게이트 드라이버 지연 확인 |
| IWDG 를 켜니 디버거에서 계속 리셋 | 중단점 동안 워치독 만료 | `__HAL_DBGMCU_FREEZE_IWDG()` |
| RTC 시간이 전원 끄면 사라짐 | VBAT 이 VDD 에 연결 (Nucleo), LSE 없음 | 코인 전지 회로, LSE 크리스털 장착 (UM1724 솔더 브리지) |
