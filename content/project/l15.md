## 학습 목표

- 요구사항을 **입력 · 출력 · 상태(모드)** 로 나누고, 핀 배치와 CubeMX 설정표로 옮깁니다.
- ADC · PWM · EXTI · I2C LCD · UART 를 **하나의 프로그램**으로 묶고, `HAL_GetTick()` 으로 작업 주기를 나눕니다.
- 인터럽트(버튼)와 메인 루프 사이에서 `volatile` 플래그로 상태를 안전하게 주고받습니다.
- 동작 시험 체크리스트로 스스로 검증합니다.

## 요구사항

| 번호 | 요구사항 |
|---|---|
| R1 | 가변저항을 돌리면 선풍기(DC 모터) 속도가 0 ~ 100 % 로 바뀐다 (MANUAL 모드) |
| R2 | B1 버튼을 누를 때마다 모드가 **OFF → MANUAL → BREEZE(자연풍) → OFF** 순서로 바뀐다 |
| R3 | BREEZE 모드는 8초 주기로 30 % ~ 80 % 사이를 부드럽게 오르내린다 |
| R4 | LCD 1행에 모드, 2행에 현재 속도(%)를 표시한다 (0.2초마다 갱신) |
| R5 | UART 로 1초마다 `[시간] mode=… pot=… duty=…%` 로그를 보낸다 |
| R6 | 모드가 OFF 가 아니면 LD2 가 켜진다 |

## 설계

### 핀 배치

| `PA0` | `ADC1_IN0` | — | 가변저항 와이퍼 |

### 주변장치 설정

| 주변장치 | 설정 |
|---|---|
| USART2 | Asynchronous, 115200 8N1 |
| ADC1 | IN0, 12비트, 단일 변환(폴링) |
| TIM3 | PSC `3`, ARR `999`, CH1 PWM Generation, Pulse `0` |
| I2C1 | Standard mode 100 kHz |
| NVIC | EXTI line[15:10] Enabled |

### 프로그램 구조

```text
            ┌────────── B1 인터럽트 (EXTI) ───────────┐
            │  mode = (mode + 1) % 3,  mode_changed = 1 │
            └──────────────────────────────────────────┘
main 루프 (20 ms 마다)
  1. pot  = read_pot()                 ← ADC
  2. duty = compute_duty()             ← 모드별 계산
  3. motor_set(duty), LD2              ← PWM / GPIO
  4. 0.2초마다(또는 모드 변경 시) LCD 갱신   ← I2C
  5. 1초마다 UART 로그                    ← printf
```

**느린 일(LCD, UART)은 주기를 길게, 빠른 일(모터 갱신)은 매번** 하는 것이 핵심입니다. LCD 를 20 ms 마다 쓰면 I2C 전송에 시간이 많이 들어
루프가 느려집니다. 각 작업의 "마지막 실행 시각" 을 저장해 두고 `HAL_GetTick()` 과 비교합니다(L06, L07).

### 코드 읽기

- **모드 상수** — `#define MODE_OFF 0` 처럼 이름을 붙이면 `if (mode == 1)` 보다 읽기 쉽고 실수가 줄어듭니다.
- **`const char *MODE_NAME[3]`** — 모드 번호를 인덱스로 문자열을 꺼냅니다. LCD 와 UART 가 같은 이름을 씁니다.
- **`compute_duty()`** — 모드별 계산을 한 함수로 모아, 새 모드를 추가할 때 이 함수만 고치면 됩니다.
  BREEZE 모드의 삼각파는 `HAL_GetTick() % 8000` 으로 8초 주기 시간을 만들고, 앞 4초는 증가, 뒤 4초는 감소하게 했습니다.
- **`"Mode: %-10s"`** — 6글자 + 10칸 = 16글자로 LCD 한 줄을 꽉 채워 이전 글자를 지웁니다. `"Speed: %3d %%    "` 도 16글자입니다.
- **`%%`** — printf 에서 `%` 글자 자체를 출력합니다.
- **인터럽트는 짧게** — 콜백은 디바운스 후 `mode` 와 `mode_changed` 만 바꾸고, LCD 갱신은 메인 루프가 합니다.

## 시험

:::task 동작 시험 체크리스트
- [ ] 시작 직후 LCD 에 `Mode: OFF`, `Speed:   0 %` 가 보이고 모터가 멈춰 있다 (R2, R4)
- [ ] B1 을 한 번 누르면 `MANUAL` 로 바뀌고 LD2 가 켜진다 (R2, R6)
- [ ] MANUAL 에서 가변저항 `value` 를 0 / 2048 / 4095 로 바꾸면 속도가 0 / 약 50 / 100 % 가 된다 (R1)
- [ ] B1 을 한 번 더 누르면 `BREEZE` — 가변저항과 상관없이 30 ~ 80 % 를 8초 주기로 오르내린다 (R3)
- [ ] 한 번 더 누르면 `OFF` 로 돌아가 모터가 멈추고 LD2 가 꺼진다 (R2, R6)
- [ ] UART 터미널에 1초마다 로그가 한 줄씩 나온다 (R5)
- [ ] 버튼을 빠르게 연타해도 모드가 한 번에 두 칸씩 건너뛰지 않는다 (디바운스)
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| LCD 가 깜빡이거나 글자가 겹침 | 매 루프 Clear(`0x01`) 사용, 16칸을 다 채우지 않음 | Clear 대신 16칸 덮어쓰기 |
| 버튼 반응이 한 박자 늦음 | 루프 안의 긴 작업(LCD 를 매번 갱신) | LCD·UART 주기 분리, `mode_changed` 로 즉시 갱신 |
| MANUAL 에서 가변저항을 0 으로 해도 모터가 윙윙거림 | 낮은 듀티에서 기동하지 못함 | 데드존(L13) 또는 최소 듀티 |
| 모드가 두 칸씩 넘어감 | 디바운스 없음 | 콜백의 200 ms 시간 비교 |
| 빌드 오류 `MODE_NAME` 관련 경고 | 문자열 배열 선언 위치 | PV 구역에 `const char *MODE_NAME[3]` |
| 실물에서 모터가 돌면 LCD 가 깨짐 | 모터 노이즈·전원 강하가 I2C 에 영향 | 모터 전원 분리, 콘덴서, 배선 분리 |

## 과제

1. **자동 모드(AUTO)** 를 추가하세요: 조도센서(CDS, `PA1` ADC1_IN1, L09) 값이 어두우면 약하게, 밝으면 강하게. `compute_duty()` 와 `MODE_NAME` 만 고치면 되도록 설계합니다.
2. **꺼짐 예약**: UART 명령 `timer 10` 을 받으면 10초 뒤 OFF 로 바뀌고, LCD 2행 오른쪽에 남은 초를 표시하세요.
3. 모드가 바뀔 때 속도가 갑자기 변하지 않도록, 목표 듀티까지 초당 30 % 씩 천천히 따라가는 **램프** 기능을 넣으세요.
4. 설계 문서를 작성하세요: 요구사항표, 핀표, 설정표, 구조도, 시험 결과(체크리스트 캡처).
