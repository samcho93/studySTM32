## 학습 목표

- STM32가 **Arm Cortex-M 코어 + ST의 주변장치**로 이루어진 MCU 제품군이라는 것을 설명할 수 있습니다.
- F0 · F1 · F4 · L4 · H7 제품군의 차이(코어, 클럭, 용도)를 표로 비교하고, 칩 이름(`STM32F411RET6`)을 읽을 수 있습니다.
- STM32CubeMX · STM32CubeIDE가 각각 무엇을 하는지, **HAL · LL · 레지스터** 방식이 어떻게 다른지 말할 수 있습니다.
- 이 강좌에서 쓰는 보드(NUCLEO-F411RE, NUCLEO-F103RB, BluePill)의 내장 LED·버튼·가상 COM 포트를 알고 있습니다.

:::info 더 깊이 알고 싶다면 PART 0
이 레슨은 실습에 필요한 만큼만 STM32 를 소개합니다. 제품군 전체 표와 이름 규칙은 [T01](t01.html),
Cortex-M 코어 내부는 [T02](t02.html), 메모리 맵·버스·클럭·GPIO 회로·NVIC·타이머·통신 원리는 [T03](t03.html)~[T08](t08.html) 에서
데이터시트 숫자와 함께 다룹니다. 지금은 건너뛰고 실습을 먼저 해도 되고, 막히는 개념이 나올 때 돌아와도 됩니다.
:::

## STM32는 무엇인가

STM32는 ST마이크로일렉트로닉스(ST)가 만드는 32비트 마이크로컨트롤러(MCU) 제품군입니다.
CPU 코어는 Arm이 설계한 **Cortex-M** 시리즈를 라이선스해 쓰고, 그 둘레에 ST가 만든 GPIO · 타이머 · UART · ADC · I2C · SPI 같은
**주변장치(peripheral)**, 플래시 메모리, SRAM, 클럭 회로를 붙여 한 칩으로 만듭니다.

| 코어 | 특징 | 주로 쓰는 STM32 |
|---|---|---|
| Cortex-M0 / M0+ | 가장 작고 저렴, 저전력 | F0, G0, L0, C0 |
| Cortex-M3 | 32비트 기본형, 하드웨어 나눗셈 | F1, F2, L1 |
| Cortex-M4F | M3 + **DSP 명령 + 단정밀도 FPU** | F3, F4, G4, L4, WB |
| Cortex-M7 | 고성능, 캐시, (일부) 배정밀도 FPU | F7, H7 |
| Cortex-M33 | M4급 성능 + TrustZone 보안 | L5, U5, H5 |

같은 Cortex-M이라도 **주변장치의 레지스터 구조는 ST가 정한 것**이라서, STM32끼리는 제품군이 달라도 코드가 비슷합니다.
그리고 ST가 제공하는 **HAL 라이브러리**가 이 차이를 한 번 더 감춰 주기 때문에, F1에서 쓰던 코드를 F4로 옮기기가 쉽습니다.

## 제품군 비교

| 제품군 | 코어 | 최대 클럭 | 특징 | 대표 칩 · 보드 |
|---|---|---|---|---|
| **F0** | M0 | 48 MHz | 저가형 입문 제품군 | STM32F030, NUCLEO-F030R8 |
| **F1** | M3 | 72 MHz | 가장 오래되고 자료가 많은 주력 제품군 | STM32F103C8(BluePill), NUCLEO-F103RB |
| **F4** | M4F | 84~180 MHz | FPU·DSP, 교육·산업에서 가장 흔한 고성능 범용 | STM32F401/F411(최대 100 MHz), F446(180 MHz) |
| **L4** | M4F | 80 MHz | 초저전력(배터리 기기), 고성능 ADC | STM32L476, NUCLEO-L476RG |
| **H7** | M7 (일부 M7+M4 듀얼) | 480~550 MHz | 최고 성능, 대용량 메모리, 캐시 | STM32H743, NUCLEO-H743ZI |

이 밖에 G0/G4(F0/F3 후속), U5(초저전력 + 보안), WB/WL(블루투스·LoRa 무선) 등이 있습니다.
처음 배울 때는 **F4(특히 F411/F401) 또는 F1** 중 하나로 시작하면 자료를 찾기 쉽습니다.

### 칩 이름 읽기

`STM32F411RET6` 을 한 글자씩 나눠 보면 칩의 사양이 보입니다.

@table[pinmap]
| 부분 | 값 | 뜻 |
|---|---|---|
| `STM32` | — | ST의 32비트 Arm MCU |
| `F` | 제품 종류 | F = 범용(Foundation/Mainstream), L = 저전력, H = 고성능, G = 차세대 범용 |
| `4` | 시리즈 | F4 시리즈 (Cortex-M4F) |
| `11` | 라인 | F411 라인 (최대 100 MHz) |
| `R` | 핀 수 | C = 48핀, R = 64핀, V = 100핀, Z = 144핀 |
| `E` | 플래시 크기 | 8 = 64 KB, B = 128 KB, C = 256 KB, E = 512 KB |
| `T` | 패키지 | T = LQFP, U = QFN, H = BGA |
| `6` | 온도 범위 | 6 = −40~85 °C, 7 = −40~105 °C |

그래서 BluePill의 `STM32F103C8T6` 은 "F1 시리즈 103 라인, **48핀**, **64 KB 플래시**, LQFP, 산업용 온도" 입니다.

## 개발 도구: CubeMX와 CubeIDE

| 도구 | 하는 일 | 이 강좌에서 |
|---|---|---|
| **STM32CubeMX** | 칩 그림에서 핀 기능을 고르고(핀아웃), 클럭 트리와 주변장치(UART 보레이트, 타이머 분주 …)를 설정한 뒤 **초기화 C 코드를 생성**. 설정은 `.ioc` 파일에 저장 | 시뮬레이터의 **핀아웃·설정** 탭이 같은 역할 |
| **STM32CubeIDE** | Eclipse 기반 통합 개발 환경. GCC 컴파일러, 빌드, ST-Link로 플래시·디버그(중단점, 변수 보기) | 시뮬레이터의 **코드** 탭과 빌드·실행 버튼, 실물은 L16 |
| **STM32CubeProgrammer** | 이미 만든 `.hex`/`.bin`/`.elf` 를 보드에 쓰거나 지우기, 옵션 바이트 설정 | L16에서 참고 |

:::info 버전에 따라 설치 방식이 다릅니다
CubeIDE 1.x는 `.ioc` 를 IDE 안에서 바로 열어 CubeMX 화면을 씁니다.
최근 2.x 버전부터는 CubeMX를 **별도 프로그램으로 설치**해 코드를 생성하고, CubeIDE는 편집·빌드·디버그에 집중하도록 바뀌었습니다.
어느 쪽이든 "CubeMX에서 설정 → 코드 생성 → IDE에서 USER CODE 작성 → 빌드·플래시" 흐름은 같습니다.
:::

Keil MDK, IAR EWARM 같은 상용 IDE나 VS Code + CMake 조합도 쓰이지만, 이 강좌는 무료이고 ST가 직접 지원하는 CubeIDE를 기준으로 합니다.

## HAL · LL · 레지스터

STM32 코드를 쓰는 방법은 크게 세 가지입니다. 같은 일 — PA5 핀(LD2)을 반전 — 을 세 방식으로 써 보면 차이가 보입니다.

```c
/* 1) 레지스터 직접 접근: 데이터시트의 레지스터 비트를 그대로 씀 */
GPIOA->ODR ^= (1 << 5);

/* 2) LL (Low-Layer) 드라이버: 레지스터를 얇게 감싼 인라인 함수 (시뮬레이터 미지원) */
LL_GPIO_TogglePin(GPIOA, LL_GPIO_PIN_5);

/* 3) HAL (Hardware Abstraction Layer): 제품군이 달라도 같은 이름·같은 사용법 */
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
```

| 방식 | 장점 | 단점 |
|---|---|---|
| 레지스터 | 가장 빠르고 작음, 동작 원리를 정확히 이해 | 레퍼런스 매뉴얼을 계속 봐야 함, 제품군마다 다를 수 있음 |
| LL | 레지스터에 가까운 속도, 이름이 읽기 쉬움 | 초기화 코드가 길고 제품군 차이가 조금 드러남 |
| **HAL** | CubeMX가 초기화 코드를 만들어 줌, 인터럽트·DMA 처리까지 포함, 제품군 간 이식 쉬움 | 코드 크기가 크고 호출 오버헤드가 있음 |

이 강좌는 **HAL**을 기본으로 하고, 필요한 곳(L03 BSRR, L12 FND)에서 레지스터 직접 접근을 함께 보여 줍니다.
시뮬레이터가 지원하는 HAL 함수 목록은 [HAL 레퍼런스](hal-reference.html)에 정리되어 있습니다.

## 이 강좌의 보드

@table[pinmap]
| 보드 | MCU | 클럭(기본) | 내장 장치 | 연결 |
|---|---|---|---|---|
| **NUCLEO-F411RE** | STM32F411RET6 (M4F) | 84 MHz | LD2 = `PA5`, B1 = `PC13`(누르면 LOW), VCP = USART2(`PA2` TX / `PA3` RX) | USB 하나로 전원 + ST-Link 디버거 + 가상 COM |
| **NUCLEO-F103RB** | STM32F103RBT6 (M3) | 72 MHz | 위와 같은 배치 | 위와 같음 |
| **BluePill** | STM32F103C8T6 (M3) | 72 MHz | LED = `PC13` (**LOW일 때 켜짐**) | 별도 ST-Link(SWD) 필요, USB는 전원/USB 장치용 |

Nucleo-64 보드는 윗부분에 **ST-Link가 내장**되어 있어 USB 케이블 하나로 전원, 프로그램 쓰기, 디버그, 시리얼 통신(가상 COM 포트)이 모두 됩니다.
아두이노 우노와 같은 모양의 헤더(A0~A5, D0~D15)와 모든 핀이 나오는 모포(morpho) 헤더가 있어 브레드보드 실습에 편합니다.
그래서 이 강좌의 예제는 대부분 **NUCLEO-F411RE**를 기준으로 합니다.

:::warn BluePill 구입 시 주의
값싼 BluePill 중에는 STM32가 아닌 호환 칩(CKS32, CS32 등)이 달린 제품이 있습니다.
CubeIDE가 "ST 정품이 아닌 장치"라며 디버그를 거부하거나 동작이 조금 다를 수 있으니, 수업용으로는 Nucleo 보드를 권합니다.
:::

## 이 강좌의 학습 흐름

1. **CubeMX 핀 설정** — 시뮬레이터의 핀아웃·설정 탭에서 핀 기능과 주변장치를 정합니다.
2. **HAL 코드** — 생성된 `main.c` 의 `USER CODE` 구역에 코드를 씁니다.
3. **시뮬레이터** — 회로 노드(LED, 버튼, LCD, 모터 …)를 연결하고 빌드·실행해 결과를 확인합니다.
4. **실물 보드** — 같은 `.ioc` 설정과 같은 코드를 STM32CubeIDE로 옮겨 Nucleo 보드에서 실행합니다(L16).

다음 레슨(L02)에서 시뮬레이터 화면을 둘러보고 첫 프로젝트를 만들어 봅니다.

- CubeMX가 만들어 주는 것과 여러분이 직접 써야 하는 것은 각각 무엇인가요?

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| CubeIDE에서 보드를 골랐는데 칩 이름이 다름 | Board Selector 대신 MCU Selector에서 비슷한 칩을 고름 | 새 프로젝트를 **Board Selector → NUCLEO-F411RE** 로 다시 만들기 (LD2·B1·USART2가 자동 설정됨) |
| PC에서 보드가 인식되지 않음 (`No ST-LINK detected`) | 충전 전용 USB 케이블, ST-Link 드라이버 미설치 | 데이터 케이블로 교체, CubeIDE/CubeProgrammer 설치 시 ST-Link 드라이버 포함 여부 확인 |
| BluePill이 디버거에 연결되지 않음 | 정품이 아닌 호환 칩, SWD 배선 오류, 3.3V 미공급 | SWDIO·SWCLK·GND·3.3V 네 선 확인, 가능하면 Nucleo로 실습 |
| 인터넷 예제 코드가 컴파일되지 않음 | 다른 제품군(F1 ↔ F4) 헤더·클럭 설정 차이, LL/레지스터 코드 혼용 | 예제가 어느 보드·HAL 기준인지 확인하고 CubeMX 설정부터 맞추기 |

## 과제

1. 여러분이 가진(또는 사고 싶은) STM32 보드의 칩 이름을 적고, 위의 "칩 이름 읽기" 표로 사양을 풀어 쓰세요.
2. NUCLEO-F411RE 의 LD2, B1, 가상 COM 포트가 연결된 핀을 외우고, 왜 PA5를 다른 용도로 쓰면 LED가 같이 반응하는지 설명하세요.
3. HAL · LL · 레지스터 방식을 쓰기 쉬움 / 실행 속도 / 이식성 기준으로 비교한 표를 직접 만들어 보세요.
