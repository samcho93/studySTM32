## 학습 목표

- 시뮬레이터의 네 영역 — **프로젝트 탐색기, 디자인 영역(회로 노드 / 핀아웃·설정 / 코드), 실습 결과 영역, Properties** — 이 각각 무엇을 하는지 압니다.
- CubeMX 흐름 **핀아웃 설정 → Generate Code → USER CODE 작성 → Build → Run** 을 처음부터 끝까지 한 번 해 봅니다.
- `main.c` 의 구조(초기화 함수 호출 → `while (1)`)와 **USER CODE 구역 규칙**을 설명할 수 있습니다.

## 시뮬레이터 화면 구성

@sim[l02-first] 첫 프로젝트 열기

시뮬레이터는 STM32CubeIDE와 CubeMX 화면을 한 페이지에 합친 모양입니다. 레슨 페이지에서 위 버튼을 누르면 오른쪽 실습 패널에 열리고,
**새 창**을 누르면 전체 화면으로 열립니다. 화면은 다음 네 영역으로 나뉩니다.

| 영역 | 하는 일 | CubeIDE에서는 |
|---|---|---|
| **프로젝트 탐색기** (왼쪽) | `Core/Inc/main.h`, `Core/Src/main.c`, `.ioc` 설정, 읽기 전용 HAL 헤더(`Drivers/STM32F4xx_HAL_Driver/Inc/*.h`) 파일 트리 | Project Explorer |
| **디자인 영역** (가운데) | 세 개의 탭: **회로 노드** · **핀아웃·설정** · **코드** | `.ioc` 편집기 + C 편집기 |
| **실습 결과 영역** | 보드 그림(LD2·B1), 연결한 장치의 상태(LED 밝기, LCD 글자, 모터 회전), UART 터미널, 로직 분석기 파형 | 실물 보드 + 터미널 프로그램 |
| **Properties** | 선택한 핀·노드·주변장치의 속성(LED 색, 가변저항 값, 보레이트 …)을 보고 바꾸기 | Properties 뷰 |

### 디자인 영역의 세 탭

- **회로 노드** — LED, 버튼, 가변저항, LCD, 모터 같은 장치 노드를 놓고, 노드의 포트를 MCU 핀에 선으로 연결합니다.
  보드 프리셋을 고르면 그 보드의 내장 장치(Nucleo: LD2, B1, ST-Link 가상 COM)가 처음부터 들어 있습니다.
- **핀아웃·설정** — CubeMX처럼 칩 그림에서 핀을 눌러 기능(`GPIO_Output`, `USART2_TX`, `TIM3_CH1` …)을 고르고,
  주변장치 모드와 파라미터(보레이트, 타이머 PSC/ARR, ADC 채널), NVIC 인터럽트를 켭니다. 핀에 **User Label**(예: `LD2`)을 붙일 수 있습니다.
- **코드** — 설정으로 생성된 `main.c` 를 편집합니다. 여러분이 코드를 쓸 수 있는 곳은 `/* USER CODE BEGIN ... */` 와 `/* USER CODE END ... */` 사이뿐입니다.

## 첫 프로젝트: 따라 하기

목표는 보드 LED **LD2를 0.1초 켜고 0.9초 끄는** 심장 박동 표시등입니다. 위의 예제 버튼으로 완성본을 열 수 있지만,
처음 한 번은 아래 순서대로 직접 해 보세요.

1. **MCU 고르기** — Properties(또는 클럭 & 프로젝트 탭)의 **MCU** 에서 `STM32F411RE` 를, **보드 프리셋**에서 `NUCLEO-F411RE` 를 고릅니다.
   SYSCLK는 84 MHz로 설정됩니다. 보드 프리셋을 "없음"으로 두면 MCU 만 놓고 LED·버튼을 직접 배선하는 연습을 할 수 있습니다.
2. **핀아웃** — 핀아웃·설정 탭에서 `PA5` 를 눌러 `GPIO_Output` 을 고르고, User Label을 `LD2` 로 적습니다.
   (Nucleo 보드 기본 설정에는 이미 들어 있습니다.)
3. **Generate Code** — 코드를 생성하면 `main.h` 에 라벨 매크로가, `main.c` 에 `MX_GPIO_Init()` 이 만들어집니다.
4. **USER CODE 작성** — `main.c` 의 `while (1)` 안, `USER CODE BEGIN 3` 구역에 아래 코드를 씁니다.
5. **Build** — 빌드 버튼을 누르고 콘솔에 오류가 0개인지 확인합니다. 플래시·RAM 사용량(text/data/bss)도 표시됩니다.
6. **Run** — 실행하면 실습 결과 영역의 보드 그림에서 LD2가 1초에 한 번 짧게 깜빡입니다.

## 생성된 코드 읽기

CubeMX가 만든 `main.c` 는 항상 같은 뼈대를 가집니다. (주석과 일부 줄은 줄였습니다)

```c Core/Src/main.c
#include "main.h"

/* USER CODE BEGIN Includes */
/* USER CODE END Includes */

/* USER CODE BEGIN PV */          // 전역 변수는 여기
/* USER CODE END PV */

void SystemClock_Config(void);
static void MX_GPIO_Init(void);
/* USER CODE BEGIN PFP */         // 내 함수 원형은 여기
/* USER CODE END PFP */

/* USER CODE BEGIN 0 */           // 내 함수 정의 (main 위)
/* USER CODE END 0 */

int main(void)
{
  HAL_Init();                     // HAL 초기화 + 1 ms SysTick 시작
  SystemClock_Config();           // 클럭 트리 설정 (84 MHz)
  MX_GPIO_Init();                 // CubeMX에서 설정한 핀 초기화

  /* USER CODE BEGIN 2 */         // 초기화 뒤 한 번만 실행할 코드
  /* USER CODE END 2 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */       // 계속 반복할 코드
  }
  /* USER CODE END 3 */
}

/* USER CODE BEGIN 4 */           // 콜백 함수 등 (main 아래)
/* USER CODE END 4 */
```

`main.h` 에는 핀 라벨로 만든 매크로가 들어갑니다. 코드에서 `GPIOA`, `GPIO_PIN_5` 대신 `LD2_GPIO_Port`, `LD2_Pin` 을 쓰면
나중에 LED를 다른 핀으로 옮겨도 CubeMX에서 라벨만 옮기면 됩니다.

```c Core/Inc/main.h
#define LD2_Pin GPIO_PIN_5
#define LD2_GPIO_Port GPIOA
#define B1_Pin GPIO_PIN_13
#define B1_GPIO_Port GPIOC
```

:::warn USER CODE 구역 밖에 쓴 코드는 사라집니다
CubeMX 설정을 바꾸고 코드를 다시 생성하면 `USER CODE BEGIN` ~ `END` **사이만 보존**되고 나머지는 새로 덮어씁니다.
`#include` 는 `Includes` 구역, 전역 변수는 `PV`, 함수 원형은 `PFP`, 함수 정의는 `0` 또는 `4` 구역에 쓰는 습관을 들이세요.
:::

### 이 강좌의 코드 표기

레슨의 코드 블록은 위처럼 `/* USER CODE BEGIN ... */` 표시와 함께 보여 줍니다. 시뮬레이터 예제도 같은 구역에 같은 코드가 들어 있으니,
표시된 구역에 그대로 옮겨 쓰면 됩니다. 실물 CubeIDE 프로젝트에서도 마찬가지입니다(L16).

## 실습

:::task 실습 A — 속도 바꾸기
1. 예제를 열고 `HAL_Delay(100)` 과 `HAL_Delay(900)` 의 값을 바꿔 **빠르게 두 번 깜빡이고 쉬는** 패턴을 만드세요.
2. Build → Run 으로 확인합니다. 빌드 오류가 나면 콘솔의 줄 번호를 눌러 해당 줄로 이동합니다.
:::

:::task 실습 B — 코드 재생성 실험
1. `USER CODE` 구역 **밖**(예: `MX_GPIO_Init();` 바로 아래)에 `HAL_Delay(1000);` 을 한 줄 넣습니다.
2. 핀아웃·설정 탭에서 아무 설정이나 바꾼 뒤 코드를 다시 생성하고, 그 줄이 사라지는지 확인합니다.
3. 같은 줄을 `USER CODE BEGIN 2` 구역에 넣고 다시 생성해 보존되는지 확인합니다.
:::

:::check 스스로 확인
- `HAL_Init()` 이 없으면 `HAL_Delay()` 가 동작하지 않는 이유는? (힌트: SysTick)
- 핀 라벨을 `LD2` 에서 `LED_STATUS` 로 바꾸면 코드에서 무엇을 고쳐야 하나요?
:::

:::info 다른 MCU 로 바꿔 보기
시뮬레이터는 F0 · F1 · F4 · G0 · L4 제품군의 MCU 9종을 지원합니다. 같은 프로젝트에서 MCU 만 바꾸면
`SystemClock_Config()` 의 PLL 설정, Flash 대기 상태, ADC 초기화, EXTI 인터럽트 이름이 그 제품군에 맞게 다시 생성되고,
USER CODE 구역과 직접 추가한 장치·배선은 그대로 남습니다. 예를 들어 `STM32G071RB` 로 바꾸고 다시 빌드한 뒤
`main.c` 의 `SystemClock_Config()` 가 어떻게 달라졌는지 비교해 보세요. 제품군별 차이는 [T01 STM32 제품군 총람](t01.html)에서 다룹니다.
:::

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `'LD2_Pin' undeclared` | 핀에 User Label을 붙이지 않았거나 다른 이름으로 붙임 | 핀아웃에서 라벨 확인 후 다시 생성, 또는 `GPIO_PIN_5` / `GPIOA` 직접 사용 |
| 코드를 다시 생성했더니 내가 쓴 코드가 없어짐 | `USER CODE` 구역 밖에 작성 | 구역 안으로 옮기기 (위 실습 B) |
| 빌드는 되는데 LED가 켜진 채 그대로 | `while (1)` 밖(`USER CODE 2`)에 깜빡임 코드를 씀 | 반복할 코드는 `USER CODE BEGIN 3` 에 |
| `expected ';' before ...` | 앞 줄 끝의 세미콜론 누락 | 오류가 난 줄의 **바로 윗줄**을 확인 |
| 실행해도 아무 변화 없음 | 핀을 `GPIO_Output` 으로 설정하지 않음(Reset 상태) | 핀아웃에서 PA5 기능 확인 후 다시 생성 |

## 과제

1. LD2로 모스 부호 SOS(짧게 3번, 길게 3번, 짧게 3번)를 반복하는 프로그램을 만드세요. 짧게 = 200 ms, 길게 = 600 ms.
2. 생성된 `main.c` 에서 `HAL_Init`, `SystemClock_Config`, `MX_GPIO_Init` 이 각각 무엇을 하는지 한 줄씩 적으세요.
3. 여러분이 쓴 코드를 USER CODE 구역별(Includes / PV / PFP / 0 / 2 / 3 / 4)로 나누어 정리하는 표를 만드세요.
