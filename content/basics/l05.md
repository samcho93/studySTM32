## 학습 목표

- 폴링과 인터럽트의 차이를 알고, 인터럽트가 필요한 상황을 판단합니다.
- EXTI 라인(0~15)과 포트의 관계, NVIC 인터럽트 채널(`EXTI0` … `EXTI15_10`)을 이해합니다.
- CubeMX에서 `GPIO_EXTI` 핀과 NVIC 를 설정하고, `HAL_GPIO_EXTI_Callback` 을 올바르게 작성합니다.
- 인터럽트 코드의 규칙 — **짧게, `volatile`, 안에서 `HAL_Delay` 금지** — 을 지킵니다.

## 폴링 vs 인터럽트

L04에서는 `while (1)` 안에서 버튼을 계속 읽었습니다(폴링). 루프에 1초짜리 `HAL_Delay` 가 있다면 버튼을 눌러도 최대 1초 뒤에야 알아챕니다.
**인터럽트**는 하드웨어가 신호 변화를 감지하는 즉시 CPU가 하던 일을 잠시 멈추고 정해진 함수(인터럽트 핸들러)를 실행한 뒤 돌아오는 방식입니다.

| | 폴링 | 인터럽트 |
|---|---|---|
| 반응 시간 | 루프 한 바퀴만큼 늦을 수 있음 | 수 µs 이내 |
| CPU 사용 | 계속 확인하느라 바쁨 | 일이 있을 때만 |
| 코드 난이도 | 쉬움 | 공유 변수·우선순위를 신경 써야 함 |
| 알맞은 곳 | 느린 입력, 단순한 프로그램 | 버튼, 엔코더, 통신 수신, 정확한 타이밍 |

## EXTI 와 NVIC

**EXTI(External Interrupt/Event Controller)** 는 GPIO 핀의 상승·하강 에지를 감지하는 블록입니다. 라인이 0~15 까지 있고,
**라인 번호 = 핀 번호** 입니다. `PA0`, `PB0`, `PC0` 은 모두 EXTI0 라인을 공유하므로 **같은 번호의 핀은 한 포트만** 인터럽트로 쓸 수 있습니다.

EXTI 라인은 NVIC(중첩 벡터 인터럽트 컨트롤러)의 인터럽트 채널에 이렇게 묶입니다.

@table[regmap]
| NVIC 채널 | EXTI 라인 | 핸들러 함수 (`stm32f4xx_it.c`) |
|---|---|---|
| `EXTI0_IRQn` ~ `EXTI4_IRQn` | 0 ~ 4 (각각 따로) | `EXTI0_IRQHandler` … `EXTI4_IRQHandler` |
| `EXTI9_5_IRQn` | 5 ~ 9 공유 | `EXTI9_5_IRQHandler` |
| `EXTI15_10_IRQn` | 10 ~ 15 공유 | `EXTI15_10_IRQHandler` — **B1(PC13)** 이 여기 |

### CubeMX 설정

1. `PC13` 을 눌러 `GPIO_EXTI13` 을 고르고 라벨을 `B1` 로 둡니다.
2. GPIO 설정에서 **GPIO mode** 를 `External Interrupt Mode with Falling edge trigger detection` 으로 — B1 은 누르면 LOW 이므로 **하강 에지**.
3. **NVIC** 탭에서 `EXTI line[15:10] interrupts` 를 **Enabled** 로 켭니다. 이걸 빼먹으면 콜백이 절대 불리지 않습니다.

## HAL 인터럽트 호출 흐름

코드를 생성하면 인터럽트 한 번에 다음 순서로 함수가 불립니다.

```text
PC13 하강 에지
  → EXTI15_10_IRQHandler()                 (stm32f4xx_it.c, 자동 생성)
    → HAL_GPIO_EXTI_IRQHandler(B1_Pin)     (HAL: 대기 플래그 확인 후 지움)
      → HAL_GPIO_EXTI_Callback(B1_Pin)     ← 여러분이 USER CODE 4 에 작성
```

`HAL_GPIO_EXTI_Callback` 은 HAL 안에 **weak(약한) 함수**로 비어 있게 정의되어 있고, 같은 이름의 함수를 여러분이 정의하면 그것이 대신 쓰입니다.
여러 핀이 같은 콜백을 부르므로 인자 `GPIO_Pin` 으로 어느 핀인지 구분합니다.

:::info 일부 새 제품군은 이름이 다릅니다
G0 · L5 · U5 · H5 같은 제품군은 콜백이 `HAL_GPIO_EXTI_Rising_Callback` / `HAL_GPIO_EXTI_Falling_Callback` 으로 나뉘어 있습니다.
이 강좌의 F4 · F1 은 하나의 `HAL_GPIO_EXTI_Callback` 을 씁니다.
:::

## 예제 — 인터럽트로 LD2 토글

메인 루프는 일부러 1초씩 멈추며(`HAL_Delay(1000)`) 외부 LED 를 깜빡입니다. 그래도 B1 을 누르면 LD2 는 **즉시** 바뀝니다.

@sim[l05-exti] EXTI 토글 열기

@code[l05-exti] pv,loop,u4

### 코드 읽기

- **`volatile`** — `press_count` 는 인터럽트에서 바뀌고 메인 코드에서 읽힙니다. 컴파일러 최적화가 "이 변수는 루프 안에서 안 바뀐다" 고 판단해
  값을 레지스터에 담아 두면 변화가 보이지 않습니다. `volatile` 은 "매번 메모리에서 다시 읽어라" 는 표시입니다.
- **시간 비교 디바운스** — 인터럽트 안에서는 기다릴 수 없으므로, 마지막으로 인정한 시각(`last_press`)에서 200 ms 가 지나지 않았으면 무시합니다.
  `now - last_press` 처럼 **뺄셈으로 비교**하면 `HAL_GetTick()` 이 약 49.7일 뒤 0으로 돌아가도(unsigned 오버플로) 올바르게 동작합니다.
- **짧게** — 콜백에서는 플래그·카운터만 바꾸고, 긴 작업(printf, LCD 출력)은 메인 루프에서 처리하는 것이 원칙입니다.

:::danger 인터럽트 안에서 HAL_Delay 금지
`HAL_Delay()` 는 SysTick 인터럽트가 올려 주는 틱 카운터를 기다립니다. CubeMX 기본 설정에서 SysTick 의 우선순위(TICK_INT_PRIORITY)는
EXTI 와 같거나 낮기 때문에, EXTI 콜백 안에서 `HAL_Delay()` 를 부르면 **SysTick 이 끼어들지 못해 틱이 멈추고 프로그램이 영원히 멈춥니다.**
:::

## 인터럽트 우선순위

NVIC 는 우선순위 숫자가 **작을수록 먼저** 처리합니다. 우선순위가 더 높은(숫자가 작은) 인터럽트는 낮은 인터럽트 처리 중에도 끼어들 수 있습니다(선점).
CubeMX NVIC 탭의 *Preemption Priority* 로 정하고, 생성 코드에서는 다음처럼 설정됩니다.

```c
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 0, 0);   // (IRQ 번호, 선점 우선순위, 서브 우선순위)
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
```

:::task 실습
1. NVIC 에서 `EXTI line[15:10]` 을 끄고 실행해 보세요. 버튼을 눌러도 아무 일이 없는 것을 확인합니다.
2. 트리거를 `rising`(상승 에지)으로 바꾸면 LD2 가 언제 바뀌나요? `both` 로 바꾸면?
3. 디바운스 시간을 0으로 바꾸고 결과를 관찰한 뒤, 실물 보드에서는 어떻게 될지 설명하세요.
:::

:::check 스스로 확인
- `PA3` 과 `PB3` 을 동시에 EXTI 로 쓸 수 없는 이유는?
- `PC13` 과 `PA10` 을 EXTI 로 쓰면 콜백 안에서 어떻게 구분하나요? 두 핀은 같은 NVIC 채널인가요?
:::

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 콜백이 전혀 불리지 않음 | NVIC 채널을 켜지 않음 / 핀 모드가 `GPIO_Input` / 함수 이름 오타(`HAL_GPIO_EXTI_CallBack`) | NVIC 탭 확인, `GPIO_EXTIx` 로 설정, 이름은 대소문자까지 정확히 (weak 함수라 오타여도 오류가 안 남) |
| 한 번 눌렀는데 여러 번 실행 | 채터링 | 시간 비교 디바운스 |
| 버튼을 누르면 프로그램이 멈춤 | 콜백 안 `HAL_Delay`, 긴 `printf` | 콜백은 플래그만, 작업은 메인 루프에서 |
| 메인에서 변수 변화가 안 보임 | `volatile` 누락 (최적화 켠 실물 빌드에서 특히) | 공유 변수에 `volatile` |
| 다른 핀 인터럽트에도 LED 가 바뀜 | `GPIO_Pin` 을 확인하지 않음 | `if (GPIO_Pin == B1_Pin)` |

## 과제

1. B1 로 LD2 깜빡임 속도를 100 / 300 / 1000 ms 세 단계로 바꾸는 프로그램을 만드세요. 속도 변경은 인터럽트, 깜빡임은 메인 루프에서.
2. 외부 버튼 두 개를 `PA1`(EXTI1)과 `PB4`(EXTI4)에 연결하고 하나는 +1, 하나는 −1 을 하도록 만드세요. NVIC 에서 무엇을 켜야 하나요?
3. `volatile` 을 빼고 컴파일 최적화(-O2)를 켰을 때 생길 수 있는 문제를 예를 들어 설명하세요.
