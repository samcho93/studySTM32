## 학습 목표

- 비동기 직렬 통신(UART)의 프레임(시작 비트, 8N1)과 보레이트를 이해하고, TX ↔ RX 교차 배선을 합니다.
- Nucleo 의 **ST-Link 가상 COM 포트(USART2)** 로 PC 터미널과 문자를 주고받습니다.
- `__io_putchar` **리타깃**으로 `printf` 를 UART 로 보내고, **줄 버퍼**와 `%f` 설정 문제를 해결합니다.
- `HAL_UART_Receive_IT` 와 `HAL_UART_RxCpltCallback` 으로 수신을 인터럽트로 처리하고, 한 줄 명령어를 해석합니다.

## UART 기초

UART 는 클럭 선 없이 **송신(TX)** 과 **수신(RX)** 두 선으로 데이터를 주고받습니다. 양쪽이 같은 속도(보레이트)를 미리 약속해 두고,
한 글자(바이트)마다 다음 모양의 프레임을 보냅니다.

```text
 대기(HIGH) ─┐  시작  D0 D1 D2 D3 D4 D5 D6 D7  정지 ┌─ 대기
             └─ 0 ──[   데이터 8비트, LSB 먼저   ]── 1 ┘
          8N1 = 데이터 8비트, 패리티 없음(None), 정지 비트 1
```

115200 bps 에서 한 비트는 약 8.7 µs, 한 글자(10비트)는 약 87 µs 입니다. 연결은 **내 TX → 상대 RX, 내 RX ← 상대 TX** 로 교차하고, **GND 를 공통**으로 묶습니다.

### Nucleo 의 가상 COM 포트

NUCLEO-F411RE 의 `USART2`(`PA2` = TX, `PA3` = RX)는 보드 위 ST-Link 에 연결되어 있고, ST-Link 가 이를 USB 가상 COM 포트(VCP)로 PC 에 보여 줍니다.
그래서 **USB 케이블 하나로** PC 터미널(Tera Term, PuTTY, CubeIDE 콘솔)과 통신할 수 있습니다. 시뮬레이터에서는 보드 내장 `vcp` 노드가 이 터미널입니다.

@table[pinmap]
| 핀 | 신호 | 연결 |
|---|---|---|
| `PA2` | `USART2_TX` | ST-Link VCP 의 RX (PC 로 가는 방향) |
| `PA3` | `USART2_RX` | ST-Link VCP 의 TX (PC 에서 오는 방향) |

CubeMX 설정: **Connectivity → USART2 → Mode: Asynchronous**, Baud Rate `115200`, Word Length 8 Bits, Parity None, Stop Bits 1.
수신 인터럽트를 쓰려면 **NVIC Settings → USART2 global interrupt** 를 켭니다.

## HAL 송수신 함수

```c
HAL_StatusTypeDef HAL_UART_Transmit(UART_HandleTypeDef *huart, const uint8_t *pData, uint16_t Size, uint32_t Timeout);
HAL_StatusTypeDef HAL_UART_Receive(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size, uint32_t Timeout);
HAL_StatusTypeDef HAL_UART_Receive_IT(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size);
```

- `huart` — CubeMX 가 만든 핸들 `&huart2`
- `Transmit` / `Receive` 는 **다 보내거나 받을 때까지(또는 Timeout ms 까지) 기다리는** 블로킹 함수입니다. `HAL_MAX_DELAY` 는 무한 대기.
- `Receive_IT` 는 수신을 **예약만 하고 바로 돌아옵니다.** `Size` 바이트가 다 들어오면 `HAL_UART_RxCpltCallback` 이 불립니다.

```c
char msg[] = "Hello\r\n";
HAL_UART_Transmit(&huart2, (uint8_t *)msg, strlen(msg), 100);
```

## printf 리타깃

`printf` 는 표준 라이브러리 함수라서 "글자를 어디로 보낼지" 모릅니다. STM32CubeIDE 프로젝트의 `syscalls.c` 에는 다음과 같은 `_write()` 가 들어 있고,
글자마다 `__io_putchar()` 를 부릅니다. 이 함수를 **여러분이 정의해 UART 로 보내면** printf 가 UART 로 나갑니다.

```c Core/Src/syscalls.c (CubeIDE 생성, 요약)
extern int __io_putchar(int ch) __attribute__((weak));

int _write(int file, char *ptr, int len)
{
  for (int i = 0; i < len; i++) {
    __io_putchar(*ptr++);
  }
  return len;
}
```

리타깃 코드는 이렇게 씁니다. `(uint8_t *)&ch` 는 `int ch` 의 첫 바이트(리틀 엔디언이므로 하위 바이트 = 글자)를 가리킵니다.

@code[l06-printf] includes,pfp,u4

:::warn printf 가 안 나오는 대표 원인 세 가지
1. **리타깃 함수가 없음** — 실물과 똑같이 시뮬레이터도 `__io_putchar` (또는 `_write`) 를 정의해야 출력됩니다.
2. **줄 버퍼** — stdout 은 `\n` 이 나올 때 한꺼번에 내보냅니다. `printf("> ")` 처럼 줄바꿈이 없으면 쌓여만 있다가 나중에 나옵니다.
   바로 보내려면 `fflush(stdout);` 을 부르세요.
3. **`%f` 가 빈칸** — 용량을 줄인 newlib-nano 는 기본으로 실수 출력을 뺍니다. CubeIDE 에서
   *Project Properties → C/C++ Build → Settings → MCU Settings → Use float with printf from newlib-nano (-u _printf_float)* 를 켜야 합니다.
   시뮬레이터는 프로젝트 설정 `printfFloat` 이 같은 역할입니다(L09 에서 사용).
:::

터미널 프로그램은 줄바꿈으로 `\r\n`(CR LF) 을 기대하는 경우가 많아 예제는 `\r\n` 으로 끝냅니다.

@code[l06-printf] pv,u2,loop,u4

### 코드 읽기

- **`HAL_Delay` 없이 1초마다** — `HAL_GetTick() - last_print >= 1000` 을 확인하는 방식이라 루프가 멈추지 않고, 그 사이에 수신 처리도 할 수 있습니다.
- **수신 인터럽트** — `u2` 에서 한 번 `HAL_UART_Receive_IT` 로 1바이트 수신을 예약하고, 콜백에서 **다시 예약**합니다. 다시 예약하지 않으면 첫 글자만 받고 끝납니다.
- **콜백은 짧게** — 콜백은 `rx_flag` 만 세우고, printf 는 메인 루프에서 합니다(L05 의 규칙).
- `%lu` — `uint32_t` 는 Arm GCC 에서 `unsigned long` 이므로 `%lu` 가 맞습니다(`%u` 도 동작하지만 경고).

- `line[line_len] = '\0'` — C 문자열은 끝에 0 이 있어야 `strcmp`, `printf("%s")` 가 끝을 압니다.
- `line_len < sizeof(line) - 1` — 버퍼가 넘치지 않도록 마지막 한 칸은 `'\0'` 자리로 남깁니다.
- 한 줄을 처리하는 동안(`line_ready == 1`) 들어온 글자는 버립니다. 더 견고하게 하려면 링 버퍼를 씁니다(과제).

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 터미널에 알 수 없는 글자(깨진 문자)만 나옴 | **보레이트 불일치**, 클럭 설정 오류 | 양쪽 보레이트·8N1 동일하게, SystemClock 설정 확인 |
| printf 가 아무것도 안 나옴 | 리타깃 함수 없음, `__io_putchar` 이름 오타 | USER CODE 4 에 `__io_putchar` 정의, PFP 에 원형 |
| 줄바꿈 없는 printf 가 늦게 나옴 | stdout 줄 버퍼 | `\n` 을 붙이거나 `fflush(stdout)` |
| `%f` 자리에 아무것도 없음 | newlib-nano 실수 출력 꺼짐 | `-u _printf_float` (시뮬레이터: `printfFloat` 설정) |
| 첫 글자만 받고 이후 수신 안 됨 | 콜백에서 `Receive_IT` 재예약 누락 | 콜백 끝에서 다시 `HAL_UART_Receive_IT` |
| 수신 콜백이 전혀 안 불림 | NVIC 에서 USART2 global interrupt 꺼짐 | NVIC 켜기 |
| 실물에서 COM 포트가 안 보임 | ST-Link 드라이버, 충전 전용 케이블 | 드라이버 설치, 장치 관리자에서 *STMicroelectronics STLink Virtual COM Port* 확인 |
