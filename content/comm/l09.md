## 학습 목표

- 12비트 ADC 의 분해능과 **변환 공식**(값 ↔ 전압)을 이해합니다.
- 가변저항과 조도센서(CDS)를 **분압 회로**로 ADC 핀에 연결합니다.
- `HAL_ADC_Start` → `HAL_ADC_PollForConversion` → `HAL_ADC_GetValue` 폴링 변환으로 값을 읽고, PWM 밝기와 UART 출력에 씁니다.
- 여러 채널을 **스캔 + 연속 변환 + 순환 DMA** 로 자동으로 받아 오는 설정을 할 수 있습니다.

## ADC 기초

ADC(Analog-to-Digital Converter)는 핀의 전압을 숫자로 바꿉니다. STM32F4 의 ADC 는 **12비트**라서 0 V ~ 기준 전압(VREF+, Nucleo 에서는 3.3 V)을
**0 ~ 4095** 로 나타냅니다.

$전압 = 값 × 3.3 / 4095$ 　　 $값 = 전압 × 4095 / 3.3$

| 입력 전압 | ADC 값 |
|---|---|
| 0 V | 0 |
| 1.65 V | 약 2048 |
| 3.3 V | 4095 |

(엄밀히는 한 칸이 3.3/4096 V 이지만, 끝값 4095 가 3.3 V 가 되도록 4095 로 나누는 방식을 흔히 씁니다.)

:::danger ADC 핀에 5 V 금지
아날로그 입력으로 설정한 핀은 **5V 허용(FT) 핀이라도 3.3 V 를 넘으면 안 됩니다.** 5 V 센서 모듈은 저항 분압으로 3.3 V 이하로 낮추세요.
:::

### 채널과 핀 (NUCLEO-F411RE, ADC1)

@table[pinmap]
| 핀 | 채널 | Nucleo 헤더 |
|---|---|---|
| `PA0` | `ADC1_IN0` | A0 |
| `PA1` | `ADC1_IN1` | A1 |
| `PA4` | `ADC1_IN4` | A2 |
| `PB0` | `ADC1_IN8` | A3 |
| `PC1` | `ADC1_IN11` | A4 |
| `PC0` | `ADC1_IN10` | A5 |

### 배선: 분압 회로

- **가변저항** — 양 끝을 3.3 V 와 GND, 가운데(와이퍼)를 `PA0` 에. 돌리면 0 ~ 3.3 V 가 나옵니다.
- **조도센서(CDS)** — CDS 와 고정 저항(10 kΩ 정도)을 직렬로 3.3 V–GND 사이에 두고 가운데를 `PA1` 에. 밝을수록 CDS 저항이 작아지므로,
  CDS 가 3.3 V 쪽이면 밝을수록 값이 **커지고**, GND 쪽이면 **작아집니다.** 어느 방향인지는 배선을 보고 판단하세요.

## 예제 1 — 폴링으로 가변저항 읽기

CubeMX: **Analog → ADC1 → IN0** 체크(나머지는 기본값: 12 bits, 단일 변환). 같은 프로젝트에 TIM3 CH1 PWM(L08)과 USART2(L06)도 켭니다.

@sim[l09-pot] 가변저항 → UART + LED 열기

@code[l09-pot] u2,loop

폴링 변환은 세 단계입니다.

```c
HAL_ADC_Start(&hadc1);                      // 1) 변환 시작
HAL_ADC_PollForConversion(&hadc1, 10);      // 2) 끝날 때까지 최대 10 ms 대기 → HAL_OK / HAL_TIMEOUT
uint32_t v = HAL_ADC_GetValue(&hadc1);      // 3) 12비트 결과 (0~4095)
```

- 같은 값으로 PWM 듀티(`adc_value * 999 / 4095`)를 정해 가변저항을 돌리면 LED 밝기가 따라 바뀝니다.
- `printf("%.2f")` 를 쓰므로 **실수 printf 설정**이 켜져 있어야 합니다(L06). 이 예제는 시뮬레이터 설정 `printfFloat` 을 켜 두었습니다.
  실수 출력을 피하고 싶다면 `mv = adc_value * 3300 / 4095;` 로 **mV 정수**를 계산해 `%lu mV` 로 출력하는 방법도 좋습니다.

:::tip 값이 떨린다면 평균을 내세요
실물 ADC 값은 잡음으로 ±몇 칸씩 흔들립니다. 8번 읽어 평균을 내거나(`sum >> 3`), 이전 값과 섞는 지수 평균
`filtered = (filtered * 7 + v) / 8;` 을 쓰면 안정됩니다.
:::

## 예제 2 — 두 채널을 DMA 로 계속 받기

채널이 여러 개면 "시작 → 대기 → 읽기" 를 반복하기 번거롭습니다. **스캔 모드**로 여러 채널을 순서대로 변환하고,
**연속 변환 + 순환(Circular) DMA** 로 결과를 배열에 계속 덮어쓰게 하면, CPU 는 배열을 읽기만 하면 됩니다.

### CubeMX 설정

1. **ADC1 → IN0, IN1** 체크
2. Parameter Settings: **Scan Conversion Mode: Enabled**, **Continuous Conversion Mode: Enabled**, **DMA Continuous Requests: Enabled**
3. **Number Of Conversion: 2** — Rank 1 = Channel 0, Rank 2 = Channel 1 (Sampling Time 은 넉넉히, 예: 84 Cycles)
4. **DMA Settings → Add → ADC1**, Mode **Circular**, Data Width **Half Word**(16비트)

@sim[l09-dma] 두 채널 DMA 열기

@code[l09-dma] pv,u2,loop

- `adc_buf[0]` 에는 Rank 1(IN0 가변저항), `adc_buf[1]` 에는 Rank 2(IN1 CDS) 값이 **계속 갱신**됩니다.
- `HAL_ADC_Start_DMA` 의 두 번째 인자 형이 `uint32_t *` 라서 `(uint32_t *)adc_buf` 로 캐스트합니다. 실제 전송 단위는 DMA 설정의 Half Word 입니다.
- 메인 루프는 필요할 때 배열을 읽기만 합니다. 변환이 끝날 때마다 알림을 받고 싶으면 `HAL_ADC_ConvCpltCallback` 을 정의합니다.

:::warn 실물 CubeIDE: DMA 초기화 순서
일부 CubeMX 버전은 `main()` 에서 `MX_ADC1_Init()` 을 `MX_DMA_Init()` **보다 먼저** 부르도록 생성해, DMA 가 동작하지 않는 문제가 있었습니다.
배열이 계속 0 이면 `MX_DMA_Init();` 이 `MX_ADC1_Init();` 보다 위에 있는지 확인하고, CubeMX 의 *Project Manager → Advanced Settings* 에서 순서를 바꾸세요.
:::

### 채널을 바꿔 가며 폴링하기 (참고)

DMA 없이 채널을 바꿔 가며 읽으려면 `HAL_ADC_ConfigChannel()` 로 채널을 다시 설정한 뒤 변환합니다.

```c
ADC_ChannelConfTypeDef sConfig = {0};
sConfig.Channel = ADC_CHANNEL_1;
sConfig.Rank = 1;
sConfig.SamplingTime = ADC_SAMPLETIME_84CYCLES;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);    // 이제 Start/Poll/GetValue 는 IN1 을 읽음
```

1. 예제 1에서 가변저항 노드의 `value` 를 Properties 에서 0, 2048, 4095 로 바꾸며 출력 전압이 공식과 맞는지 확인하세요.
2. 예제 2의 CDS 노드 `lux` 를 바꿔 가며 값이 어느 방향으로 변하는지 기록하세요.
3. 예제 2에 "CDS 값이 기준보다 어두운 쪽이면 LD2 켜기" 를 추가하세요(자동 야간등). 기준값은 실습 2의 결과로 정합니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 항상 0 또는 4095 | 와이퍼가 아닌 끝 단자에 연결, 핀 채널 틀림 | 배선·핀아웃 채널 확인 |
| 값이 크게 흔들림 | 떠 있는 입력(연결 안 됨), 잡음 | 배선 확인, 평균 필터, 샘플링 시간 늘리기 |
| `HAL_ADC_PollForConversion` 이 `HAL_TIMEOUT` | `HAL_ADC_Start` 누락 | Start → Poll → GetValue 순서 |
| DMA 배열이 계속 0 | DMA 미설정, `MX_DMA_Init` 순서, DMA Continuous Requests 꺼짐 | 위 설정 1~4 와 초기화 순서 |
| 두 번째 채널이 갱신되지 않음 | Scan Conversion Mode 꺼짐, Number Of Conversion = 1 | 스캔 켜고 Rank 2 추가 |
| `%.2f` 자리에 아무것도 안 나옴 | 실수 printf 꺼짐 | `-u _printf_float` / `printfFloat`, 또는 mV 정수로 출력 |

## 과제

1. 가변저항 값으로 **서보 각도**(L08)를 0~180° 로 조절하세요.
2. 가변저항 값을 10단계로 나눠 LED 5개에 막대 그래프(레벨 미터)로 표시하세요.
3. 이동 평균(최근 16개)과 지수 평균의 반응 속도·잡음 제거 효과를 비교해 UART 로 출력해 보세요.
