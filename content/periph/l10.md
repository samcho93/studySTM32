## 학습 목표

- I2C 버스(SDA · SCL, 오픈드레인, 풀업, 7비트 주소, ACK)의 동작을 설명합니다.
- HAL 이 **7비트 주소를 왼쪽으로 1비트 민 값**(`0x27 << 1`)을 받는 이유를 압니다.
- PCF8574 I2C 백팩이 달린 LCD1602 를 **4비트 모드**로 초기화하고 글자를 쓰는 드라이버를 이해하고 사용합니다.
- I2C 스캐너로 연결된 장치를 찾고, `HAL_I2C_Mem_Read` 로 센서 레지스터를 읽습니다.

## I2C 기초

I2C 는 **SDA(데이터)** 와 **SCL(클럭)** 두 선으로 여러 장치를 연결하는 버스입니다. 마스터(STM32)가 클럭을 만들고,
장치마다 고유한 **7비트 주소**로 상대를 고릅니다.

- 두 선은 **오픈드레인** — 장치들은 선을 LOW 로 끌어내리기만 하고, HIGH 는 **풀업 저항**(보통 4.7 kΩ)이 만듭니다. 풀업이 없으면 통신이 안 됩니다.
- 한 번의 전송: **START → 주소(7비트) + R/W 비트 → ACK → 데이터 바이트 → ACK … → STOP**
- 장치가 자기 주소를 알아들으면 9번째 클럭에 SDA 를 LOW 로 당겨 **ACK** 를 보냅니다. 아무도 ACK 하지 않으면 HAL 함수는 `HAL_ERROR` 를 돌려줍니다.
- 속도: 표준 모드 100 kHz, 고속 모드 400 kHz

### HAL 주소 규칙: `<< 1`

주소 바이트는 **상위 7비트 = 주소, 최하위 1비트 = 읽기(1)/쓰기(0)** 입니다. HAL 함수는 이 바이트 모양 그대로(주소를 한 칸 민 값)를 받습니다.

```c
#define LCD_ADDR (0x27 << 1)     // 0x27 → 0x4E. HAL 이 R/W 비트를 알아서 채움
HAL_I2C_Master_Transmit(&hi2c1, LCD_ADDR, data, 2, 10);
```

`0x27` 을 그대로 넘기면 HAL 은 주소 `0x13` 에게 말을 거는 셈이 되어 응답이 없습니다. **I2C 오류의 절반은 이 실수**입니다.

## LCD1602 와 PCF8574 백팩

LCD1602(HD44780 호환)는 원래 데이터 8선 + 제어 3선이 필요합니다. 뒤에 붙은 **PCF8574 I2C 확장 칩**이 I2C 로 받은 1바이트를 8개 핀으로 내보내
LCD 를 대신 조작합니다. 흔한 백팩의 비트 배치는 다음과 같습니다.

@table[regmap]
| PCF8574 비트 | P7 | P6 | P5 | P4 | P3 | P2 | P1 | P0 |
|---|---|---|---|---|---|---|---|---|
| LCD 신호 | D7 | D6 | D5 | D4 | 백라이트 | EN | RW | RS |

- 데이터선이 4개(D4~D7)뿐이라 LCD 를 **4비트 모드**로 쓰고, 1바이트를 **상위 4비트 → 하위 4비트** 두 번에 나눠 보냅니다.
- **RS** = 0 이면 명령, 1 이면 글자 데이터. **RW** 는 항상 0(쓰기).
- LCD 는 **EN 이 1 → 0 으로 떨어질 때** 데이터선을 읽습니다. 그래서 같은 값을 EN=1, EN=0 두 번 연달아 보냅니다.
- 주소는 PCF8574 가 `0x27`, PCF8574**A** 가 `0x3F` 인 경우가 많습니다. 모르면 아래 스캐너로 찾으세요.

### 초기화 순서가 이런 이유

전원이 켜진 LCD 는 8비트 모드인지 4비트 모드인지 알 수 없습니다. 그래서 HD44780 데이터시트의 절차대로
`0x3` 을 세 번(8비트 모드로 확실히 맞춤) 보낸 뒤 `0x2` 로 4비트 모드에 들어가고, 그다음부터 명령을 두 번에 나눠 보냅니다.

| 명령 | 값 | 의미 |
|---|---|---|
| Function set | `0x28` | 4비트, 2줄, 5×8 글꼴 |
| Display off | `0x08` | 초기화 중 표시 끔 |
| Clear | `0x01` | 화면 지움 (1.52 ms 걸림 → 2 ms 대기) |
| Entry mode | `0x06` | 글자를 쓰면 커서가 오른쪽으로 |
| Display on | `0x0C` | 표시 켬, 커서·깜빡임 끔 |
| Set DDRAM addr | `0x80 \| addr` | 커서 위치. 1행 = `0x00`~, 2행 = `0x40`~ |

## 예제 2 — I2C 스캐너와 레지스터 읽기

주소를 모를 때는 1 ~ 127 모든 주소에 `HAL_I2C_IsDeviceReady` 를 보내 ACK 하는 주소를 찾습니다.
예제 회로에는 LCD(0x27)와 LM75 형 온도센서를 흉내 낸 범용 I2C 장치(0x48)가 연결되어 있습니다.

@sim[l10-scan] I2C 스캐너 열기

@code[l10-scan] u2,loop

`HAL_I2C_Mem_Read` 는 "레지스터 주소를 쓰고(START) → 다시 START → 데이터 읽기" 를 한 번에 해 주는 함수입니다.

```c
HAL_I2C_Mem_Read(&hi2c1, 장치주소 << 1, 레지스터주소, I2C_MEMADD_SIZE_8BIT, 버퍼, 길이, 타임아웃);
```

LM75 의 0번 레지스터는 온도를 2바이트로 담고, 상위 9비트가 0.5 °C 단위 온도입니다. `0x19 0x80` → `0x1980 >> 7 = 51` → 51 × 0.5 = **25.5 °C**.
시뮬레이터 장치의 `regs` 속성을 바꾸면 읽히는 값이 바뀝니다.

## 자주 나는 오류와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `HAL_ERROR`, 아무것도 표시 안 됨 | 주소를 `<< 1` 하지 않음, 주소가 0x3F, 배선(SDA↔SCL 바뀜) | 스캐너로 주소 확인, `(addr << 1)` |
| 백라이트만 켜지고 글자 없음 / 네모 칸만 | 대비(contrast) 가변저항 조정 필요, 초기화 순서·지연 부족 | 백팩 뒤 파란 가변저항 돌리기, `lcd_init` 지연 확인 |
| 이상한 글자가 섞여 나옴 | 4비트 순서 착오(하위 먼저 보냄), EN 펄스 없음 | 상위 → 하위 순서, EN=1 → EN=0 두 번 보내기 |
| 한동안 되다가 `HAL_BUSY` 로 멈춤 | 전송 중 리셋되어 장치가 SDA 를 잡고 있음 | 전원 껐다 켜기, 긴 배선 줄이기 |
| 스캐너가 모든 주소에서 응답 | 풀업 없음·배선 단락 등으로 SDA 가 항상 LOW | 풀업 저항과 배선 확인 |
