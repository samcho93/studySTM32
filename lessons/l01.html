L01STM32 시리즈와 개발 환경

Cortex-M 코어와 F0·F1·F4·L4·H7 제품군, CubeIDE·CubeMX, HAL·LL·레지스터의 차이, Nucleo와 BluePill 보드를 정리합니다.

HAL 레퍼런스

학습 목표#

  • STM32가 Arm Cortex-M 코어 + ST의 주변장치로 이루어진 MCU 제품군이라는 것을 설명할 수 있습니다.
  • F0 · F1 · F4 · L4 · H7 제품군의 차이(코어, 클럭, 용도)를 표로 비교하고, 칩 이름(STM32F411RET6)을 읽을 수 있습니다.
  • STM32CubeMX · STM32CubeIDE가 각각 무엇을 하는지, HAL · LL · 레지스터 방식이 어떻게 다른지 말할 수 있습니다.
  • 이 강좌에서 쓰는 보드(NUCLEO-F411RE, NUCLEO-F103RB, BluePill)의 내장 LED·버튼·가상 COM 포트를 알고 있습니다.

STM32는 무엇인가#

STM32는 ST마이크로일렉트로닉스(ST)가 만드는 32비트 마이크로컨트롤러(MCU) 제품군입니다. CPU 코어는 Arm이 설계한 Cortex-M 시리즈를 라이선스해 쓰고, 그 둘레에 ST가 만든 GPIO · 타이머 · UART · ADC · I2C · SPI 같은 주변장치(peripheral), 플래시 메모리, SRAM, 클럭 회로를 붙여 한 칩으로 만듭니다.

코어특징주로 쓰는 STM32
Cortex-M0 / M0+가장 작고 저렴, 저전력F0, G0, L0, C0
Cortex-M332비트 기본형, 하드웨어 나눗셈F1, F2, L1
Cortex-M4FM3 + DSP 명령 + 단정밀도 FPUF3, F4, G4, L4, WB
Cortex-M7고성능, 캐시, (일부) 배정밀도 FPUF7, H7
Cortex-M33M4급 성능 + TrustZone 보안L5, U5, H5

같은 Cortex-M이라도 주변장치의 레지스터 구조는 ST가 정한 것이라서, STM32끼리는 제품군이 달라도 코드가 비슷합니다. 그리고 ST가 제공하는 HAL 라이브러리가 이 차이를 한 번 더 감춰 주기 때문에, F1에서 쓰던 코드를 F4로 옮기기가 쉽습니다.

제품군 비교#

제품군코어최대 클럭특징대표 칩 · 보드
F0M048 MHz저가형 입문 제품군STM32F030, NUCLEO-F030R8
F1M372 MHz가장 오래되고 자료가 많은 주력 제품군STM32F103C8(BluePill), NUCLEO-F103RB
F4M4F84~180 MHzFPU·DSP, 교육·산업에서 가장 흔한 고성능 범용STM32F401/F411(최대 100 MHz), F446(180 MHz)
L4M4F80 MHz초저전력(배터리 기기), 고성능 ADCSTM32L476, NUCLEO-L476RG
H7M7 (일부 M7+M4 듀얼)480~550 MHz최고 성능, 대용량 메모리, 캐시STM32H743, NUCLEO-H743ZI

이 밖에 G0/G4(F0/F3 후속), U5(초저전력 + 보안), WB/WL(블루투스·LoRa 무선) 등이 있습니다. 처음 배울 때는 F4(특히 F411/F401) 또는 F1 중 하나로 시작하면 자료를 찾기 쉽습니다.

칩 이름 읽기#

STM32F411RET6 을 한 글자씩 나눠 보면 칩의 사양이 보입니다.

부분값뜻
STM32—ST의 32비트 Arm MCU
F제품 종류F = 범용(Foundation/Mainstream), L = 저전력, H = 고성능, G = 차세대 범용
4시리즈F4 시리즈 (Cortex-M4F)
11라인F411 라인 (최대 100 MHz)
R핀 수C = 48핀, R = 64핀, V = 100핀, Z = 144핀
E플래시 크기8 = 64 KB, B = 128 KB, C = 256 KB, E = 512 KB
T패키지T = LQFP, U = QFN, H = BGA
6온도 범위6 = −40~85 °C, 7 = −40~105 °C

그래서 BluePill의 STM32F103C8T6 은 "F1 시리즈 103 라인, 48핀, 64 KB 플래시, LQFP, 산업용 온도" 입니다.

개발 도구: CubeMX와 CubeIDE#

도구하는 일이 강좌에서
STM32CubeMX칩 그림에서 핀 기능을 고르고(핀아웃), 클럭 트리와 주변장치(UART 보레이트, 타이머 분주 …)를 설정한 뒤 초기화 C 코드를 생성. 설정은 .ioc 파일에 저장시뮬레이터의 핀아웃·설정 탭이 같은 역할
STM32CubeIDEEclipse 기반 통합 개발 환경. GCC 컴파일러, 빌드, ST-Link로 플래시·디버그(중단점, 변수 보기)시뮬레이터의 코드 탭과 빌드·실행 버튼, 실물은 L16
STM32CubeProgrammer이미 만든 .hex/.bin/.elf 를 보드에 쓰거나 지우기, 옵션 바이트 설정L16에서 참고
버전에 따라 설치 방식이 다릅니다

CubeIDE 1.x는 .ioc 를 IDE 안에서 바로 열어 CubeMX 화면을 씁니다. 최근 2.x 버전부터는 CubeMX를 별도 프로그램으로 설치해 코드를 생성하고, CubeIDE는 편집·빌드·디버그에 집중하도록 바뀌었습니다. 어느 쪽이든 "CubeMX에서 설정 → 코드 생성 → IDE에서 USER CODE 작성 → 빌드·플래시" 흐름은 같습니다.

Keil MDK, IAR EWARM 같은 상용 IDE나 VS Code + CMake 조합도 쓰이지만, 이 강좌는 무료이고 ST가 직접 지원하는 CubeIDE를 기준으로 합니다.

HAL · LL · 레지스터#

STM32 코드를 쓰는 방법은 크게 세 가지입니다. 같은 일 — PA5 핀(LD2)을 반전 — 을 세 방식으로 써 보면 차이가 보입니다.

c
/* 1) 레지스터 직접 접근: 데이터시트의 레지스터 비트를 그대로 씀 */
GPIOA->ODR ^= (1 << 5);

/* 2) LL (Low-Layer) 드라이버: 레지스터를 얇게 감싼 인라인 함수 (시뮬레이터 미지원) */
LL_GPIO_TogglePin(GPIOA, LL_GPIO_PIN_5);

/* 3) HAL (Hardware Abstraction Layer): 제품군이 달라도 같은 이름·같은 사용법 */
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
방식장점단점
레지스터가장 빠르고 작음, 동작 원리를 정확히 이해레퍼런스 매뉴얼을 계속 봐야 함, 제품군마다 다를 수 있음
LL레지스터에 가까운 속도, 이름이 읽기 쉬움초기화 코드가 길고 제품군 차이가 조금 드러남
HALCubeMX가 초기화 코드를 만들어 줌, 인터럽트·DMA 처리까지 포함, 제품군 간 이식 쉬움코드 크기가 크고 호출 오버헤드가 있음

이 강좌는 HAL을 기본으로 하고, 필요한 곳(L03 BSRR, L12 FND)에서 레지스터 직접 접근을 함께 보여 줍니다. 시뮬레이터가 지원하는 HAL 함수 목록은 HAL 레퍼런스에 정리되어 있습니다.

이 강좌의 보드#

보드MCU클럭(기본)내장 장치연결
NUCLEO-F411RESTM32F411RET6 (M4F)84 MHzLD2 = PA5, B1 = PC13(누르면 LOW), VCP = USART2(PA2 TX / PA3 RX)USB 하나로 전원 + ST-Link 디버거 + 가상 COM
NUCLEO-F103RBSTM32F103RBT6 (M3)72 MHz위와 같은 배치위와 같음
BluePillSTM32F103C8T6 (M3)72 MHzLED = PC13 (LOW일 때 켜짐)별도 ST-Link(SWD) 필요, USB는 전원/USB 장치용

Nucleo-64 보드는 윗부분에 ST-Link가 내장되어 있어 USB 케이블 하나로 전원, 프로그램 쓰기, 디버그, 시리얼 통신(가상 COM 포트)이 모두 됩니다. 아두이노 우노와 같은 모양의 헤더(A0~A5, D0~D15)와 모든 핀이 나오는 모포(morpho) 헤더가 있어 브레드보드 실습에 편합니다. 그래서 이 강좌의 예제는 대부분 NUCLEO-F411RE를 기준으로 합니다.

BluePill 구입 시 주의

값싼 BluePill 중에는 STM32가 아닌 호환 칩(CKS32, CS32 등)이 달린 제품이 있습니다. CubeIDE가 "ST 정품이 아닌 장치"라며 디버그를 거부하거나 동작이 조금 다를 수 있으니, 수업용으로는 Nucleo 보드를 권합니다.

이 강좌의 학습 흐름#

  1. CubeMX 핀 설정 — 시뮬레이터의 핀아웃·설정 탭에서 핀 기능과 주변장치를 정합니다.
  2. HAL 코드 — 생성된 main.c 의 USER CODE 구역에 코드를 씁니다.
  3. 시뮬레이터 — 회로 노드(LED, 버튼, LCD, 모터 …)를 연결하고 빌드·실행해 결과를 확인합니다.
  4. 실물 보드 — 같은 .ioc 설정과 같은 코드를 STM32CubeIDE로 옮겨 Nucleo 보드에서 실행합니다(L16).

자주 나는 오류와 해결#

증상원인해결
CubeIDE에서 보드를 골랐는데 칩 이름이 다름Board Selector 대신 MCU Selector에서 비슷한 칩을 고름새 프로젝트를 Board Selector → NUCLEO-F411RE 로 다시 만들기 (LD2·B1·USART2가 자동 설정됨)
PC에서 보드가 인식되지 않음 (No ST-LINK detected)충전 전용 USB 케이블, ST-Link 드라이버 미설치데이터 케이블로 교체, CubeIDE/CubeProgrammer 설치 시 ST-Link 드라이버 포함 여부 확인
BluePill이 디버거에 연결되지 않음정품이 아닌 호환 칩, SWD 배선 오류, 3.3V 미공급SWDIO·SWCLK·GND·3.3V 네 선 확인, 가능하면 Nucleo로 실습
인터넷 예제 코드가 컴파일되지 않음다른 제품군(F1 ↔ F4) 헤더·클럭 설정 차이, LL/레지스터 코드 혼용예제가 어느 보드·HAL 기준인지 확인하고 CubeMX 설정부터 맞추기

과제#

  1. 여러분이 가진(또는 사고 싶은) STM32 보드의 칩 이름을 적고, 위의 "칩 이름 읽기" 표로 사양을 풀어 쓰세요.
  2. NUCLEO-F411RE 의 LD2, B1, 가상 COM 포트가 연결된 핀을 외우고, 왜 PA5를 다른 용도로 쓰면 LED가 같이 반응하는지 설명하세요.
  3. HAL · LL · 레지스터 방식을 쓰기 쉬움 / 실행 속도 / 이식성 기준으로 비교한 표를 직접 만들어 보세요.
