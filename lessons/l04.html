L04GPIO 입력 — 스위치

풀업·풀다운과 active-low 버튼, 폴링으로 읽기, 에지 검출과 디바운스를 다룹니다.

선수 레슨: L03
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • 입력 핀이 떠 있는(floating) 상태가 왜 위험한지 알고, 풀업·풀다운 저항으로 기본 레벨을 정할 수 있습니다.
  • active-low 버튼(누르면 LOW)을 HAL_GPIO_ReadPin 으로 읽고 LED에 반영합니다.
  • 버튼의 채터링(바운스) 을 이해하고, 에지 검출 + 디바운스로 "누를 때마다 한 번" 동작하게 만듭니다.

입력 핀과 풀업·풀다운#

버튼 한쪽을 핀에, 다른 쪽을 GND에 연결했다고 해 봅시다. 누르면 핀이 0 V(LOW)가 되지만, 떼었을 때는 핀이 어디에도 연결되지 않은 상태입니다. 이렇게 떠 있는 입력은 주변 잡음과 손의 정전기에 따라 0과 1을 멋대로 오갑니다. 그래서 저항으로 기본값을 정해 줍니다.

배선저항평소누르면CubeMX 설정
버튼 → GND핀 ↔ 3.3V 풀업HIGH (1)LOW (0) — active-lowGPIO Pull-up
버튼 → 3.3V핀 ↔ GND 풀다운LOW (0)HIGH (1) — active-highGPIO Pull-down

STM32는 핀마다 약 40 kΩ 정도의 내부 풀업·풀다운 저항을 켤 수 있어서 외부 저항 없이도 됩니다. 긴 배선이나 잡음이 많은 환경에서는 4.7~10 kΩ 외부 저항을 쓰는 편이 안정적입니다.

Nucleo 의 B1 버튼

NUCLEO-F411RE 의 파란 버튼 B1(PC13)은 보드에 외부 풀업 저항이 달려 있고 버튼이 GND 쪽으로 연결되어 있습니다. 그래서 CubeMX에서 풀업을 켜지 않아도(No pull) 평소 HIGH, 누르면 LOW 입니다.

시뮬레이터의 버튼 노드는 Properties 의 wiring 속성으로 세 가지 배선을 흉내 냅니다.

wiring의미핀 설정
gnd버튼이 GND 쪽 — 누르면 LOWPull-up 필요 (없으면 떠 있는 입력)
vcc버튼이 3.3V 쪽 — 누르면 HIGHPull-down 필요
module풀업이 내장된 버튼 모듈 — 평소 HIGH, 누르면 LOW설정 없어도 됨

HAL로 읽기#

c
GPIO_PinState HAL_GPIO_ReadPin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);

반환값은 GPIO_PIN_SET(1) 또는 GPIO_PIN_RESET(0) 입니다. 내부적으로는 GPIOx->IDR 의 해당 비트를 읽습니다.

예제 1 — 누르는 동안 LED 켜기#

B1 을 계속 확인(폴링)하다가 LOW 이면 LD2 를 켭니다.

시뮬레이터에서 열기버튼 → LED 열기새 창l04-button
cCore/Src/main.c
  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_RESET) {   // 눌림 (active-low)
      HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_SET);
    } else {
      HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);
    }
    HAL_Delay(10);
  }
  /* USER CODE END 3 */

== GPIO_PIN_RESET 으로 비교한 이유는 B1 이 active-low 이기 때문입니다. if (HAL_GPIO_ReadPin(...)) 처럼 쓰면 "누르지 않았을 때" 참이 되어 반대로 동작합니다.

채터링과 디바운스#

기계식 버튼은 접점이 붙는 순간 수 ms 동안 여러 번 붙었다 떨어졌다 합니다(바운스). MCU는 이 짧은 떨림을 모두 읽을 만큼 빠르기 때문에, "누를 때마다 LED 토글" 을 단순하게 만들면 한 번 눌렀는데 여러 번 토글되어 결과가 랜덤해 보입니다.

text
버튼 전압 (누르는 순간)
HIGH ─────┐ ┌┐ ┌─┐
          │ ││ │ │
LOW       └─┘└─┘ └──────────────  ← 약 1~10 ms 떨린 뒤 안정

대표적인 해결 방법은 세 가지입니다.

  1. 지연 후 재확인 — 변화를 감지하면 20 ms 쯤 기다렸다가 다시 읽어 같으면 인정 (아래 예제)
  2. 시간 비교 — 마지막으로 인정한 시각에서 일정 시간(예: 200 ms) 안의 변화는 무시 (L05 인터럽트 예제)
  3. 하드웨어 — RC 필터(저항 + 커패시터)나 슈미트 트리거로 전기적으로 떨림을 줄임

예제 2 — 누를 때마다 토글 (에지 검출 + 디바운스)#

외부 버튼을 PB4 에 연결하고 내부 풀업을 켭니다. "누르고 있는 상태" 가 아니라 HIGH → LOW 로 바뀌는 순간(하강 에지) 만 잡습니다.

핀모드라벨연결
PB4GPIO_Input, Pull-upBTN버튼 → GND (Nucleo D5)
PA6GPIO_OutputLED초록 LED → 저항 → GND (D12)
시뮬레이터에서 열기토글 버튼 열기새 창l04-toggle
cCore/Src/main.c
/* USER CODE BEGIN PV */
uint8_t led_on = 0;          // LED 상태 (0: 꺼짐, 1: 켜짐)
uint8_t last_state = 1;      // 직전에 읽은 버튼 값 (풀업이므로 평소 1)
uint32_t press_count = 0;    // 눌린 횟수
/* USER CODE END PV */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    uint8_t now = HAL_GPIO_ReadPin(BTN_GPIO_Port, BTN_Pin);
    if (last_state == 1 && now == 0) {          // HIGH -> LOW : 눌린 순간(하강 에지)
      HAL_Delay(20);                            // 디바운스: 20 ms 뒤에 다시 확인
      if (HAL_GPIO_ReadPin(BTN_GPIO_Port, BTN_Pin) == GPIO_PIN_RESET) {
        led_on = !led_on;
        press_count++;
        HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, led_on ? GPIO_PIN_SET : GPIO_PIN_RESET);
      }
    }
    last_state = now;
  }
  /* USER CODE END 3 */
  • last_state 에 직전 값을 저장해 두고 이번 값과 비교하면 에지를 알 수 있습니다: 직전 1, 지금 0 → 눌린 순간.
  • 20 ms 뒤 다시 읽어 여전히 LOW 일 때만 인정합니다.
  • press_count 는 시뮬레이터의 변수 보기(Live Expressions)에서 눌린 횟수를 확인하는 용도입니다.
실습
  1. 예제 2에서 디바운스 두 줄(HAL_Delay(20) 과 재확인 if)을 지우고 버튼 노드를 여러 번 눌러 보세요. 버튼 노드 Properties 의 채터링 시뮬레이션 옵션을 켜면 실물처럼 튀는 신호가 나옵니다. 옵션을 켰을 때와 껐을 때 press_count 를 비교하세요.
  2. PB4 의 풀업을 끄고(No pull) 실행하면 어떻게 되나요? 버튼 노드의 wiring 을 module 로 바꾸면요?
  3. 버튼을 1초 이상 길게 누르면 LED가 빠르게 깜빡이는 모드로 바뀌도록 확장하세요. (힌트: 눌린 시각을 HAL_GetTick() 으로 저장)
스스로 확인
  • 풀업 저항이 켜진 입력에 버튼을 3.3V 쪽으로 연결하면 어떤 문제가 생기나요?
  • 예제 2의 last_state = now; 를 if 블록 안에 넣으면 무엇이 달라지나요?

자주 나는 오류와 해결#

증상원인해결
버튼을 안 눌러도 값이 제멋대로 바뀜떠 있는 입력(풀업/풀다운 없음)CubeMX에서 Pull-up 또는 Pull-down, 배선 방향과 맞추기
버튼 동작이 반대active-low 인데 SET 을 "눌림" 으로 판단== GPIO_PIN_RESET 으로 비교
한 번 눌렀는데 여러 번 토글채터링지연 재확인 또는 시간 비교 디바운스
버튼 반응이 늦음 / 가끔 놓침루프 안에 긴 HAL_Delay 가 있어 폴링 간격이 김긴 지연 없애기, 또는 EXTI 인터럽트(L05)
누르면 보드가 리셋됨(실물)버튼을 3.3V–GND 사이에 직접 연결(단락)버튼은 반드시 핀과 GND(또는 3.3V) 사이에

과제#

  1. 버튼 두 개(PB4: +1, PB5: −1)로 0~7 값을 조절하고, LED 세 개에 이진수로 표시하세요.
  2. 디바운스 방법 1(지연 재확인)과 2(시간 비교)의 장단점을 비교하세요. 어떤 방법이 메인 루프를 멈추나요?
  3. 풀업 저항 값이 너무 크거나(1 MΩ) 너무 작을 때(100 Ω) 각각 생기는 문제를 조사하세요.
