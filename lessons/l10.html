L10I2C와 LCD1602

I2C 주소와 HAL의 8비트 주소 규칙, PCF8574 4비트 LCD 프로토콜, 완성 드라이버와 I2C 스캐너를 만듭니다.

선수 레슨: L06
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • I2C 버스(SDA · SCL, 오픈드레인, 풀업, 7비트 주소, ACK)의 동작을 설명합니다.
  • HAL 이 7비트 주소를 왼쪽으로 1비트 민 값(0x27 << 1)을 받는 이유를 압니다.
  • PCF8574 I2C 백팩이 달린 LCD1602 를 4비트 모드로 초기화하고 글자를 쓰는 드라이버를 이해하고 사용합니다.
  • I2C 스캐너로 연결된 장치를 찾고, HAL_I2C_Mem_Read 로 센서 레지스터를 읽습니다.

I2C 기초#

I2C 는 SDA(데이터) 와 SCL(클럭) 두 선으로 여러 장치를 연결하는 버스입니다. 마스터(STM32)가 클럭을 만들고, 장치마다 고유한 7비트 주소로 상대를 고릅니다.

  • 두 선은 오픈드레인 — 장치들은 선을 LOW 로 끌어내리기만 하고, HIGH 는 풀업 저항(보통 4.7 kΩ)이 만듭니다. 풀업이 없으면 통신이 안 됩니다.
  • 한 번의 전송: START → 주소(7비트) + R/W 비트 → ACK → 데이터 바이트 → ACK … → STOP
  • 장치가 자기 주소를 알아들으면 9번째 클럭에 SDA 를 LOW 로 당겨 ACK 를 보냅니다. 아무도 ACK 하지 않으면 HAL 함수는 HAL_ERROR 를 돌려줍니다.
  • 속도: 표준 모드 100 kHz, 고속 모드 400 kHz

HAL 주소 규칙: << 1#

주소 바이트는 상위 7비트 = 주소, 최하위 1비트 = 읽기(1)/쓰기(0) 입니다. HAL 함수는 이 바이트 모양 그대로(주소를 한 칸 민 값)를 받습니다.

c
#define LCD_ADDR (0x27 << 1)     // 0x27 → 0x4E. HAL 이 R/W 비트를 알아서 채움
HAL_I2C_Master_Transmit(&hi2c1, LCD_ADDR, data, 2, 10);

0x27 을 그대로 넘기면 HAL 은 주소 0x13 에게 말을 거는 셈이 되어 응답이 없습니다. I2C 오류의 절반은 이 실수입니다.

LCD1602 와 PCF8574 백팩#

LCD1602(HD44780 호환)는 원래 데이터 8선 + 제어 3선이 필요합니다. 뒤에 붙은 PCF8574 I2C 확장 칩이 I2C 로 받은 1바이트를 8개 핀으로 내보내 LCD 를 대신 조작합니다. 흔한 백팩의 비트 배치는 다음과 같습니다.

PCF8574 비트P7P6P5P4P3P2P1P0
LCD 신호D7D6D5D4백라이트ENRWRS
  • 데이터선이 4개(D4~D7)뿐이라 LCD 를 4비트 모드로 쓰고, 1바이트를 상위 4비트 → 하위 4비트 두 번에 나눠 보냅니다.
  • RS = 0 이면 명령, 1 이면 글자 데이터. RW 는 항상 0(쓰기).
  • LCD 는 EN 이 1 → 0 으로 떨어질 때 데이터선을 읽습니다. 그래서 같은 값을 EN=1, EN=0 두 번 연달아 보냅니다.
  • 주소는 PCF8574 가 0x27, PCF8574A 가 0x3F 인 경우가 많습니다. 모르면 아래 스캐너로 찾으세요.

드라이버 코드#

USER CODE BEGIN 0 에 들어가는 완성 드라이버입니다. 함수는 lcd_init, lcd_set_cursor(행, 열), lcd_print(문자열) 세 개만 쓰면 됩니다.

cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* ---- I2C LCD1602 (PCF8574 백팩) 드라이버 ----
 * PCF8574 비트: P0=RS, P1=RW, P2=EN, P3=백라이트, P4~P7=D4~D7 (4비트 모드) */
#define LCD_ADDR  (0x27 << 1)   // HAL 은 7비트 주소를 왼쪽으로 1비트 민 값을 받습니다
#define LCD_RS    0x01
#define LCD_EN    0x04
#define LCD_BL    0x08

/* 상위 4비트(nibble)를 EN 펄스와 함께 보냅니다. */
void lcd_send4(uint8_t nibble, uint8_t rs)
{
  uint8_t data[2];
  data[0] = nibble | LCD_BL | LCD_EN | rs;   // EN = 1
  data[1] = nibble | LCD_BL | rs;            // EN = 0 (하강 에지에서 LCD 가 읽음)
  HAL_I2C_Master_Transmit(&hi2c1, LCD_ADDR, data, 2, 10);
}

/* 8비트 값을 상위 -> 하위 4비트 순서로 두 번 나눠 보냅니다. */
void lcd_send(uint8_t value, uint8_t rs)
{
  lcd_send4(value & 0xF0, rs);
  lcd_send4((value << 4) & 0xF0, rs);
}

void lcd_cmd(uint8_t cmd)
{
  lcd_send(cmd, 0);
  if (cmd == 0x01 || cmd == 0x02) HAL_Delay(2);   // Clear / Home 은 1.5 ms 이상 걸림
}

void lcd_data(uint8_t ch)
{
  lcd_send(ch, LCD_RS);
}

void lcd_init(void)
{
  HAL_Delay(50);                 // 전원 인가 후 안정화
  lcd_send4(0x30, 0); HAL_Delay(5);
  lcd_send4(0x30, 0); HAL_Delay(1);
  lcd_send4(0x30, 0); HAL_Delay(1);
  lcd_send4(0x20, 0); HAL_Delay(1);   // 4비트 모드로 전환
  lcd_cmd(0x28);                 // 4비트, 2줄, 5x8 글꼴
  lcd_cmd(0x08);                 // 표시 끔
  lcd_cmd(0x01);                 // 화면 지우기
  lcd_cmd(0x06);                 // 글자 쓰면 커서 오른쪽으로
  lcd_cmd(0x0C);                 // 표시 켬, 커서 숨김
}

void lcd_set_cursor(uint8_t row, uint8_t col)
{
  uint8_t addr = (row == 0 ? 0x00 : 0x40) + col;   // 1행 DDRAM 0x00, 2행 0x40
  lcd_cmd(0x80 | addr);
}

void lcd_print(const char *s)
{
  while (*s) {
    lcd_data((uint8_t)*s++);
  }
}
/* USER CODE END 0 */

초기화 순서가 이런 이유#

전원이 켜진 LCD 는 8비트 모드인지 4비트 모드인지 알 수 없습니다. 그래서 HD44780 데이터시트의 절차대로 0x3 을 세 번(8비트 모드로 확실히 맞춤) 보낸 뒤 0x2 로 4비트 모드에 들어가고, 그다음부터 명령을 두 번에 나눠 보냅니다.

명령값의미
Function set0x284비트, 2줄, 5×8 글꼴
Display off0x08초기화 중 표시 끔
Clear0x01화면 지움 (1.52 ms 걸림 → 2 ms 대기)
Entry mode0x06글자를 쓰면 커서가 오른쪽으로
Display on0x0C표시 켬, 커서·깜빡임 끔
Set DDRAM addr0x80 | addr커서 위치. 1행 = 0x00~, 2행 = 0x40~

예제 1 — Hello + 카운터#

시뮬레이터에서 열기LCD 카운터 열기새 창l10-lcd
cCore/Src/main.c
/* USER CODE BEGIN PV */
uint32_t count = 0;
char buf[17];               // LCD 한 줄 16글자 + '\0'
/* USER CODE END PV */

  /* USER CODE BEGIN 2 */
  if (HAL_I2C_IsDeviceReady(&hi2c1, LCD_ADDR, 3, 100) != HAL_OK) {
    HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_SET);   // LCD 응답 없음 -> LD2 켜서 알림
  }
  lcd_init();
  lcd_set_cursor(0, 0);
  lcd_print("Hello, STM32!");
  /* USER CODE END 2 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    sprintf(buf, "Count: %-9lu", count++);   // 16칸을 꽉 채워 이전 글자를 덮어씀
    lcd_set_cursor(1, 0);
    lcd_print(buf);
    HAL_Delay(1000);
  }
  /* USER CODE END 3 */
  • HAL_I2C_IsDeviceReady 로 먼저 LCD 가 응답하는지 확인하고, 없으면 LD2 를 켜 알립니다.
  • "Count: %-9lu" 는 7글자 + 왼쪽 정렬 9칸 = 16글자를 꽉 채워 이전에 있던 긴 숫자의 잔상을 덮어씁니다.

LCD 는 lcd_cmd(0x01)(Clear)로 지우는 것보다 덮어쓰는 편이 빠르고 깜빡임이 없습니다.

예제 2 — I2C 스캐너와 레지스터 읽기#

주소를 모를 때는 1 ~ 127 모든 주소에 HAL_I2C_IsDeviceReady 를 보내 ACK 하는 주소를 찾습니다. 예제 회로에는 LCD(0x27)와 LM75 형 온도센서를 흉내 낸 범용 I2C 장치(0x48)가 연결되어 있습니다.

시뮬레이터에서 열기I2C 스캐너 열기새 창l10-scan
cCore/Src/main.c
  /* USER CODE BEGIN 2 */
  printf("\r\nI2C scan...\r\n");
  for (uint16_t addr = 1; addr < 128; addr++) {
    if (HAL_I2C_IsDeviceReady(&hi2c1, addr << 1, 1, 10) == HAL_OK) {
      printf("  found device at 0x%02X\r\n", addr);
    }
  }
  printf("scan done.\r\n");
  /* USER CODE END 2 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (HAL_I2C_Mem_Read(&hi2c1, 0x48 << 1, 0x00, I2C_MEMADD_SIZE_8BIT, reg, 2, 100) == HAL_OK) {
      int16_t raw = (int16_t)((reg[0] << 8) | reg[1]);
      int t10 = (raw >> 7) * 5;             // 0.5 도 단위 -> 0.1 도 단위 (양수 온도 기준)
      printf("temp = %d.%d C  (raw 0x%02X 0x%02X)\r\n", t10 / 10, t10 % 10, reg[0], reg[1]);
    } else {
      printf("0x48 no response\r\n");
    }
    HAL_Delay(1000);
  }
  /* USER CODE END 3 */

HAL_I2C_Mem_Read 는 "레지스터 주소를 쓰고(START) → 다시 START → 데이터 읽기" 를 한 번에 해 주는 함수입니다.

c
HAL_I2C_Mem_Read(&hi2c1, 장치주소 << 1, 레지스터주소, I2C_MEMADD_SIZE_8BIT, 버퍼, 길이, 타임아웃);

LM75 의 0번 레지스터는 온도를 2바이트로 담고, 상위 9비트가 0.5 °C 단위 온도입니다. 0x19 0x80 → 0x1980 >> 7 = 51 → 51 × 0.5 = 25.5 °C. 시뮬레이터 장치의 regs 속성을 바꾸면 읽히는 값이 바뀝니다.

자주 나는 오류와 해결#

증상원인해결
HAL_ERROR, 아무것도 표시 안 됨주소를 << 1 하지 않음, 주소가 0x3F, 배선(SDA↔SCL 바뀜)스캐너로 주소 확인, (addr << 1)
백라이트만 켜지고 글자 없음 / 네모 칸만대비(contrast) 가변저항 조정 필요, 초기화 순서·지연 부족백팩 뒤 파란 가변저항 돌리기, lcd_init 지연 확인
이상한 글자가 섞여 나옴4비트 순서 착오(하위 먼저 보냄), EN 펄스 없음상위 → 하위 순서, EN=1 → EN=0 두 번 보내기
한동안 되다가 HAL_BUSY 로 멈춤전송 중 리셋되어 장치가 SDA 를 잡고 있음전원 껐다 켜기, 긴 배선 줄이기
스캐너가 모든 주소에서 응답풀업 없음·배선 단락 등으로 SDA 가 항상 LOW풀업 저항과 배선 확인
