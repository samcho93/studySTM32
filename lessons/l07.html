L07타이머 인터럽트

타이머 클럭·PSC·ARR 계산 공식을 84 MHz·72 MHz 예로 익히고, HAL_TIM_PeriodElapsedCallback으로 정확한 주기 작업을 만듭니다.

선수 레슨: L06
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • 타이머의 구조(클럭 → 프리스케일러 PSC → 카운터 CNT → 자동 재장전 ARR)를 이해합니다.
  • 업데이트 주파수 공식 으로 원하는 주기의 PSC · ARR 값을 84 MHz(F411)와 72 MHz(F103) 기준으로 계산합니다.
  • HAL_TIM_Base_Start_IT 와 HAL_TIM_PeriodElapsedCallback 으로 정확한 주기 작업을 만듭니다.
  • HAL_Delay · HAL_GetTick 비교 · 타이머 인터럽트의 쓰임새를 구분합니다.

타이머의 구조#

범용 타이머는 입력 클럭을 PSC+1 로 나눈 속도로 CNT 를 1씩 올리고, CNT 가 ARR 에 도달하면 0으로 돌아가며 "업데이트 이벤트" 를 냅니다. 업데이트 이벤트에서 인터럽트를 켜 두면 그 순간마다 콜백이 불립니다.

text
 타이머 클럭 ──► [ PSC 분주기 (÷ PSC+1) ] ──► CNT: 0,1,2,…,ARR,0,1,… ──► ARR 도달 = 업데이트 이벤트 ──► 인터럽트
   84 MHz              PSC = 83                1 MHz 로 증가              ARR = 999 → 1 ms 마다

업데이트 주파수 = 타이머 클럭 / ((PSC + 1) × (ARR + 1))

PSC 와 ARR 은 0부터 세기 때문에 +1 이 붙습니다. "8400 으로 나누고 싶다" 면 PSC 에는 8399 를 넣습니다.

타이머 클럭은 얼마인가#

타이머는 APB 버스 클럭을 받는데, APB 분주비가 1이 아니면 타이머 클럭은 APB 클럭의 2배 입니다(클럭 트리 규칙).

보드SYSCLKAPB1 (TIM2~5)APB2 (TIM1, TIM9~11)타이머 클럭
NUCLEO-F411RE (이 강좌 기본)84 MHz42 MHz (÷2)84 MHz (÷1)모두 84 MHz
NUCLEO-F103RB / BluePill72 MHz36 MHz (÷2)72 MHz (÷1)모두 72 MHz

자주 쓰는 값#

목표84 MHz (F411) PSC / ARR72 MHz (F103) PSC / ARR카운터 1틱
1 Hz (1 s)8399 / 99997199 / 9999100 µs
10 Hz (100 ms)8399 / 9997199 / 999100 µs
1 kHz (1 ms)83 / 99971 / 9991 µs
50 Hz (서보, L08)83 / 1999971 / 199991 µs
20 kHz 근처 (모터 PWM, L13)3 / 999 → 21 kHz3 / 899 → 20 kHz—

TIM3 · TIM4 는 16비트 카운터라 PSC · ARR 이 각각 0~65535 입니다. F4 의 TIM2 · TIM5 는 32비트라 ARR 을 크게 잡을 수 있습니다. 계산 요령: 먼저 PSC 로 1 MHz(1 µs) 나 10 kHz(100 µs) 같은 딱 떨어지는 틱을 만들고, ARR 로 주기를 정하면 쉽습니다.

CubeMX 설정 (TIM3, 1 Hz)#

  1. Timers → TIM3 → Clock Source: Internal Clock
  2. Parameter Settings: **Prescaler 8399, Counter Mode Up, Counter Period(ARR) 9999**, auto-reload preload Enable
  3. NVIC Settings → TIM3 global interrupt: Enabled

생성 코드에는 TIM_HandleTypeDef htim3; 과 MX_TIM3_Init() 이 들어가지만, 타이머를 시작하는 코드는 여러분이 써야 합니다.

예제 1 — 1 Hz 타이머 인터럽트#

시뮬레이터에서 열기TIM3 1 Hz 열기새 창l07-timer
cCore/Src/main.c
/* USER CODE BEGIN PV */
volatile uint32_t seconds = 0;
volatile uint8_t tick_flag = 0;
/* USER CODE END PV */

  /* USER CODE BEGIN 2 */
  HAL_TIM_Base_Start_IT(&htim3);     // 타이머 시작 + 업데이트 인터럽트 허용
  /* USER CODE END 2 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (tick_flag) {
      tick_flag = 0;
      printf("uptime: %lu s\r\n", seconds);
    }
  }
  /* USER CODE END 3 */

/* USER CODE BEGIN 4 */
/* printf 리타깃: syscalls.c 의 _write() 가 글자마다 이 함수를 부릅니다. */
int __io_putchar(int ch)
{
  HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* 타이머 카운터가 ARR 에 도달해 0 으로 돌아갈 때마다 호출됩니다. */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM3) {
    seconds++;
    tick_flag = 1;
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
  }
}
/* USER CODE END 4 */
  • HAL_TIM_Base_Start_IT(&htim3) — 카운터를 시작하고 업데이트 인터럽트를 켭니다. _IT 없는 HAL_TIM_Base_Start 는 세기만 하고 콜백을 부르지 않습니다.
  • 콜백은 모든 타이머가 공유하므로 htim->Instance == TIM3 으로 어느 타이머인지 확인합니다.
  • 콜백에서는 카운터와 플래그만 바꾸고, printf 는 메인 루프에서 합니다.
시작하자마자 콜백이 한 번 불리는 경우

HAL 버전에 따라 MX_TIM3_Init() 이 설정을 적용하며 업데이트 플래그를 세워 두어, HAL_TIM_Base_Start_IT 직후 콜백이 곧바로 한 번 불리기도 합니다. 첫 주기가 정확해야 하면 시작 전에 __HAL_TIM_CLEAR_FLAG(&htim3, TIM_FLAG_UPDATE); 로 플래그를 지우세요(시뮬레이터 미지원 매크로).

예제 2 — 1 kHz 틱 하나로 여러 주기 만들기#

타이머를 1 ms 마다 부르게 하고(PSC 83, ARR 999), 콜백 안의 소프트웨어 카운터로 여러 주기를 만듭니다. 메인 루프는 비어 있어도 됩니다.

시뮬레이터에서 열기1 kHz 멀티 주기 열기새 창l07-multi
cCore/Src/main.c
  /* USER CODE BEGIN 2 */
  HAL_TIM_Base_Start_IT(&htim3);
  /* USER CODE END 2 */

/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM3) {
    ms++;
    if (ms % 500 == 0) HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);   // 1 Hz 깜빡임
    if (ms % 100 == 0) HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);   // 5 Hz 깜빡임
  }
}
/* USER CODE END 4 */

ms % 500 == 0 은 500 ms 마다 참이 됩니다. 주기가 서로 다른 작업을 여러 개 돌리는 가장 단순한 스케줄러입니다. 단, 콜백이 1 ms 안에 끝나야 한다는 점을 기억하세요.

실습
  1. 예제 1을 0.25초 주기로 바꾸세요. PSC 는 그대로 두고 ARR 만 바꾸면 얼마인가요?
  2. 같은 1 Hz 를 PSC 83 으로 만들 수 있나요? ARR 이 65535 를 넘으면 어떻게 하나요? (TIM2 는 32비트)
  3. 예제 2에 1초마다 printf 로 ms 값을 출력하는 코드를 메인 루프에 추가하세요. USART2 설정과 리타깃이 필요합니다.
스스로 확인
  • 84 MHz 에서 PSC = 839, ARR = 499 이면 업데이트 주파수는?
  • 72 MHz 보드로 코드를 옮기면서 PSC 를 그대로 두면 1 Hz 가 몇 Hz 가 되나요?

자주 나는 오류와 해결#

증상원인해결
콜백이 불리지 않음HAL_TIM_Base_Start (IT 없음) 사용, NVIC 꺼짐, 시작 코드 누락HAL_TIM_Base_Start_IT + NVIC TIM3 global interrupt
주기가 조금 다름 (예: 0.9999 s 대신 1.0001 s)PSC/ARR 에 −1 을 빼먹음공식의 +1 확인
주기가 2배·절반타이머 클럭을 APB 클럭으로 착각, 보드 클럭 다름클럭 트리에서 APB Timer clocks 값 확인
다른 타이머 콜백에서도 LED 가 바뀜htim->Instance 확인 누락if (htim->Instance == TIM3)
FreeRTOS 프로젝트에서 콜백이 이상하게 자주 불림HAL 타임베이스를 TIM 으로 바꾸면 그 타이머도 같은 콜백을 부름자동 생성 코드의 타임베이스 분기 확인, Instance 로 구분

과제#

  1. TIM3 을 10 kHz 틱(84 MHz 기준 PSC 8399)으로 두고, ARR 을 __HAL_TIM_SET_AUTORELOAD 로 바꿔 B1 을 누를 때마다 깜빡임 주기가 1 s → 0.5 s → 0.2 s 로 바뀌게 하세요.
  2. 스톱워치: B1 을 누르면 시작/정지, 10 ms 단위로 UART 에 12.34 s 형식으로 출력하세요.
  3. F411(84 MHz)과 F103(72 MHz)에서 각각 100 µs 틱과 1 kHz 인터럽트를 만드는 PSC/ARR 를 표로 정리하세요.
