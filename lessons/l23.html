L23FreeRTOS 통신과 동기화

메시지 큐(ISR → 태스크), 뮤텍스로 UART 공유, 세마포어·스레드 플래그로 신호 보내기, 소프트웨어 타이머, 우선순위 역전을 다룹니다.

선수 레슨: L22
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • 태스크끼리, 그리고 ISR 에서 태스크로 데이터를 넘길 때 전역 변수 대신 메시지 큐를 씁니다.
  • 뮤텍스로 UART 같은 공유 자원을 보호하고, 세마포어와의 차이(소유권, 우선순위 상속)를 설명합니다.
  • 세마포어 · 스레드 플래그로 ISR 이 태스크를 깨우게 합니다.
  • 소프트웨어 타이머의 실행 문맥과 제약을 압니다.
  • 우선순위 역전이 무엇이고 뮤텍스가 어떻게 막는지 설명합니다.
  • RTOS API 를 부르는 인터럽트의 NVIC 우선순위 규칙(5 이상)을 지킵니다.

공유의 문제#

태스크는 언제든 다른 태스크나 인터럽트에게 CPU 를 빼앗길 수 있습니다. 그래서 둘 이상이 같은 것을 쓰면 문제가 생깁니다.

  • 전역 변수: count++ 는 읽기 → 더하기 → 쓰기 세 단계라, 중간에 전환되면 한 번의 증가가 사라집니다.
  • UART: 두 태스크가 동시에 printf 하면 글자 단위로 섞입니다. 뮤텍스 없이 출력하면 실제로 이런 줄이 나옵니다.
text
[[3 432432]3 ]h olga teen=d4        ← "[3432] late=419 ..." 와 "[3432] hog end" 가 글자 단위로 섞임

RTOS 는 이런 공유를 안전하게 하는 도구를 줍니다.

도구한 줄 요약ISR 에서대표 쓰임
메시지 큐값을 복사해서 줄 세워 전달넣기 가능 (timeout 0)센서 값, 키 입력, 명령
뮤텍스한 번에 한 태스크만 들어가는 열쇠 (소유자 있음)불가UART · I2C · SPI · 공유 구조체 보호
세마포어신호 개수를 세는 카운터 (소유자 없음)Release 가능ISR → 태스크 신호, 자원 개수 관리
스레드 플래그특정 태스크에게 보내는 비트 신호Set 가능한 태스크를 깨우는 가벼운 신호
이벤트 플래그여러 태스크가 보는 비트 모음Set 가능"모두 준비됨" 같은 조건 대기
소프트웨어 타이머틱 기반 콜백—주기적 짧은 작업, 타임아웃

ISR 에서 RTOS 함수를 부를 때의 규칙#

  1. 기다리지 않습니다. ISR 에서는 timeout 을 0 으로 줍니다. CMSIS-RTOS2 는 ISR 안이라는 것을 알아서 FreeRTOS 의 …FromISR 판을 부르며, 0 이 아닌 timeout 은 osErrorParameter 를 돌려줍니다.
  2. 뮤텍스는 쓰지 않습니다. 뮤텍스는 소유 태스크가 있어야 하므로 ISR 에서 쓸 수 없습니다.
  3. NVIC 우선순위를 5 이상(숫자) 으로 둡니다. CubeMX 의 FreeRTOS 설정 LIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 가 5 이므로, 0~4 인 인터럽트에서 RTOS 함수를 부르면 configASSERT 에 걸려 멈춥니다. CubeMX NVIC 표의 Uses FreeRTOS functions 를 체크하면 자동으로 맞춰집니다. 이 레슨의 예제는 USER CODE 2 에서 HAL_NVIC_SetPriority(EXTI15_10_IRQn, 5, 0); 으로 직접 맞춥니다.

예제 1 — 메시지 큐 (버튼 ISR → 태스크)#

B1 의 EXTI 콜백은 버튼 코드 0xFF 를 큐에 넣기만 하고 끝납니다. sensorTask 는 500 ms 마다 센서 값(0~100)을 같은 큐에 넣고, defaultTask 는 osMessageQueueGet(…, osWaitForever) 로 잠들어 있다가 메시지가 오면 깨어나 처리합니다.

시뮬레이터에서 열기메시지 큐 열기새 창l23-queue
cCore/Src/main.c
/* USER CODE BEGIN PV */
/* 메시지 = uint8_t 하나: 0~100 = 센서 값(%), 0xFF = 버튼 눌림 */
#define MSG_BUTTON  0xFF
osMessageQueueId_t eventQueueHandle;
volatile uint32_t last_press = 0;
volatile uint32_t press_tick = 0;        // 마지막으로 누른 시각 (ms)
volatile uint32_t dropped = 0;           // 큐가 가득 차서 버린 메시지
/* USER CODE END PV */

  /* USER CODE BEGIN 2 */
  HAL_NVIC_SetPriority(EXTI15_10_IRQn, 5, 0);   // RTOS API 를 부르는 ISR 은 우선순위 5 이상(숫자)
  printf("Queue demo: press B1\r\n");
  /* USER CODE END 2 */

/* USER CODE BEGIN 4 */
/* printf 리타깃: syscalls.c 의 _write() 가 글자마다 이 함수를 부릅니다. */
int __io_putchar(int ch)
{
  HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* ISR: 절대 기다리지 않는다 → timeout 0. 실패하면 세기만 하고 돌아감 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin != B1_Pin) return;
  uint32_t now = HAL_GetTick();
  if (now - last_press < 50) return;             // 50 ms 안의 채터링 무시
  last_press = now;
  press_tick = now;
  uint8_t msg = MSG_BUTTON;
  if (osMessageQueuePut(eventQueueHandle, &msg, 0, 0) != osOK) dropped++;
}
/* USER CODE END 4 */

큐는 USER CODE BEGIN RTOS_QUEUES 에서 만들고(CubeMX 의 Tasks and Queues 탭에서 Add 해도 같은 코드가 생성됨), 두 태스크는 다음과 같습니다.

cCore/Src/main.c
  /* USER CODE BEGIN RTOS_QUEUES */
  /* 1바이트 메시지 8개를 담는 큐 */
  eventQueueHandle = osMessageQueueNew(8, sizeof(uint8_t), NULL);
  /* USER CODE END RTOS_QUEUES */

void StartDefaultTask(void *argument)          /* osPriorityNormal — 소비자 */
{
  uint8_t msg;
  for(;;)
  {
    if (osMessageQueueGet(eventQueueHandle, &msg, NULL, osWaitForever) == osOK) {   // 메시지가 올 때까지 Blocked
      if (msg == MSG_BUTTON) {
        osDelay(20);                                                   // 채터링이 가라앉은 뒤
        if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_RESET) { // 아직 눌려 있으면 진짜 누름 (뗄 때 튄 에지는 무시)
          HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
          printf("[%5lu] BUTTON (pressed at %lu ms, waiting=%lu, dropped=%lu)\r\n",
                 osKernelGetTickCount(), press_tick, osMessageQueueGetCount(eventQueueHandle), dropped);
        }
      } else {
        printf("[%5lu] SENSOR %u %%\r\n", osKernelGetTickCount(), msg);
      }
    }
  }
}

void StartSensorTask(void *argument)           /* osPriorityBelowNormal — 생산자 */
{
  uint8_t value = 40;
  for(;;)
  {
    value = (value + 7) % 101;                                       // 센서를 읽었다고 치고 0~100 값
    uint8_t msg = value;
    osMessageQueuePut(eventQueueHandle, &msg, 0, osWaitForever);   // 태스크는 큐가 빌 때까지 기다려도 됨
    osDelay(500);
  }
}
text
[ 1001] SENSOR 61 %
[ 1029] BUTTON (pressed at 1009 ms, waiting=0, dropped=0)
[ 1501] SENSOR 68 %
  • 큐는 값을 복사합니다. &msg 가 가리키는 지역 변수는 Put 이 끝나면 사라져도 됩니다.
  • ISR 은 큐가 가득 차면 기다리지 않고 실패(osErrorResource)하므로, 버린 개수(dropped)를 세어 둡니다.
  • 버튼은 뗄 때도 채터링으로 하강 에지가 생깁니다. 소비자 태스크가 20 ms 뒤 레벨을 다시 읽어 진짜 누름만 처리합니다. 태스크 안이라 osDelay 를 마음 놓고 씁니다.
구조체 메시지

실물 FreeRTOS 의 큐는 크기만 맞으면 구조체도 통째로 복사합니다. 센서 종류와 값, 시각을 한 번에 보낼 때 편합니다.

c
typedef struct { uint8_t src; uint16_t value; uint32_t tick; } Msg_t;
q = osMessageQueueNew(8, sizeof(Msg_t), NULL);
Msg_t m = { 1, adc, HAL_GetTick() };
osMessageQueuePut(q, &m, 0, 0);

이 레슨의 예제는 시뮬레이터에서 확실히 동작하도록 1바이트 메시지를 씁니다.

예제 2 — 뮤텍스로 UART 함께 쓰기#

같은 우선순위의 taskA · taskB 가 3줄짜리 보고서를 출력합니다. 보고서 중간에 osDelay(5) 로 일부러 쉬지만, 뮤텍스를 잡고 있으므로 다른 태스크는 osMutexAcquire 에서 기다리고 줄이 섞이지 않습니다.

시뮬레이터에서 열기뮤텍스 열기새 창l23-mutex
cCore/Src/main.c
/* USER CODE BEGIN PV */
osMutexId_t uartMutexHandle;
uint32_t total = 0;                      // 두 태스크가 함께 바꾸는 값 → 뮤텍스로 보호
/* USER CODE END PV */

/* USER CODE BEGIN 0 */
/* 태스크 이름과 함께 3줄짜리 보고서. 뮤텍스를 잡은 동안 다른 태스크는 기다립니다. */
void report(const char *who, uint32_t n)
{
  osMutexAcquire(uartMutexHandle, osWaitForever);
  total++;
  printf("---- %s report #%lu ----\r\n", who, n);
  osDelay(5);                           // 보고서 중간에 쉬어도(다른 태스크로 전환돼도) 줄이 섞이지 않음
  printf("  tick  : %lu\r\n", osKernelGetTickCount());
  printf("  total : %lu\r\n", total);
  osMutexRelease(uartMutexHandle);
}
/* USER CODE END 0 */

뮤텍스는 USER CODE BEGIN RTOS_MUTEX 에서 uartMutexHandle = osMutexNew(NULL); 로 만들고, 두 태스크는 report() 를 부르기만 합니다.

cCore/Src/main.c
void StartTaskA(void *argument) { uint32_t n = 0; for(;;) { report("taskA", ++n); osDelay(700); } }
void StartTaskB(void *argument) { uint32_t n = 0; for(;;) { report("taskB", ++n); osDelay(1100); } }
text
---- taskA report #1 ----
  tick  : 8
  total : 1
---- taskB report #1 ----
  tick  : 17
  total : 2
  • 잡은 뮤텍스는 반드시 같은 태스크가 놓아야 합니다. 함수 중간에 return 하는 길이 있으면 놓치기 쉬우니 한 곳에서 놓도록 짭니다.
  • 뮤텍스를 잡은 채 오래 기다리면 다른 태스크가 모두 멈춥니다. 잡고 있는 구간은 짧게 합니다.
  • 같은 태스크가 중첩해서 잡아야 하면 속성에 osMutexRecursive 를 줍니다.

예제 3 — 세마포어로 ISR 이 태스크 깨우기 + 소프트웨어 타이머#

ISR 은 osSemaphoreRelease 로 신호만 주고, 우선순위가 높은 buttonTask 가 osSemaphoreAcquire 에서 깨어나 처리합니다. 주기 500 ms 소프트웨어 타이머가 LD2 를 깜빡입니다.

시뮬레이터에서 열기세마포어 + 소프트웨어 타이머 열기새 창l23-semaphore-isr
cCore/Src/main.c
/* USER CODE BEGIN PV */
osSemaphoreId_t buttonSemHandle;
osTimerId_t blinkTimerHandle;
volatile uint32_t isr_count = 0;         // ISR 이 불린 횟수 (채터링 포함)
uint32_t presses = 0;                    // 태스크가 처리한 누름 횟수
/* USER CODE END PV */

  /* USER CODE BEGIN 2 */
  HAL_NVIC_SetPriority(EXTI15_10_IRQn, 5, 0);   // RTOS API 를 부르는 ISR 은 우선순위 5 이상(숫자)
  printf("Semaphore demo: press B1\r\n");
  /* USER CODE END 2 */

/* USER CODE BEGIN 4 */
/* printf 리타깃: syscalls.c 의 _write() 가 글자마다 이 함수를 부릅니다. */
int __io_putchar(int ch)
{
  HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* ISR: 신호만 주고 바로 끝 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == B1_Pin) {
    isr_count++;
    osSemaphoreRelease(buttonSemHandle);
  }
}

/* 소프트웨어 타이머 콜백: 타이머 서비스 태스크에서 실행 → 짧게, 기다리지 않기 */
void BlinkTimerCallback(void *argument)
{
  HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
}
/* USER CODE END 4 */

세마포어는 RTOS_SEMAPHORES 구역에서 osSemaphoreNew(1, 0, NULL)(최대 1, 처음 0 = 이진 세마포어), 타이머는 RTOS_TIMERS 구역에서 osTimerNew(BlinkTimerCallback, osTimerPeriodic, NULL, NULL) 로 만들고 osTimerStart(blinkTimerHandle, 500) 으로 시작합니다.

cCore/Src/main.c
void StartButtonTask(void *argument)            /* osPriorityAboveNormal */
{
  for(;;)
  {
    osSemaphoreAcquire(buttonSemHandle, osWaitForever);        // ISR 이 Release 할 때까지 Blocked
    osDelay(50);                                               // 채터링이 가라앉을 때까지
    while (osSemaphoreAcquire(buttonSemHandle, 0) == osOK) { } // 그동안 쌓인 신호는 버림
    if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_RESET) {
      presses++;
      printf("[%5lu] B1 press #%lu (ISR calls so far: %lu)\r\n", osKernelGetTickCount(), presses, isr_count);
    }
  }
}
text
[ 1059] B1 press #1 (ISR calls so far: 2)
[ 2355] B1 press #2 (ISR calls so far: 6)
  • ISR 호출 횟수(채터링 포함)는 누름 횟수보다 많지만, 태스크는 누름마다 한 번만 처리합니다.
  • 이진 세마포어(최대 1)는 신호가 여러 번 와도 1 로 포화됩니다. 개수를 세야 하면 최대값을 키운 카운팅 세마포어를 씁니다.
  • 소프트웨어 타이머 콜백은 FreeRTOS 의 타이머 서비스 태스크(Timer task, CubeMX 기본 우선순위 2) 안에서 실행됩니다. 콜백 안에서 osDelay 나 대기는 금지이고, 모든 타이머가 이 태스크 하나를 나눠 쓰므로 짧게 끝냅니다. (시뮬레이터는 인터럽트처럼 실행)

스레드 플래그로 바꾸기#

한 태스크만 깨우면 되는 경우는 세마포어 객체 없이 스레드 플래그가 더 가볍습니다.

c
/* ISR */
osThreadFlagsSet(buttonTaskHandle, 0x0001);

/* buttonTask */
uint32_t f = osThreadFlagsWait(0x0001, osFlagsWaitAny, osWaitForever);   /* 받은 플래그를 돌려주고 지움 */

우선순위 역전#

높은(H) · 중간(M) · 낮은(L) 우선순위 태스크가 있고, H 와 L 이 같은 자원을 씁니다.

text
시간 ─────────────────────────────────────────────────────────►
L:  [자원 잡음 ....]                    [.... 자원 놓음]
H:          [자원 요청 → 대기 ..........................][실행]
M:               [ H 와 상관없는 긴 작업 ...........]        ← L 을 선점해 L 이 자원을 못 놓음
                 → 결과: H 가 M 때문에 기다림 (우선순위가 뒤집힘)

1997년 화성 탐사선 Mars Pathfinder 가 바로 이 문제로 워치독 리셋을 반복했습니다. 뮤텍스는 우선순위 상속으로 이를 막습니다: H 가 L 이 가진 뮤텍스를 기다리면, L 의 우선순위를 잠시 H 로 올려 M 이 끼어들지 못하게 합니다. 세마포어에는 소유자가 없어 상속이 없습니다. 그래서 자원 보호에는 뮤텍스, 신호 전달에는 세마포어를 씁니다.

  2. 예제 1의 큐 길이를 2 로 줄이고 버튼을 빠르게 여러 번 눌러 dropped 가 늘어나는지 확인하세요. 소비자 태스크의 osDelay(20) 은 어떤 영향을 주나요?

과제#

  1. 출력 전담 태스크를 만드세요. 다른 태스크는 출력할 문자열 번호(1바이트)를 큐에 넣고, 출력 태스크만 printf 합니다. 뮤텍스가 필요 없어지는 이유를 설명하세요.
  2. 이벤트 플래그로 "센서 준비됨(0x01)" 과 "통신 준비됨(0x02)" 이 모두 켜졌을 때만 동작을 시작하는 태스크를 만드세요(osFlagsWaitAll).
  3. L20 의 워치독을 RTOS 에 적용하세요. 태스크마다 스레드 플래그로 "살아 있음" 을 알리고, 감시 태스크가 모두 받았을 때만 HAL_IWDG_Refresh 합니다.
