L21RTC 와 저전력 모드

RTC 달력(BCD·BIN, GetTime 뒤 GetDate), 웨이크업 타이머, SLEEP·STOP·STANDBY 비교와 STOP 복귀 후 SystemClock_Config 를 실습합니다.

선수 레슨: L05 L20
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • RTC 의 클럭(LSE 32.768 kHz)과 분주 128 × 256 = 1 Hz 구조, 백업 도메인을 설명합니다.
  • HAL_RTC_GetTime → HAL_RTC_GetDate 순서 규칙과 BCD / BIN 형식을 구분합니다.
  • RTC 웨이크업 타이머로 주기적인 인터럽트를 만듭니다.
  • SLEEP · STOP · STANDBY 모드의 차이(멈추는 것, 유지되는 것, 깨우는 원인)를 표로 정리합니다.
  • STOP 에서 깨어난 뒤 SystemClock_Config() 를 다시 불러야 하는 이유를 압니다.

RTC 구조#

RTC(Real-Time Clock)는 시 · 분 · 초와 연 · 월 · 일 · 요일을 하드웨어로 세는 달력 시계입니다. 메인 클럭과 따로 백업 도메인에 있어서, MCU 가 리셋되어도 계속 가고, VBAT 핀에 코인 전지를 달면 전원이 꺼져도 갑니다.

Nucleo-64 보드는 리비전(C-02 이후)에 따라 32.768 kHz 크리스털(X2)이 달려 있습니다. 보드 매뉴얼 UM1724 에서 확인하세요.

CubeMX 설정#

  1. System Core → RCC → Low Speed Clock (LSE): Crystal/Ceramic Resonator
  2. Timers → RTC → Activate Clock Source, Activate Calendar 체크
  3. Clock Configuration 탭에서 RTC Clock Mux → LSE
  4. Parameter Settings: Hour Format 24, Asynchronous 127, Synchronous 255, 초기 시각 · 날짜
  5. (웨이크업) WakeUp: Internal WakeUp, Wake Up Clock 1 Hz, Wake Up Counter 0 → NVIC 에서 RTC wake-up interrupt through EXTI line 22 켜기

생성된 MX_RTC_Init() 은 시각을 BCD 형식(sTime.Hours = 0x23;)으로 설정합니다. CubeMX 의 규칙입니다.

시각 읽기 — 순서가 중요합니다#

c
RTC_TimeTypeDef t;
RTC_DateTypeDef d;
HAL_RTC_GetTime(&hrtc, &t, RTC_FORMAT_BIN);   /* 1) 시각 먼저 */
HAL_RTC_GetDate(&hrtc, &d, RTC_FORMAT_BIN);   /* 2) 반드시 날짜도 */

CPU 는 RTC 를 그림자(shadow) 레지스터를 통해 읽습니다. 시각 레지스터(TR)를 읽으면 날짜 레지스터(DR)를 읽을 때까지 그림자 값이 잠깁니다. 그래서 날짜가 필요 없어도 GetDate 를 불러야 다음 GetTime 이 새 값을 봅니다. 이 규칙을 어기면 시계가 멈춘 것처럼 보입니다.

형식23시 59분 51초가 들어오는 모양쓰는 곳
RTC_FORMAT_BINHours = 23, Seconds = 51계산 · printf %d
RTC_FORMAT_BCDHours = 0x23, Seconds = 0x51 (십의 자리 = 위 4비트)레지스터 그대로, 7세그먼트 표시

Year 는 0~99(2000년 기준), WeekDay 는 1(월)~7(일)입니다.

예제 1 — RTC 달력 시계#

CubeMX 에서 2026-12-31 23:59:50 으로 초기화하고, 초가 바뀔 때만 출력합니다. 10 초 뒤 해가 바뀌는지 보세요. B1 을 누르면 같은 시각을 BCD 로도 읽습니다.

시뮬레이터에서 열기RTC 달력 시계 열기새 창l21-rtc-clock
cCore/Src/main.c
/* USER CODE BEGIN PV */
RTC_TimeTypeDef now_time;
RTC_DateTypeDef now_date;
uint8_t last_sec = 99;
uint8_t last_btn = 1;
const char *WEEKDAY[8] = {"", "Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"};
/* USER CODE END PV */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    /* 규칙: GetTime 다음에 반드시 GetDate (그림자 레지스터 잠금 해제) */
    HAL_RTC_GetTime(&hrtc, &now_time, RTC_FORMAT_BIN);
    HAL_RTC_GetDate(&hrtc, &now_date, RTC_FORMAT_BIN);

    if (now_time.Seconds != last_sec) {
      last_sec = now_time.Seconds;
      printf("20%02d-%02d-%02d (%s) %02d:%02d:%02d\r\n", now_date.Year, now_date.Month, now_date.Date,
             WEEKDAY[now_date.WeekDay], now_time.Hours, now_time.Minutes, now_time.Seconds);
      HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    }

    uint8_t btn = HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin);
    if (last_btn == 1 && btn == 0) {                   // B1: 같은 값을 BCD 로 읽어 보기
      RTC_TimeTypeDef t;
      RTC_DateTypeDef d;
      HAL_RTC_GetTime(&hrtc, &t, RTC_FORMAT_BCD);
      HAL_RTC_GetDate(&hrtc, &d, RTC_FORMAT_BCD);
      printf("  BCD raw: Hours=0x%02X Minutes=0x%02X Seconds=0x%02X (BIN %d)\r\n", t.Hours, t.Minutes, t.Seconds, now_time.Seconds);
    }
    last_btn = btn;
    HAL_Delay(100);
  }
  /* USER CODE END 3 */

  BCD raw: Hours=0x23 Minutes=0x59 Seconds=0x51 (BIN 51)
2026-12-31 (Thu) 23:59:52

MX_RTC_Init() 은 부팅마다 시각을 다시 씁니다. 실물에서 시각을 유지하려면 CubeMX 가 만든 USER CODE BEGIN Check_RTC_BKUP 구역에서 백업 레지스터를 확인해, 이미 설정했으면 return; 으로 시각 설정을 건너뜁니다.

c
/* USER CODE BEGIN Check_RTC_BKUP */
if (HAL_RTCEx_BKUPRead(&hrtc, RTC_BKP_DR0) == 0x32F2) return;   /* 이미 설정됨 */
HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR0, 0x32F2);                  /* 처음: 표시 남기고 아래에서 시각 설정 */
/* USER CODE END Check_RTC_BKUP */

백업 레지스터 함수는 시뮬레이터 미지원입니다.

웨이크업 타이머#

RTC 웨이크업 타이머는 RTC 클럭으로 도는 16비트 다운카운터입니다. 0 이 되면 인터럽트(EXTI 22)를 내고 다시 채워집니다.

c
HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 0, RTC_WAKEUPCLOCK_CK_SPRE_16BITS);   /* 1 Hz 클럭, 카운터 0 → (0+1) = 1 초마다 */
void HAL_RTCEx_WakeUpTimerEventCallback(RTC_HandleTypeDef *hrtc);          /* 사용자 정의 콜백 */
HAL_RTCEx_DeactivateWakeUpTimer(&hrtc);                                     /* 끄기 */
WakeUpClock한 칸범위
RTC_WAKEUPCLOCK_RTCCLK_DIV1616 / 32768 Hz ≈ 488 µs488 µs ~ 32 s
RTC_WAKEUPCLOCK_CK_SPRE_16BITS1 s1 s ~ 18.2 시간 (카운터 + 1 초)
RTC_WAKEUPCLOCK_CK_SPRE_17BITS1 s18.2 ~ 36.4 시간

저전력 모드 비교#

배터리로 몇 달씩 동작하는 장치는 대부분의 시간을 잠들어 있다가, 필요할 때만 깨어나 일하고 다시 잡니다. STM32F4 의 세 가지 모드는 다음과 같습니다.

모드들어가는 함수멈추는 것유지되는 것깨우는 원인깨어난 뒤대표 전류

STOPHAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI)PLL · HSI · HSE, 거의 모든 클럭 (SysTick · 타이머 · UART 멈춤)RAM · 레지스터 · GPIO 상태, LSE · RTC · IWDGEXTI 라인 (GPIO EXTI, RTC 웨이크업 · 알람)다음 줄부터, 클럭은 HSI → SystemClock_Config()수~수십 µA (데이터시트 확인)

  • 전류 값은 칩 · 온도 · 전압 · 설정에 따라 크게 다르므로 반드시 데이터시트의 전기적 특성 표에서 확인합니다. L0 · L4 · U5 같은 저전력 제품군은 STOP 에서 1 µA 안팎까지 내려갑니다.
  • 시뮬레이터 런타임은 모드마다 머문 시간으로 평균 전류를 대략 추정합니다(제품군 대표값 기준). 실제 설계는 실측으로 확인합니다.

SLEEP 과 SysTick#

HAL 은 1 ms 마다 SysTick 인터럽트를 냅니다. SLEEP 에 들어가도 1 ms 뒤 SysTick 이 깨우므로 잠든 효과가 거의 없습니다. 그래서 잠들기 전에 HAL_SuspendTick(), 깨어난 뒤 HAL_ResumeTick() 을 부릅니다. STOP 에서도 같은 짝을 씁니다.

STOP 에서 깨어나면 클럭부터#

STOP 모드는 PLL 을 끄므로, 깨어난 직후 시스템 클럭은 HSI 16 MHz 입니다. 그대로 두면 84 MHz 기준으로 계산한 UART 보레이트 · 타이머 주기 · HAL_Delay 가 모두 틀어집니다. 깨어나자마자 CubeMX 가 만든 SystemClock_Config() 를 다시 부릅니다.

예제 2 — STOP 모드 + RTC 1초 웨이크업 + B1#

RTC 가 1 초마다, B1(EXTI13)은 누를 때 MCU 를 깨웁니다. 깨어나면 원인과 시각을 출력하고 다시 잡니다.

시뮬레이터에서 열기STOP + 웨이크업 열기새 창l21-stop-wakeup
cCore/Src/main.c
  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    /* 1) 잠들기 전: 할 일을 끝내고 UART 전송도 끝났는지 확인 (HAL_UART_Transmit 은 끝날 때까지 기다림) */
    HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);
    HAL_SuspendTick();                                  // SysTick 인터럽트가 깨우지 않게
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

    /* 2) 여기서 깨어남: STOP 에서는 PLL 이 꺼지고 HSI 로 돌아오므로 클럭부터 복구 */
    SystemClock_Config();
    HAL_ResumeTick();

    HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_SET);
    HAL_RTC_GetTime(&hrtc, &tm, RTC_FORMAT_BIN);
    HAL_RTC_GetDate(&hrtc, &dt, RTC_FORMAT_BIN);
    printf("[%02d:%02d:%02d] woke by %s (rtc=%lu, btn=%lu)\r\n", tm.Hours, tm.Minutes, tm.Seconds,
           wake_src == 2 ? "B1" : "RTC", rtc_wakes, btn_wakes);
    wake_src = 0;
  }
  /* USER CODE END 3 */

/* USER CODE BEGIN 4 */
/* printf 리타깃: syscalls.c 의 _write() 가 글자마다 이 함수를 부릅니다. */
int __io_putchar(int ch)
{
  HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}

/* RTC 웨이크업 타이머: 1 초마다 */
void HAL_RTCEx_WakeUpTimerEventCallback(RTC_HandleTypeDef *hrtc)
{
  rtc_wakes++;
  if (wake_src == 0) wake_src = 1;
}

/* B1 (EXTI13) */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == B1_Pin) {
    btn_wakes++;
    wake_src = 2;
  }
}
/* USER CODE END 4 */
text
[08:00:01] woke by RTC (rtc=1, btn=0)
[08:00:01] woke by B1 (rtc=1, btn=1)
[08:00:02] woke by RTC (rtc=2, btn=1)
  • 버튼을 한 번 눌러도 채터링 때문에 두세 번 깰 수 있습니다(btn 이 여러 번 증가). 깨어난 뒤 20 ms 쯤 기다렸다 레벨을 다시 읽으면 걸러집니다.
  • STOP 동안 UART 는 멈춥니다. printf 가 끝난 뒤에 잠들어야 마지막 글자가 잘리지 않습니다. HAL_UART_Transmit 은 전송이 끝날 때까지 기다리므로 안전합니다.
  • 시뮬레이터의 콘솔(로그)에 STOP 모드 진입 이 찍히고, 잠든 동안에는 가상 시간이 다음 사건까지 건너뜁니다.
STANDBY 를 쓰는 코드의 모양
c
/* USER CODE BEGIN 2 */
if (__HAL_PWR_GET_FLAG(PWR_FLAG_SB)) {           /* STANDBY 에서 깨어난 리셋인가? */
  __HAL_PWR_CLEAR_FLAG(PWR_FLAG_SB);
  printf("wake from STANDBY\r\n");
}
/* ... 할 일 ... */
__HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);                /* 남아 있는 웨이크업 플래그를 지워야 곧바로 깨지 않음 */
HAL_PWR_EnableWakeUpPin(PWR_WAKEUP_PIN1);         /* PA0 상승 에지로 깨우기 */
HAL_PWR_EnterSTANDBYMode();                        /* 돌아오지 않음 — 다음은 main() 처음 */

STANDBY 는 RAM 이 지워지므로, 깨어난 뒤 이어서 할 정보는 RTC 백업 레지스터에 저장합니다.

실물에서 저전력 실험할 때
  • 디버거 연결이 끊깁니다. STOP · STANDBY 에서는 SWD 가 응답하지 않아 다시 플래시할 수 없게 보일 수 있습니다. 이때 CubeProgrammer 에서 Connect under reset 으로 연결합니다. 개발 중에는 부팅 직후 2~3 초 기다렸다가 잠들게 하면 안전합니다.
  • 소비 전류는 Nucleo-64 의 JP6(IDD) 점퍼를 빼고 그 자리에 전류계를 직렬로 연결해 잽니다. 전류계 범위를 mA → µA 로 바꾸는 순간 전원이 끊기지 않게 주의하고, 측정 중 핀에 연결된 LED · 모듈 전류도 함께 잡힌다는 점을 기억하세요.
  • 쓰지 않는 핀은 아날로그 입력으로 두면 누설 전류가 줄어듭니다. 떠 있는 디지털 입력은 µA 단위 누설을 만듭니다.
  • 배선 변경은 USB 를 뽑은 상태에서 합니다.

시계가 멈춰 있음GetDate 를 부르지 않아 그림자 레지스터가 잠김GetTime 뒤 항상 GetDate
시각이 이상한 숫자 (예: 35시)BCD 값을 %d 로 출력RTC_FORMAT_BIN 으로 읽기
하루에 몇 분씩 틀림LSI 사용LSE 크리스털, RTC 클럭 Mux 확인
리셋할 때마다 시각이 초기화MX_RTC_Init 이 매번 설정백업 레지스터 확인 후 건너뛰기
STOP 뒤 UART 글자가 깨짐클럭이 HSI 로 돌아옴깨어난 뒤 SystemClock_Config()
SLEEP 에 들어가도 전류가 그대로SysTick 이 1 ms 마다 깨움HAL_SuspendTick()
STOP 에서 영원히 깨지 않음깨울 EXTI · RTC 인터럽트가 NVIC 에서 꺼짐RTC_WKUP / EXTI15_10 켜기
STANDBY 에 들어가자마자 깨어남WUF 플래그가 남아 있음__HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU) 뒤 진입

과제#

  1. 1 분마다 깨어나 DHT11(L17) 온습도를 읽고 UART 로 보낸 뒤 다시 STOP 으로 들어가는 데이터 로거를 설계하세요. 평균 전류를 줄이려면 무엇을 더 끌 수 있나요?
  2. RTC 알람(HAL_RTC_SetAlarm_IT, 실물)으로 매일 07:00 에 릴레이를 켜는 타이머 스위치를 설계하세요.
  3. 한 번 깨어나 5 ms 일하고 995 ms 자는 장치의 평균 전류를 계산하세요(RUN 20 mA, STOP 50 µA 로 가정). 배터리 1000 mAh 로 며칠 가나요?
