PART 5 중급 활용 · 약 45분 · 중급

L20워치독과 리셋

IWDG 제한 시간 계산식과 Refresh 위치 설계, RCC 리셋 플래그로 원인 판별, WWDG 의 창 개념, NVIC_SystemReset 을 익힙니다.

선수 레슨: L06 L07
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • 워치독이 필요한 이유와 독립 워치독(IWDG) 의 동작(LSI 클럭, 다운카운터, Refresh)을 설명합니다.
  • 제한 시간 공식 T = 4 × 2^PR × (RL + 1) / LSI 로 프리스케일러와 Reload 값을 고르고, LSI 오차를 반영합니다.
  • HAL_IWDG_Refresh 를 어디에 두어야 멈춤을 제대로 잡는지 설계합니다.
  • RCC 리셋 플래그로 리셋 원인을 판별하고, NVIC_SystemReset() 으로 소프트웨어 리셋을 겁니다.
  • 창 워치독(WWDG)의 "너무 늦어도, 너무 일러도 리셋" 개념을 이해합니다.

왜 워치독인가#

현장의 장치는 사람이 리셋 버튼을 눌러 줄 수 없습니다. 무한 루프, I2C 장치가 응답하지 않아 멈춘 while, 스택 오버플로, 잡음으로 틀어진 레지스터 … 원인이 무엇이든 프로그램이 멈추면 스스로 리셋해서 다시 시작해야 합니다.

워치독은 혼자 거꾸로 세는 타이머입니다. 프로그램이 정상이면 주기적으로 카운터를 다시 채우고(Refresh, "개에게 먹이 주기"), 멈춰서 Refresh 가 끊기면 카운터가 0 에 닿아 MCU 전체를 리셋합니다.

IWDG 구조#

  • 클럭은 메인 클럭과 독립된 LSI RC 발진기(F4 약 32 kHz, F1 약 40 kHz)입니다. 메인 클럭이 죽어도 동작합니다.
  • 12비트 다운카운터(0~4095)와 프리스케일러(÷4 ~ ÷256)로 구성됩니다.
  • 한 번 시작하면 리셋 외에는 멈출 수 없습니다. (옵션 바이트로 전원을 켜자마자 자동 시작하게 할 수도 있음: 하드웨어 워치독)

제한 시간 = 4 × 2^PR × (Reload + 1) / LSI 주파수 — PR 은 0~6 이고, HAL 에서는 IWDG_PRESCALER_4 ~ IWDG_PRESCALER_256 과 Reload(0~4095)로 줍니다.

Prescaler틱 (32 kHz)Reload 999Reload 4095 (최대)
IWDG_PRESCALER_40.125 ms125 ms512 ms
IWDG_PRESCALER_321 ms1.0 s4.1 s
IWDG_PRESCALER_642 ms2.0 s8.2 s
IWDG_PRESCALER_2568 ms8.0 s32.8 s
LSI 는 정확하지 않습니다

STM32F411 데이터시트의 LSI 는 최소 17 kHz, 보통 32 kHz, 최대 47 kHz 입니다. 1 s 로 설계한 IWDG 가 실제로는 0.68 s ~ 1.88 s 일 수 있습니다. 그래서 LSI 가 가장 빠를 때(가장 짧은 제한 시간) 에도 정상 루프가 넉넉히 Refresh 할 수 있게 잡습니다. 이 예제는 200 ms 마다 Refresh 하므로 0.68 s 안에 충분히 들어갑니다.

CubeMX 설정#

System Core → IWDG → Activated, IWDG counter clock prescaler 32, IWDG down-counter reload value 999. IWDG_HandleTypeDef hiwdg; 와 MX_IWDG_Init() 이 생성되고, **MX_IWDG_Init() 이 불리는 순간부터 카운트가 시작**됩니다. 그 뒤의 초기화(LCD, 센서 대기 등)가 제한 시간보다 길면 while 루프에 닿기도 전에 리셋되므로, 긴 초기화 중간에도 Refresh 하거나 IWDG 초기화를 뒤로 미룹니다.

예제 — 멈추면 스스로 리셋#

200 ms 마다 LD2 를 토글하며 Refresh 합니다. B1 을 누르면 무한 루프에 빠진 척합니다. 1초 뒤 IWDG 가 리셋하고, 다시 시작한 main() 이 리셋 원인을 출력합니다. 터미널에 r 을 보내면 NVIC_SystemReset() 으로 소프트웨어 리셋합니다.

시뮬레이터에서 열기IWDG 리셋 열기새 창l20-iwdg
cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* 리셋 원인 출력. 여러 플래그가 함께 켜질 수 있어 구체적인 것부터 검사합니다. */
void print_reset_cause(void)
{
  if (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST))      printf("Reset cause: IWDG (independent watchdog)\r\n");
  else if (__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST)) printf("Reset cause: WWDG (window watchdog)\r\n");
  else if (__HAL_RCC_GET_FLAG(RCC_FLAG_SFTRST))  printf("Reset cause: software (NVIC_SystemReset)\r\n");
  else if (__HAL_RCC_GET_FLAG(RCC_FLAG_PORRST))  printf("Reset cause: power-on\r\n");
  else if (__HAL_RCC_GET_FLAG(RCC_FLAG_PINRST))  printf("Reset cause: NRST pin (reset button)\r\n");
  else                                           printf("Reset cause: unknown\r\n");
  __HAL_RCC_CLEAR_RESET_FLAGS();                  // 지우지 않으면 다음 리셋 때도 남아 있음
}
/* USER CODE END 0 */

  /* USER CODE BEGIN 2 */
  print_reset_cause();
  printf("IWDG running: refresh every 200 ms. B1 = hang, 'r' = software reset\r\n");
  /* USER CODE END 2 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    loops++;

    if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_RESET) {
      printf("B1: main loop stuck after %lu loops...\r\n", loops);
      while (1) { }                               // 버그로 멈춘 상황 흉내 — Refresh 가 더는 불리지 않음
    }
    if (HAL_UART_Receive(&huart2, &rx_ch, 1, 0) == HAL_OK && rx_ch == 'r') {
      printf("Software reset\r\n");
      NVIC_SystemReset();                         // 즉시 리셋 (돌아오지 않음)
    }

    HAL_IWDG_Refresh(&hiwdg);                     // 한 바퀴가 정상으로 끝났을 때만 Refresh
    HAL_Delay(200);
  }
  /* USER CODE END 3 */

B1: main loop stuck after 6 loops...

IWDG running: refresh every 200 ms. B1 = hang, 'r' = software reset
Software reset

  • 리셋되면 전역 변수(loops)는 0 으로 돌아갑니다. RAM 은 다시 초기화되기 때문입니다.
  • 리셋 플래그는 RCC_CSR 레지스터에 남아 있다가 전원을 끄거나 __HAL_RCC_CLEAR_RESET_FLAGS() 로 지울 때까지 유지됩니다. 지우지 않으면 다음 리셋에서도 옛 원인이 보입니다.

내부 리셋(워치독 · 소프트웨어 · 전원)은 NRST 핀을 LOW 로 끌어내리므로 PINRST 도 같이 켜집니다. 그래서 예제는 구체적인 원인부터 검사하고 PINRST 를 맨 마지막에 둡니다. 현장 장치라면 리셋 원인과 횟수를 백업 레지스터나 플래시에 기록해 두면 고장 분석에 큰 도움이 됩니다.

Refresh 는 어디에#

위치결과
메인 루프 끝에서 한 번 (예제)루프가 멈추면 리셋 — 올바름
타이머 인터럽트 안메인 루프가 멈춰도 인터럽트는 계속 돌아 Refresh — 워치독이 쓸모없어짐
오래 걸리는 함수 곳곳에 여러 번어디서 멈춰도 그 근처 Refresh 가 살려 줌 — 멈춤을 놓침
모든 작업의 "살아 있음" 확인 뒤여러 작업(RTOS 태스크)이 각자 플래그를 세우고, 감시 코드가 모두 세워졌을 때만 Refresh — 가장 안전
  • 플래시 섹터 지우기(F4 의 128 KB 섹터는 1초 이상 걸릴 수 있음)처럼 오래 막히는 작업 앞에서는 Refresh 하거나 제한 시간을 넉넉히 둡니다.
  • 디버거로 중단점에 멈추면 IWDG 는 계속 셉니다. 디버깅 중 리셋을 막으려면 __HAL_DBGMCU_FREEZE_IWDG(); 를 부릅니다(시뮬레이터 미지원).
  • F4 의 IWDG 는 STOP · STANDBY 모드에서도 계속 셉니다. 저전력 장치는 RTC 웨이크업으로 주기적으로 깨어나 Refresh 합니다(L21). L4 · G0 는 옵션 바이트로 저전력 모드에서 멈출 수 있습니다.

창 워치독 WWDG (개념)#

WWDG 는 APB1 클럭으로 동작하는 7비트 다운카운터입니다. 카운터가 0x40 아래(0x3F)로 떨어지면 리셋하고, 추가로 창(Window) 값보다 클 때 Refresh 해도 리셋합니다. "정해진 시간 창 안에서만" 먹이를 주어야 합니다.

text
카운터  0x7F ─────────── W(창) ─────────── 0x40 ──► 0x3F = 리셋
         │  여기서 Refresh = 리셋 │ 여기서 Refresh = 정상 │ 늦음 = 리셋
  • 너무 빨리 도는 루프(예: 조건 검사를 건너뛰는 버그)도 잡습니다.
  • F411(APB1 42 MHz)에서 틱 = 4096 × 2^WDGTB / 42 MHz. WDGTB = 3 이면 약 0.78 ms, 최대 64틱 ≈ 50 ms 로 짧습니다.
  • 카운터가 0x40 이 되면 조기 경고 인터럽트(EWI) 로 리셋 직전에 상태를 기록할 수 있습니다.
  • 시뮬레이터는 WWDG 를 지원하지 않습니다. 개념과 설정 값 계산만 익혀 두세요.

소프트웨어 리셋#

NVIC_SystemReset() 은 코어의 AIRCR 레지스터에 리셋 요청(SYSRESETREQ)을 써서 즉시 리셋합니다. 함수는 돌아오지 않습니다. 설정을 바꾼 뒤 다시 시작하거나, 부트로더로 넘어가거나, 복구할 수 없는 오류(Error_Handler)에서 씁니다. 단, Error_Handler 에서 무조건 리셋하면 원인을 모른 채 계속 재시작하므로, 원인을 기록하고 리셋 횟수를 제한하는 편이 좋습니다.

자주 나는 오류와 해결#

증상원인해결
부팅하자마자 계속 리셋초기화가 제한 시간보다 김초기화 중 Refresh, 제한 시간 늘리기

리셋 원인이 늘 같게 나옴플래그를 지우지 않음__HAL_RCC_CLEAR_RESET_FLAGS()
멈췄는데 리셋되지 않음Refresh 를 인터럽트 안에서 호출메인 루프(또는 감시 태스크)로 옮기기

과제#

  1. 메인 루프의 작업 세 개(센서 읽기, 표시, 통신)가 각각 비트를 세우고, 세 비트가 모두 세워졌을 때만 Refresh 하는 감시 구조를 만드세요.
  2. 리셋 원인별 횟수를 RTC 백업 레지스터(HAL_RTCEx_BKUPWrite, 실물)에 누적해 부팅 때 출력하는 코드를 설계하세요.
  3. WWDG 로 20~40 ms 창을 만들려면 WDGTB, 카운터, 창 값을 얼마로 해야 하는지 계산하세요(APB1 42 MHz).
