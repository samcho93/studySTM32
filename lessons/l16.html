L16실물 보드로 옮기기

STM32CubeIDE 설치, .ioc 설정, 빌드와 ST-Link 플래시·디버그, 시뮬레이터와 실물의 차이와 안전한 배선을 정리합니다.

선수 레슨: L15
시뮬레이터에서 실습HAL 레퍼런스

학습 목표#

  • STM32CubeIDE 를 설치하고 Board Selector 로 NUCLEO-F411RE 프로젝트를 만듭니다.
  • 시뮬레이터 예제의 핀·주변장치 설정을 .ioc 로 옮기고, USER CODE 를 붙여 넣어 빌드합니다.
  • ST-Link 로 플래시(Run) 와 디버그(중단점, 한 줄 실행, Live Expressions) 를 합니다.
  • 시뮬레이터와 실물의 차이를 알고, 안전한 배선·전원 규칙을 지킵니다.
  • BluePill 처럼 별도 ST-Link 가 필요한 보드에서 주의할 점(SWD 설정, active-low LED)을 압니다.

CubeIDE 설치#

  1. ST 홈페이지의 STM32CubeIDE 페이지에서 운영체제에 맞는 설치 파일을 내려받습니다(ST 계정 로그인이 필요할 수 있습니다).
  2. 설치 중 ST-LINK 드라이버 설치 항목을 꼭 켭니다(Windows).
  3. 처음 실행하면 작업 폴더(workspace)를 고릅니다. 경로에 한글·공백이 없는 폴더(예: C:\stm32\ws)를 권합니다.
  4. 사용하는 버전에 따라 CubeMX 가 IDE 에 들어 있거나(1.x), 따로 설치해야 합니다(2.x). L01 의 안내를 참고하세요.

프로젝트 만들기와 .ioc 설정#

  1. File → New → STM32 Project → Board Selector 에서 NUCLEO-F411RE 를 고릅니다.
  2. 프로젝트 이름(영문)을 적고 Targeted Language C, Binary Type Executable 로 만듭니다.
  3. "Initialize all peripherals with their default Mode?" 에 Yes — LD2(PA5), B1(PC13), USART2(PA2/PA3)가 자동으로 설정됩니다.
  4. .ioc 화면(핀아웃)에서 시뮬레이터 예제와 똑같이 핀·주변장치·NVIC 를 설정합니다. 예를 들어 L15 스마트 선풍기라면 L15 의 핀 배치표·설정표를 그대로 따릅니다.
  5. Clock Configuration 탭에서 HCLK 가 84 MHz 인지 확인합니다(이 강좌의 PSC/ARR 계산 기준).
  6. 저장(Ctrl+S)하거나 Generate Code 를 누르면 Core/Src/main.c, Core/Inc/main.h 등이 생성됩니다.
주변장치별 파일로 생성되는 경우

Project Manager → Code Generator → Generate peripheral initialization as a pair of '.c/.h' files per peripheral 을 켜면 usart.c, tim.c 처럼 파일이 나뉘고 핸들(huart2, htim3)은 각 헤더에 extern 으로 선언됩니다. main.c 가 그 헤더들을 포함하므로 USER CODE 는 그대로 동작합니다. 시뮬레이터는 모두 main.c 에 생성하는 방식입니다.

시뮬레이터 코드 탭의 USER CODE 구역 내용을 CubeIDE 의 main.c 에서 같은 이름의 구역에 붙여 넣습니다.

터미널 연결#

UART 예제는 PC 의 터미널 프로그램으로 봅니다. Windows 장치 관리자에서 STMicroelectronics STLink Virtual COM Port (COMx) 번호를 확인하고, Tera Term · PuTTY(또는 CubeIDE 의 Console → Command Shell Console → Serial Port)에서 COMx, 115200, 8N1 로 엽니다.

BluePill 로 옮기기#

BluePill(STM32F103C8T6)은 ST-Link 가 내장되어 있지 않아 별도 ST-Link V2(동글) 를 SWD 로 연결합니다.

ST-Link V2BluePill (디버그 헤더)
SWDIODIO (PA13)
SWCLKCLK (PA14)
GNDGND
3.3V3.3 (USB 로 전원을 줄 때는 연결하지 않음)
  • CubeMX 에서 System Core → SYS → Debug: Serial Wire 를 반드시 켭니다. 꺼 두고 플래시하면 PA13/PA14 가 일반 GPIO 가 되어

다음부터 디버거가 연결되지 않습니다. 이때는 ST-Link 설정의 Connect under reset(또는 BOOT0 을 1로 두고 전원 인가)으로 복구합니다.

  • RCC → HSE: Crystal/Ceramic Resonator 를 켜고 클럭 트리에서 8 MHz × 9 = 72 MHz 로 설정합니다. 타이머 계산은 72 MHz 기준(L07 표).
  • 보드 LED 는 PC13 이고 LOW 일 때 켜집니다(active-low). PC13 은 전류를 조금밖에 못 내므로 LED 표시 용도로만 씁니다.

실습 (실물)#

배선·전원 안전 수칙
  • 배선은 전원을 끈 상태에서 합니다. USB 를 뽑고 연결을 마친 뒤, 한 번 더 확인하고 전원을 넣습니다.
  • 3.3V · 5V · GND 를 서로 직접 연결하지 마세요. 점퍼선 하나 잘못 꽂으면 보드와 PC USB 포트가 손상될 수 있습니다.
  • STM32 핀은 3.3 V 입니다. 5 V 신호는 데이터시트에서 5V 허용(FT) 핀인지 확인하고, 아날로그(ADC) 핀에는 절대 5 V 를 넣지 마세요.
  • 핀 하나의 전류는 수 mA ~ 20 mA 정도로 제한됩니다. LED 에는 저항을, 모터·릴레이·부저에는 드라이버(트랜지스터, L298N, ULN2003)를 씁니다.
  • 모터·서보는 별도 전원을 쓰고 GND 만 보드와 공통으로 묶습니다. 돌아가는 모터·기어에 손가락이나 머리카락이 닿지 않게 합니다.
  • Nucleo 에 USB 와 외부 전원을 동시에 넣지 마세요(점퍼 설정에 따라 역전류). 외부 전원을 쓸 때는 보드 매뉴얼(UM1724)의 전원 선택 점퍼를 확인합니다.
  • 부품이 뜨거워지거나 냄새·연기가 나면 즉시 USB 를 뽑습니다. 원인을 찾기 전에는 다시 켜지 않습니다.
  • L298N 방열판, 레귤레이터는 동작 중 뜨거울 수 있으니 만지지 마세요. 실습은 반드시 강사 확인 후 전원을 넣습니다.
실습 — 스마트 선풍기를 실물로
  1. CubeIDE 에서 NUCLEO-F411RE 프로젝트를 만들고 L15 의 핀·설정표대로 .ioc 를 설정합니다.
  2. 시뮬레이터 l15-fan 예제의 USER CODE 를 구역별로 옮겨 붙이고 빌드합니다(오류 0, 경고 확인).
  3. 모터 전원을 연결하지 않은 채 먼저 실행해 LCD·UART 로그·LD2 가 요구사항대로 동작하는지 봅니다.
  4. 전원을 끄고 L298N 과 모터 전원을 연결한 뒤, 강사 확인을 받고 전원을 넣어 모터 동작을 시험합니다.
  5. 디버그 모드로 HAL_GPIO_EXTI_Callback 에 중단점을 걸고, B1 을 누를 때 멈추는지와 mode 값을 확인합니다.

과제#

  1. L03 ~ L14 중 두 개의 예제를 골라 실물 보드로 옮기고, 시뮬레이터 결과와 다른 점을 사진·로그와 함께 정리하세요.
  2. CubeIDE 디버거의 SFRs 창에서 GPIOA → ODR 를 열어 두고 LD2 가 토글될 때 5번 비트가 바뀌는 것을 확인하세요.
  3. 같은 L15 코드를 NUCLEO-F103RB(72 MHz)로 옮기려면 무엇을 바꿔야 하는지 목록을 만드세요. (타이머 PSC, ADC 설정, 헤더 이름 등)
