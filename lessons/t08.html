PART 0 STM32 이해하기 · 약 55분 · 기초

T08통신 인터페이스 원리

UART 프레임과 보레이트 오차, I2C 의 오픈드레인·주소·ACK·클럭 스트레칭, SPI 의 4 모드와 NSS, 세 인터페이스 비교표, CAN·USB·I2S·SDIO 개요, SWD·JTAG 디버그 인터페이스와 선택 기준을 익힙니다.

선수 레슨: T05
시뮬레이터에서 실습

학습 목표#

  • UART 프레임(시작 · 데이터 · 패리티 · 정지 비트)을 그릴 수 있고, BRR 로 보레이트 오차를 계산하며, RS-232 · RS-485 · TTL 레벨과 흐름 제어를 구분합니다.
  • I2C 가 왜 오픈드레인인지, START · STOP · ACK · 7비트 주소와 << 1, 클럭 스트레칭, 풀업 값, 표준 · 고속 모드를 설명할 수 있습니다.
  • SPI 의 CPOL · CPHA 네 모드, 풀듀플렉스, NSS 처리, 속도 한계를 압니다.
  • 세 인터페이스를 선 수 · 속도 · 거리 · 다중 장치 기준으로 비교하고, CAN · USB · I2S · SDIO 가 어디에 쓰이는지 개요를 압니다.
  • SWD · JTAG 디버그 인터페이스와 ST-Link 가 어떻게 칩에 닿는지, 디버그 핀을 잘못 건드렸을 때 복구하는 법을 압니다.

UART#

프레임#

UART(Universal Asynchronous Receiver/Transmitter) 는 클럭 선 없이 두 장치가 미리 약속한 속도(보레이트) 로 비트를 주고받습니다. STM32 의 USART 는 동기 모드(클럭 출력)도 되지만 거의 비동기로 씁니다.

필드비트 수값뜻
유휴—1아무것도 안 보낼 때 선은 HIGH
시작10수신기가 이 하강 에지에서 타이밍을 맞춤
데이터5 ~ 9 (보통 8)LSB 먼저
패리티0 또는 1짝수 · 홀수1비트 오류 검출 (선택)
정지1 · 1.5 · 21다음 시작 비트 전에 최소 유휴 시간

"8N1" 은 데이터 8 · 패리티 없음 · 정지 1 이며, 한 바이트에 10비트가 걸립니다. 115 200 bps 에서 1비트 = 8.68 µs, 한 바이트 = 86.8 µs, 초당 최대 11 520 바이트입니다. printf("%.2f V\r\n", v) 가 10글자면 약 0.9 ms — 1 ms 타이머 ISR 안에서 printf 를 하면 안 되는 이유가 숫자로 보입니다.

수신기는 16배 오버샘플링으로 각 비트를 16번 샘플하고, 가운데 세 샘플(8 · 9 · 10번째)의 다수결로 값을 정합니다. 세 샘플이 다르면 NF(noise flag)가 섭니다. OVER8 = 1 로 8배 오버샘플링을 쓰면 최대 보레이트가 두 배가 되는 대신 잡음 여유가 줄어듭니다.

보레이트와 BRR#

STM32 의 보레이트는 주변장치 클럭을 USARTDIV 로 나눠 만듭니다. USARTDIV 는 정수부 12비트 + 소수부 4비트(1/16 단위)로 BRR 레지스터에 들어갑니다 (F1 · F4).

USARTDIV = f_{PCLK} / (16 × 보레이트) (OVER8 = 0)

장치PCLK보레이트USARTDIVBRR (정수.소수)실제 보레이트오차

USART1 (APB2, F411)84 MHz115 20045.57345 + 9/16 = 45.5625 → 0x2D9115 226+0.02 %

USART2 (F411)42 MHz921 6002.8482 + 14/16 = 2.875 → 0x2E913 043−0.93 %
  • 실제 보레이트 = PCLK / (16 × BRR 값) 입니다. 예: 42 000 000 / (16 × 22.8125) = 115 068.5.
  • 송신 · 수신 양쪽의 오차 합이 대략 2 % 이내면 안전하고, 3 % 를 넘으면 마지막 비트에서 샘플이 어긋나 프레이밍 오류가 납니다. HSI (±1 %) 만 쓰는 두 보드 사이라면 여유가 더 필요합니다.
  • 흔한 보레이트: 9 600 (센서 · GPS 기본), 115 200 (표준, ST-Link VCP), 921 600 · 1 500 000 (로그 대량 출력). 최대는 PCLK/16 (USART2: 2.625 Mbps), OVER8 로 PCLK/8.
  • HAL_UART_Init 이 huart->Init.BaudRate 로 이 계산을 대신하므로 BRR 을 직접 쓸 일은 드물지만, "왜 115 200 이 딱 맞지 않는가" 를 알아야 오차 문제를 진단할 수 있습니다.

I2C#

왜 오픈드레인인가#

I2C(Inter-Integrated Circuit) 는 SDA(데이터) · SCL(클럭) 두 선에 최대 127개 장치를 매답니다. 여러 장치가 한 선을 공유하므로 T05 에서 본 대로 오픈드레인 + 풀업이어야 합니다.

  • 누구든 선을 0 으로 당길 수 있고, 아무도 당기지 않으면 풀업이 1 로 올립니다 (wired-AND).
  • 슬레이브가 ACK 를 보내는 것, 슬레이브가 준비될 때까지 SCL 을 잡아 두는 클럭 스트레칭, 두 마스터가 동시에 말할 때의 중재가 모두 "0 이 이긴다" 는 성질로 이루어집니다.
  • STM32 핀은 GPIO_MODE_AF_OD 로 설정하고, 풀업은 외부 저항을 답니다. 내부 풀업(40 kΩ)은 너무 약해 400 kHz 에서는 파형이 삼각파가 됩니다. 브레드보드 실습에서 모듈(LCD 백팩, 센서 보드)에 4.7 kΩ 이 이미 붙어 있는 경우가 많습니다.

풀업 값은 상승 시간과 싱크 전류 사이의 타협입니다. 규격의 최대 상승 시간 tr (표준 1 000 ns, 고속 300 ns), 버스 커패시턴스 Cb 로:

R_{p,max} = t_r / (0.8473 × C_b), R_{p,min} = (V_{DD} − 0.4 V) / 3 mA

Cb = 100 pF, 3.3 V 면 표준 모드 최대 11.8 kΩ, 고속 모드 최대 3.5 kΩ, 최소 0.97 kΩ. 그래서 100 kHz 는 4.7 kΩ, 400 kHz 는 2.2 kΩ 이 흔한 값입니다. 장치가 많아 Cb 가 커지면 낮춥니다 (규격 최대 400 pF).

트랜잭션#

단계신호누가
STARTSCL = 1 인 동안 SDA 1 → 0마스터
주소 + R/W7비트 주소 MSB 먼저, 8번째 비트 0 = 쓰기 · 1 = 읽기마스터
ACK9번째 클럭에서 SDA = 0슬레이브 (주소가 맞으면)
데이터8비트 MSB 먼저쓰기: 마스터, 읽기: 슬레이브
ACK / NACK9번째 클럭 SDA 0 / 1받는 쪽. 읽기의 마지막 바이트는 마스터가 NACK 로 끝을 알림
반복 STARTSTOP 없이 다시 START레지스터 주소 쓰고 이어서 읽을 때 (HAL_I2C_Mem_Read)
STOPSCL = 1 인 동안 SDA 0 → 1마스터

데이터 비트는 SCL 이 0 일 때만 바뀌고 SCL 이 1 일 때 안정해야 합니다. SCL 이 1 인데 SDA 가 바뀌는 것은 START · STOP 신호로 해석됩니다.

7비트 주소와 << 1#

데이터시트의 주소(예: PCF8574 = 0x27, LM75 = 0x48, MPU-6050 = 0x68)는 7비트입니다. 선에는 이 7비트 뒤에 R/W 비트가 붙어 8비트가 나가므로, HAL 은 8비트 값(주소 << 1) 을 받습니다.

c
#define LCD_ADDR  (0x27 << 1)     /* 0x4E — HAL 이 R/W 비트를 채움 */
HAL_I2C_Master_Transmit(&hi2c1, LCD_ADDR, data, len, 100);
HAL_I2C_IsDeviceReady(&hi2c1, LCD_ADDR, 3, 100);            /* 스캐너 ([L10]) 도 << 1 */
  • 0x27 을 그대로 넘기면 선에는 0x27 = 0b0010_0111 이 나가 "주소 0x13, 읽기" 가 되어 아무도 응답하지 않습니다. I2C 오류의 첫 번째 용의자입니다.
  • 어떤 데이터시트는 8비트 값(0x4E 쓰기, 0x4F 읽기)으로 적기도 합니다. 두 가지 표기를 구분하세요.
  • 예약 주소: 0x00 (general call), 0x78~0x7B (10비트 주소 표시) 등 0000xxx · 1111xxx 는 쓰지 않습니다. 실제로는 0x08~0x77.
  • 같은 종류의 장치 여러 개는 주소 핀(A0~A2)으로 주소를 바꿔 답니다. PCF8574 는 0x20~0x27, PCF8574A 는 0x38~0x3F.

400 kHz 로 한 바이트(9 클럭)를 보내면 22.5 µs, 100 kHz 면 90 µs 입니다. LCD 한 글자에 4비트 모드로 네 번 쓰면 100 kHz 에서 약 0.4 ms — L10 의 LCD 가 느린 이유입니다.

클럭 스트레칭은 슬레이브가 "아직 준비 안 됐다" 며 SCL 을 0 으로 잡아 두는 것입니다. 마스터는 SCL 을 놓은 뒤 실제로 1 이 되었는지 확인해야 합니다. STM32 I2C 는 이를 지원하지만, 소프트웨어 I2C(비트뱅) 구현이나 일부 마스터는 지원하지 않아 EEPROM · 센서와 문제가 생깁니다. 반대로 STM32 를 슬레이브로 쓸 때는 인터럽트 응답이 늦으면 하드웨어가 자동으로 SCL 을 늘립니다 (NOSTRETCH 비트로 끌 수 있음).

F4 I2C 의 BUSY 고착

F4 의 I2C 는 통신 도중 리셋되거나 슬레이브가 SDA 를 잡은 채 멈추면 BUSY 플래그가 풀리지 않는 알려진 문제(에러타)가 있습니다. 복구는 SCL 핀을 GPIO 로 바꿔 9번 토글해 슬레이브를 풀어 주고, I2C 주변장치를 SWRST 로 리셋한 뒤 다시 초기화하는 것입니다. 제품 코드에는 이 복구 루틴을 넣어 둡니다.

시뮬레이터에서 열기I2C LCD1602 예제 열기새 창l10-lcd

시뮬레이터의 파형 탭에서 PB8 (SCL) · PB9 (SDA) 를 함께 보면 START, 주소 0x4E, ACK, 데이터, STOP 이 그림과 같이 나타납니다.

SPI#

네 선과 풀듀플렉스#

SPI(Serial Peripheral Interface) 는 마스터가 클럭을 내고 보내면서 동시에 받는 동기 통신입니다.

선방향뜻STM32 이름
SCK마스터 → 슬레이브클럭SPIx_SCK
MOSI마스터 → 슬레이브Master Out Slave InSPIx_MOSI
MISO슬레이브 → 마스터Master In Slave OutSPIx_MISO
NSS / CS마스터 → 슬레이브 (장치마다 하나)슬레이브 선택, active-lowSPIx_NSS 또는 아무 GPIO

클럭 한 펄스에 MOSI 로 1비트 나가고 MISO 로 1비트 들어옵니다. 8 클럭이면 양쪽에 한 바이트씩 — 이것이 HAL_SPI_TransmitReceive 가 기본인 이유입니다. "보내기만" 하는 HAL_SPI_Transmit 도 사실 MISO 로 들어오는 바이트를 버릴 뿐이고, "받기만" 하는 HAL_SPI_Receive 는 더미 바이트를 내보내 클럭을 만듭니다. 푸시풀 출력이므로 I2C 보다 훨씬 빠르지만, 슬레이브마다 CS 선이 하나씩 필요합니다.

대부분의 장치는 모드 0 이고, 많은 장치가 모드 0 과 3 을 모두 받습니다 (둘 다 "상승 에지에서 샘플"). 데이터시트의 타이밍 그림에서 "SCK 유휴가 어느 레벨인가, 데이터는 어느 에지에 유효한가" 를 읽어 정합니다. 모드가 틀리면 첫 비트가 밀리거나 MSB 가 사라져 ID 가 0xFF · 0x00 · 반씩 밀린 값으로 읽힙니다.

NSS 와 속도#

  • 소프트웨어 NSS (SPI_NSS_SOFT): 하드웨어 NSS 핀을 쓰지 않고 CS 를 아무 GPIO 로 직접 제어합니다. 장치가 여럿이거나 트랜잭션 단위로 CS 를 잡아야 할 때 가장 유연하며, L11 의 방식입니다. 이때 SSI 비트를 1 로 두어야 마스터가 "다른 마스터에게 뺏김(MODF)" 으로 오해하지 않습니다 — HAL 이 처리합니다.
  • 하드웨어 NSS 출력 (SPI_NSS_HARD_OUTPUT): SPI 가 켜져 있는 동안 NSS 를 LOW 로 유지 (F4 는 바이트 사이에 올리지 않음). 단일 슬레이브에서만 편합니다. 신형(H7 · G4)은 NSS 펄스 모드가 있습니다.
  • 속도: 마스터 클럭 = PCLK / 2 ~ 256 (2 의 거듭제곱). F411 SPI1 (APB2 84 MHz) 최대 42 Mbps, SPI2 · 3 (APB1 42 MHz) 최대 21 Mbps. 슬레이브 장치의 최대(SD 카드 25 MHz, W25Q 플래시 104 MHz, ILI9341 LCD 약 10 MHz, MAX7219 10 MHz)와 배선 길이에 맞춥니다. 브레드보드 점퍼선은 10 MHz 를 넘기면 불안정해집니다.
  • 데이터 폭 · 순서: 8 또는 16비트, MSB 먼저(기본) 또는 LSB 먼저. 대부분 MSB 먼저입니다.
  • 슬레이브 모드로 STM32 를 쓸 수도 있고, 3선(반이중) · 수신 전용 모드도 있습니다. I2S 는 같은 블록의 오디오 모드입니다.

STM32 에서기본. CubeMX SYS → Debug: Serial Wire거의 안 씀

ST-Link 는 PC 의 USB 를 SWD 로 바꿔 주는 디버그 프로브입니다. Nucleo 상단의 ST-Link V2-1 은 SWD 외에 가상 COM 포트(VCP, USART2 ↔ PA2/PA3) 와 드래그-앤-드롭 플래시(USB 드라이브로 보임) 기능을 함께 줍니다. 별매 ST-Link V3 는 더 빠르고(SWD 24 MHz) 브리지(UART · I2C · SPI · CAN)도 됩니다. SWD 프로토콜 자체는 코어의 DAP(Debug Access Port) 에 닿아 AHB 버스 마스터처럼 메모리를 읽고 씁니다. 그래서 프로그램이 돌고 있는 중에도 디버거가 변수를 읽을 수 있습니다 (Live Expressions).

디버그 핀을 잃어버리는 실수

CubeMX 에서 SYS → Debug 를 "No Debug" 로 두거나 PA13 · PA14 를 GPIO 로 쓰면, 그 코드가 올라간 순간부터 ST-Link 가 칩에 연결되지 못합니다 (핀이 더 이상 SWD 가 아니므로). 복구: STM32CubeProgrammer 에서 "Connect under reset" (NRST 를 잡은 채 연결) 을 쓰거나, BOOT0 을 1 로 올려 부트로더로 부팅한 뒤 지웁니다. Nucleo 의 CN7 BOOT0 핀을 VDD 에 잠깐 잇고 리셋하면 됩니다. 새 프로젝트에서는 항상 Serial Wire 를 켜 두고, PA13 · PA14 는 다른 용도로 쓰지 마세요. 핀이 정말 부족할 때만 마지막에 씁니다.

무엇을 고를까#

  1. PC 나 사람에게 보여 주는 로그, 명령 입력 → UART (ST-Link VCP, 115 200). 이 강좌의 printf 가 그것입니다.
  2. 센서 · 소형 디스플레이, 핀 절약, 장치 여러 개 → I2C. 데이터가 적고(수십 바이트/초) 100 ~ 400 kHz 면 충분할 때.
  3. 큰 데이터, 빠른 갱신 (TFT 화면, 플래시, SD 카드, ADC 스트리밍) → SPI. 핀은 더 들지만 수십 Mbps.
  4. 다른 보드 · 장치와 노이즈 많은 환경에서 몇 m 이상 → RS-485 (Modbus) 또는 CAN.
  5. PC 와 고속 · 표준 드라이버로 → USB CDC/HID/MSC.
  6. 같은 모듈이 여러 인터페이스를 줄 때 (예: 센서가 I2C · SPI 둘 다): 배선이 짧고 장치가 많으면 I2C, 샘플링이 빠르면 SPI.

한 프로젝트에서 세 가지를 모두 쓰는 것이 보통입니다. L15 의 스마트 선풍기가 UART 로그 + I2C LCD + (PWM · ADC) 를 조합하듯이, 주변장치마다 알맞은 것을 고르면 됩니다.

과제#

  1. 아래를 계산하세요: (a) 9 600 bps 8N1 에서 초당 최대 바이트 수, (b) F411 USART1 에서 2 Mbps 의 USARTDIV 와 오차 (OVER8 = 0 과 1 각각), (c) 100 kHz I2C 로 32바이트 EEPROM 페이지를 쓰는 데 걸리는 최소 시간 (주소 · 메모리 주소 · 데이터 · ACK 포함).
  2. Cb = 200 pF, 3.3 V, 고속 모드 조건에서 풀업 저항의 허용 범위를 계산하고 E24 값을 고르세요.
  3. 시뮬레이터 L10 예제의 파형에서 첫 트랜잭션의 START · 주소 바이트 · ACK · STOP 을 찾아 시간 축에 표시하고, SCL 주파수를 읽어 100 kHz 인지 확인하세요.
  4. ILI9341 TFT (SPI 모드 0, 최대 약 10 MHz), W25Q64 플래시 (모드 0/3, 104 MHz), MCP3008 ADC (모드 0/3, 3.6 MHz @ 5 V) 세 장치를 F411 의 SPI1 하나에 함께 달 때 분주비 · 모드 · CS 핀 · 문제점을 정리하세요.
  5. "온습도 센서 3개 + 0.96인치 OLED + PC 로그 + 10 m 떨어진 보드 하나" 로 이루어진 시스템의 인터페이스를 설계하고, 각 선택의 이유를 이 레슨의 비교표로 설명하세요.
