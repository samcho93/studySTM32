L17주변기기 모듈 활용

SSD1306 OLED 의 명령과 페이지 주소, HC-SR04 초음파, 4x4 키패드 스캔, 4자리 FND 멀티플렉싱, DHT11 단일 선 타이밍, 릴레이 안전, 로터리 엔코더 직교 신호, 조이스틱을 HAL 로 구동합니다.

선수 레슨: L10 L12

학습 목표#

  • SSD1306 OLED 의 제어 바이트(0x00 명령 / 0x40 데이터), 페이지 주소 방식, 1024바이트 화면 버퍼를 이해하고 글자를 그립니다.
  • HC-SR04 의 TRIG · ECHO 타이밍으로 거리를 계산합니다 (cm = µs / 58).
  • 4x4 키패드 행 스캔과 4자리 FND 멀티플렉싱의 원리와 전류 한계를 설명합니다.
  • DHT11 단일 선 프로토콜의 µs 단위 타이밍을 타이머로 재서 40비트를 읽습니다.
  • 릴레이(능동 LOW) · 로터리 엔코더(직교 신호) · 조이스틱(ADC 2채널)을 안전하게 연결합니다.

SSD1306 OLED#

SSD1306 은 128x64 픽셀 OLED 컨트롤러입니다. 내부 GDDRAM 은 128 열 × 8 페이지 = 1024 바이트이고, 한 바이트가 세로 8픽셀(비트0 = 위)을 맡습니다. 화면 한 줄의 글자(높이 8픽셀)가 페이지 하나에 딱 들어갑니다.

text
          열 0   열 1   ...  열 127
페이지 0  [b0]   [b0]         ← 픽셀 y = 0
          [..]   [..]
          [b7]   [b7]         ← 픽셀 y = 7
페이지 1  ...                    y = 8 ~ 15
 ...
페이지 7  ...                    y = 56 ~ 63

I2C 로 보내는 바이트마다 앞에 제어 바이트가 붙습니다. 0x00 이면 뒤의 바이트가 명령, 0x40 이면 화면 데이터입니다. HAL 의 HAL_I2C_Mem_Write 는 "메모리 주소" 1바이트를 먼저 보내므로, 이 자리에 제어 바이트를 넣으면 코드가 짧아집니다.

시뮬레이터에서 열기SSD1306 OLED 열기새 창l17-oled
cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* 제어 바이트 0x00 = 뒤따르는 바이트는 명령, 0x40 = 화면 데이터 */
void oled_cmd(uint8_t c)
{
  HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x00, I2C_MEMADD_SIZE_8BIT, &c, 1, 100);
}

void oled_init(void)
{
  HAL_Delay(100);                        // 전원 안정화
  oled_cmd(0xAE);                        // 디스플레이 OFF
  oled_cmd(0x20); oled_cmd(0x02);        // 메모리 주소 모드: 페이지 (0xB0~0xB7 로 줄 선택)
  oled_cmd(0xB0);                        // 페이지 0
  oled_cmd(0xC8);                        // COM 스캔 방향: 역방향 (위아래 뒤집힘 보정)
  oled_cmd(0x00); oled_cmd(0x10);        // 열 주소 0
  oled_cmd(0x40);                        // 시작 줄 0
  oled_cmd(0x81); oled_cmd(0xFF);        // 명암(contrast)
  oled_cmd(0xA1);                        // 세그먼트 재매핑 (좌우 뒤집힘 보정)
  oled_cmd(0xA6);                        // 정상 표시 (0xA7 = 반전)
  oled_cmd(0xA8); oled_cmd(0x3F);        // 멀티플렉스 64
  oled_cmd(0xA4);                        // RAM 내용 표시
  oled_cmd(0xD3); oled_cmd(0x00);        // 표시 오프셋 0
  oled_cmd(0xD5); oled_cmd(0xF0);        // 클럭 분주
  oled_cmd(0xD9); oled_cmd(0x22);        // 프리차지
  oled_cmd(0xDA); oled_cmd(0x12);        // COM 핀 구성
  oled_cmd(0xDB); oled_cmd(0x20);        // VCOMH
  oled_cmd(0x8D); oled_cmd(0x14);        // 차지 펌프 ON (없으면 화면이 켜지지 않음)
  oled_cmd(0xAF);                        // 디스플레이 ON
}

void oled_clear(void)
{
  memset(oled_buf, 0, sizeof(oled_buf));
}

/* 화면 버퍼 → OLED: 페이지마다 위치를 정하고 128바이트를 한 번에 보냅니다. */
void oled_update(void)
{
  for (uint8_t p = 0; p < 8; p++) {
    oled_cmd(0xB0 + p);
    oled_cmd(0x00);
    oled_cmd(0x10);
    HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x40, I2C_MEMADD_SIZE_8BIT, &oled_buf[128 * p], 128, 100);
  }
}

int font_index(char ch)
{
  for (int i = 0; FONT_CH[i] != 0; i++) {
    if (FONT_CH[i] == ch) return i;
  }
  return 0;                               // 없는 글자는 공백
}

/* x: 0~127 열, page: 0~7 줄 (글자 한 칸 = 6열) */
void oled_puts(uint8_t x, uint8_t page, const char *s)
{
  while (*s && x <= 122) {
    int idx = font_index(*s++);
    for (int c = 0; c < 5; c++) oled_buf[page * 128 + x + c] = FONT5x7[idx][c];
    oled_buf[page * 128 + x + 5] = 0;
    x += 6;
  }
}
/* USER CODE END 0 */
  • 화면에 직접 그리지 않고 **RAM 의 oled_buf[1024] 에 그린 뒤** oled_update() 로 한꺼번에 보냅니다. 이것이 프레임 버퍼 방식입니다.
  • 400 kHz I2C 에서 1024바이트는 비트로 약 9,200개(바이트마다 ACK 포함)라 한 화면 전송에 약 25 ms 가 걸립니다. 바뀐 페이지만 보내면 빨라집니다.
  • 흔한 모듈의 주소는 0x3C, 뒷면 저항(SA0)을 옮기면 0x3D 입니다. HAL 에는 0x3C << 1 을 넘깁니다(L10).
1.3인치 모듈은 SH1106 인 경우가 많습니다

겉모양이 같아도 1.3인치 OLED 는 SH1106 컨트롤러(132열 RAM)인 경우가 많습니다. 이때는 열 주소를 2 만큼 밀어야 화면이 맞고, 수평 주소 모드가 없으므로 페이지 모드로만 씁니다.

HC-SR04 초음파 거리#

  1. TRIG 에 10 µs 이상 HIGH 펄스를 줍니다.
  2. 모듈이 40 kHz 초음파를 8번 쏘고 ECHO 를 HIGH 로 올립니다.
  3. 반사파가 돌아오면 ECHO 가 LOW 로 내려갑니다. HIGH 폭 = 왕복 시간입니다.

소리는 20 °C 에서 약 343 m/s 이므로 1 cm 를 가는 데 29.2 µs, 왕복 58.3 µs 입니다. 그래서 거리(cm) = 폭(µs) / 58 입니다. 측정 범위는 약 2~400 cm, 400 cm 의 왕복 시간은 약 23 ms 입니다. 측정 간격은 60 ms 이상을 권장합니다.

시뮬레이터에서 열기HC-SR04 폴링 측정 열기새 창l17-ultrasonic
cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* TIM2 는 1 MHz 로 셉니다 (PSC = 83). 카운터 한 칸 = 1 µs */
void delay_us(uint16_t us)
{
  __HAL_TIM_SET_COUNTER(&htim2, 0);
  while (__HAL_TIM_GET_COUNTER(&htim2) < us) { }
}
/* 거리(cm)를 돌려줍니다. 음수 = 응답 없음 */
int32_t hcsr04_read_cm(void)
{
  uint32_t t_start, t_end;

  HAL_GPIO_WritePin(TRIG_GPIO_Port, TRIG_Pin, GPIO_PIN_SET);    // 1) 10 µs 트리거 펄스
  delay_us(10);
  HAL_GPIO_WritePin(TRIG_GPIO_Port, TRIG_Pin, GPIO_PIN_RESET);

  __HAL_TIM_SET_COUNTER(&htim2, 0);                             // 2) ECHO 가 HIGH 가 될 때까지
  while (HAL_GPIO_ReadPin(ECHO_GPIO_Port, ECHO_Pin) == GPIO_PIN_RESET) {
    if (__HAL_TIM_GET_COUNTER(&htim2) > 30000) return -1;
  }
  t_start = __HAL_TIM_GET_COUNTER(&htim2);

  while (HAL_GPIO_ReadPin(ECHO_GPIO_Port, ECHO_Pin) == GPIO_PIN_SET) {   // 3) HIGH 가 끝날 때까지
    if (__HAL_TIM_GET_COUNTER(&htim2) - t_start > 30000) return -2;
  }
  t_end = __HAL_TIM_GET_COUNTER(&htim2);

  return (t_end - t_start + 29) / 58;                           // 4) 왕복 시간 → cm (반올림)
}
/* USER CODE END 0 */

이 방식은 ECHO 가 끝날 때까지 CPU 가 while 에서 기다립니다(최대 23 ms). L19 에서는 입력 캡처로 기다리지 않고 재는 방법을 배웁니다.

4x4 키패드 스캔#

키 16개를 핀 16개로 읽지 않고, 4행 × 4열 매트릭스로 8개 핀만 씁니다. 키를 누르면 그 행과 열이 연결됩니다.

  • 행(R1~R4)은 출력, 열(C1~C4)은 풀업 입력입니다. 평소 열은 HIGH 입니다.
  • 행 하나만 LOW 로 만들고 열을 읽으면, LOW 로 읽힌 열의 키가 그 행에서 눌린 키입니다.
  • 네 행을 차례로 반복하면 16개 키를 모두 확인합니다. 20 ms 마다 스캔하면 채터링도 걸러집니다.

/* USER CODE BEGIN 0 */
/* 눌린 키 문자를 돌려줍니다. 없으면 0 */
char keypad_scan(void)
{
  char key = 0;
  for (int r = 0; r < 4; r++) {
    for (int k = 0; k < 4; k++)                       // r 번째 행만 LOW
      HAL_GPIO_WritePin(ROW1_GPIO_Port, ROW_PIN[k], (k == r) ? GPIO_PIN_RESET : GPIO_PIN_SET);
    for (int c = 0; c < 4; c++) {
      if (HAL_GPIO_ReadPin(COL1_GPIO_Port, COL_PIN[c]) == GPIO_PIN_RESET) key = KEYMAP[r][c];
    }
  }
  for (int k = 0; k < 4; k++) HAL_GPIO_WritePin(ROW1_GPIO_Port, ROW_PIN[k], GPIO_PIN_SET);
  return key;
}

두 키를 동시에 누를 때

같은 열의 두 키를 누르면 LOW 인 행과 HIGH 인 행이 버튼을 통해 직접 연결됩니다. 행 출력을 오픈드레인으로 설정하거나 행마다 330 Ω~1 kΩ 직렬 저항을 넣으면 핀끼리 합선되지 않습니다.

4자리 FND 멀티플렉싱#

4자리 FND 는 8개 세그먼트 선(a~g, dp)을 네 자리가 함께 씁니다. 자리 선택선(D1~D4) 중 하나만 켜서 그 자리에 숫자를 쓰고, 2~3 ms 뒤 다음 자리로 넘어갑니다. 눈은 빠른 깜빡임을 연속으로 보므로 네 자리가 동시에 켜진 것처럼 보입니다.

  • 한 바퀴(프레임) = 4 자리 × 2 ms = 8 ms → 125 Hz. 60 Hz 아래로 느려지면 깜빡임이 보입니다.
  • 한 자리는 1/4 시간만 켜지므로 1자리 FND(L12)보다 어둡습니다. 세그먼트 저항을 조금 줄여 보정합니다.
  • 자리를 바꿀 때는 먼저 모든 자리를 끄고 세그먼트를 바꾼 뒤 새 자리를 켭니다. 순서가 바뀌면 옆 자리에 잔상(고스트)이 남습니다.
시뮬레이터에서 열기4자리 FND 열기새 창l17-fnd4
cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* pos(0~3) 자리에 숫자 num 하나를 켭니다 */
void fnd_show(uint8_t pos, uint8_t num)
{
  for (int d = 0; d < 4; d++) HAL_GPIO_WritePin(DIG1_GPIO_Port, DIG_PIN[d], GPIO_PIN_SET);   // 1) 모든 자리 끄기 (잔상 방지)
  uint8_t pat = DIGIT_PAT[num];
  for (int s = 0; s < 8; s++)                                                                  // 2) 세그먼트 패턴
    HAL_GPIO_WritePin(SEG_A_GPIO_Port, SEG_PIN[s], ((pat >> s) & 1) ? GPIO_PIN_SET : GPIO_PIN_RESET);
  HAL_GPIO_WritePin(DIG1_GPIO_Port, DIG_PIN[pos], GPIO_PIN_RESET);                              // 3) 이 자리만 켜기
}
/* USER CODE END 0 */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    uint16_t v = counter;
    fnd_show(3, v % 10);        HAL_Delay(2);
    fnd_show(2, v / 10 % 10);   HAL_Delay(2);
    fnd_show(1, v / 100 % 10);  HAL_Delay(2);
    fnd_show(0, v / 1000 % 10); HAL_Delay(2);

      last_count = HAL_GetTick();
      counter = (counter + 1) % 10000;
    }
  }
  /* USER CODE END 3 */
자리 공통 핀 전류

세그먼트 8개가 모두 켜지면 공통 핀 하나로 8 × 10 mA = 80 mA 가 흐릅니다. STM32F4 핀 하나의 절대 최대 전류는 25 mA 이고 칩 전체도 120 mA 를 넘으면 안 됩니다(데이터시트 확인). 실물에서는 자리 공통 핀을 트랜지스터(예: 2N3904/2N3906, S8050) 로 구동하고, 세그먼트마다 저항을 답니다.

DHT11 단일 선 프로토콜#

DHT11 은 선 하나(DATA)로 명령과 데이터를 모두 주고받습니다. 선은 오픈드레인처럼 쓰고 풀업(4.7~10 kΩ) 이 HIGH 를 만듭니다.

단계누가시간
시작 신호MCU 가 LOW18 ms 이상
선 놓기MCU 가 입력(풀업)으로 전환20~40 µs 뒤 센서 응답
응답센서 LOW → HIGH80 µs + 80 µs
비트 40개센서 LOW 50 µs 뒤 HIGHHIGH 26~28 µs = 0, 70 µs = 1
데이터습도 정수·소수, 온도 정수·소수, 체크섬체크섬 = 앞 4바이트 합의 하위 8비트
시뮬레이터에서 열기DHT11 온습도 열기새 창l17-dht11
cCore/Src/main.c
/* USER CODE BEGIN 0 */
/* TIM2 는 1 MHz 로 셉니다 (PSC = 83). 카운터 한 칸 = 1 µs */
void delay_us(uint16_t us)
{
  __HAL_TIM_SET_COUNTER(&htim2, 0);
  while (__HAL_TIM_GET_COUNTER(&htim2) < us) { }
}
void dht_pin_output(void)
{
  dht_io.Pin = DHT_Pin;
  dht_io.Mode = GPIO_MODE_OUTPUT_PP;
  dht_io.Pull = GPIO_NOPULL;
  dht_io.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(DHT_GPIO_Port, &dht_io);
}

void dht_pin_input(void)
{
  dht_io.Pin = DHT_Pin;
  dht_io.Mode = GPIO_MODE_INPUT;
  dht_io.Pull = GPIO_PULLUP;               // 선을 놓으면 풀업이 HIGH 로 올림
  HAL_GPIO_Init(DHT_GPIO_Port, &dht_io);
}

/* 핀이 level 이 될 때까지 기다린 시간(µs). timeout 을 넘으면 -1 */
int dht_wait(uint8_t level, uint16_t timeout)
{
  __HAL_TIM_SET_COUNTER(&htim2, 0);
  while (HAL_GPIO_ReadPin(DHT_GPIO_Port, DHT_Pin) != level) {
    if (__HAL_TIM_GET_COUNTER(&htim2) > timeout) return -1;
  }
  return __HAL_TIM_GET_COUNTER(&htim2);
}

/* 0 = 성공, 그 밖 = 실패 단계 번호 */
int dht_read(void)
{
  dht_pin_output();
  HAL_GPIO_WritePin(DHT_GPIO_Port, DHT_Pin, GPIO_PIN_RESET);   // 1) 시작 신호: 18 ms 이상 LOW
  HAL_Delay(18);
  dht_pin_input();                                            // 2) 선을 놓음

  if (dht_wait(0, 100) < 0) return 1;                         // 3) 응답: 80 µs LOW
  if (dht_wait(1, 100) < 0) return 2;                         //         80 µs HIGH
  if (dht_wait(0, 100) < 0) return 3;

  for (int i = 0; i < 5; i++) dht[i] = 0;
  for (int i = 0; i < 40; i++) {                              // 4) 40비트
    if (dht_wait(1, 80) < 0) return 4;                        //    50 µs LOW 끝
    int high = dht_wait(0, 100);                              //    HIGH 길이 재기
    if (high < 0) return 5;
    dht[i / 8] <<= 1;
    if (high > 40) dht[i / 8] |= 1;                           //    26 µs = 0, 70 µs = 1
  }
  if ((uint8_t)(dht[0] + dht[1] + dht[2] + dht[3]) != dht[4]) return 6;   // 5) 체크섬
  return 0;
}
/* USER CODE END 0 */
  • µs 단위로 재야 하므로 1 MHz 로 도는 TIM2 의 카운터를 씁니다(__HAL_TIM_GET_COUNTER).
  • HIGH 폭이 40 µs 보다 길면 1 로 판정합니다. 26 µs 와 70 µs 사이의 가운데 값입니다.
  • 1초에 한 번 이하로 읽고, 전원을 넣은 뒤 1초는 기다립니다. 읽는 동안 긴 인터럽트가 끼면 비트가 틀어져 체크섬 오류가 납니다.
  • DHT11 은 0~50 °C(±2 °C), 20~90 %RH(±5 %) 범위의 저가 센서입니다. 더 정밀해야 하면 DHT22 나 I2C 센서(SHT3x 등)를 씁니다.

릴레이 모듈#

릴레이는 작은 전류(코일)로 큰 전류(접점)를 켜고 끄는 기계식 스위치입니다. 5 V 릴레이 코일은 약 70 mA 가 필요해 GPIO 로 직접 구동할 수 없습니다. 흔한 릴레이 모듈에는 트랜지스터(또는 포토커플러)와 역기전력 다이오드가 들어 있어 GPIO 로 IN 만 제어하면 됩니다.

  • 대부분의 모듈은 IN 이 LOW 일 때 켜집니다(능동 LOW). 그래서 예제는 초기값을 HIGH 로 두어 부팅 중에 릴레이가 붙지 않게 합니다.
  • 코일 전류가 끊기는 순간 코일은 수십~수백 V 의 역기전력을 만듭니다. 모듈 없이 직접 만들 때는 코일에 다이오드(1N4148, 1N4007)를 역방향 병렬로 꼭 답니다.
시뮬레이터에서 열기릴레이 토글 열기새 창l17-relay
cCore/Src/main.c
/* USER CODE BEGIN PV */
#define RELAY_ON   GPIO_PIN_RESET        // 이 모듈은 LOW 에서 켜짐 (active-low)
#define RELAY_OFF  GPIO_PIN_SET
uint8_t relay_on = 0;
uint8_t last_btn = 1;
/* USER CODE END PV */

  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    uint8_t btn = HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin);

      relay_on = !relay_on;
      HAL_GPIO_WritePin(RELAY_GPIO_Port, RELAY_Pin, relay_on ? RELAY_ON : RELAY_OFF);

  }

릴레이와 교류(AC) 부하
  • AC 220 V 는 감전으로 생명을 잃을 수 있습니다. 실습은 5~12 V 직류 부하(LED 띠, 소형 팬)로만 하세요. 교류 배선은 자격 있는 사람이 절연된 함체 안에서만 합니다.
  • 접점 정격(예: 10 A 250 VAC / 10 A 30 VDC)을 넘기지 마세요. 모터·전구처럼 켜는 순간 큰 전류가 흐르는 부하는 정격의 절반 이하로 씁니다.
  • 모듈의 JD-VCC 점퍼를 빼고 릴레이 코일 전원을 따로 주면 포토커플러로 MCU 쪽과 전기적으로 분리됩니다.
  • 배선은 전원을 모두 끈 상태에서 하고, 릴레이 뒷면의 납땜면(고전압 쪽)을 손이나 금속에 닿지 않게 합니다.

로터리 엔코더 (KY-040)#

엔코더를 돌리면 CLK(A)와 DT(B) 두 신호가 90° 어긋난 사각파(직교 신호) 로 나옵니다. 어느 쪽이 먼저 떨어지는지로 방향을 압니다.

text
시계 방향      CLK ‾‾\____/‾‾‾‾      CLK 가 먼저 LOW → 그 순간 DT 는 아직 HIGH → +1
               DT  ‾‾‾‾\____/‾‾
반시계 방향    CLK ‾‾‾‾\____/‾‾      CLK 가 떨어질 때 DT 는 이미 LOW → -1
               DT  ‾‾\____/‾‾‾‾
시뮬레이터에서 열기로터리 엔코더 열기새 창l17-encoder
cCore/Src/main.c
  /* USER CODE BEGIN WHILE */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    uint8_t clk = HAL_GPIO_ReadPin(ENC_CLK_GPIO_Port, ENC_CLK_Pin);
    if (last_clk == 1 && clk == 0) {                              // CLK 하강 에지
      if (HAL_GPIO_ReadPin(ENC_DT_GPIO_Port, ENC_DT_Pin) == 1) position++;   // DT 아직 HIGH → 시계 방향
      else position--;                                                        // DT 먼저 LOW → 반시계
      printf("Position: %ld\r\n", position);
    }
    last_clk = clk;

    uint8_t sw = HAL_GPIO_ReadPin(ENC_SW_GPIO_Port, ENC_SW_Pin);
    if (last_sw == 1 && sw == 0) {
      position = 0;
      printf("Reset\r\n");
    }
    last_sw = sw;
    HAL_Delay(1);
  }
  /* USER CODE END 3 */
  • KY-040 은 한 바퀴에 20 딸깍(detent) 이 흔합니다. 한 딸깍에 CLK 가 한 번 떨어집니다.
  • 빨리 돌리면 1 ms 폴링으로는 에지를 놓칠 수 있습니다. 실물에서는 EXTI 인터럽트를 쓰거나, 타이머의 엔코더 모드(HAL_TIM_Encoder_Start, 시뮬레이터 미지원)로 하드웨어가 직접 세게 합니다.
  • 모듈의 CLK · DT 에는 10 kΩ 풀업이 있지만 SW 는 없는 모듈도 있어 내부 풀업을 켭니다.

조이스틱#

조이스틱은 10 kΩ 가변저항 두 개(X, Y)와 누름 스위치입니다. VRx · VRy 를 ADC 두 채널로 스캔하면 가운데가 약 2048 입니다. 실물은 가운데 값이 정확히 2048 이 아니고 흔들리므로 데드존(예: 1000~3000 은 가운데로 봄)을 둡니다.

5 V 모듈을 3.3 V MCU 에 연결할 때
  • 조이스틱 · 가변저항처럼 ADC 로 읽는 모듈은 반드시 3.3 V 로 전원을 줍니다. 5 V 를 주면 출력이 3.3 V 를 넘어 ADC 핀이 손상될 수 있습니다.
  • HC-SR04 의 ECHO 는 5 V 신호입니다. 연결할 핀이 데이터시트 핀 표에서 FT(5 V 허용) 인지 확인하거나, 1 kΩ / 2 kΩ 분압으로 약 3.3 V 로 낮춥니다.
  • 배선은 전원을 끈 상태에서 하고, 5 V · 3.3 V · GND 를 서로 직접 잇지 않았는지 확인한 뒤 USB 를 꽂습니다.
